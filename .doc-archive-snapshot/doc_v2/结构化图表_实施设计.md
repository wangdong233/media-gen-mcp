# media-gen-mcp 结构化图表 + 全家桶生图 — 实施设计

> 版本: 1.0 | 日期: 2026-07-10
> 定位: 技术实施级文档(可直接照着写代码)。基于 5 维度深度调研 + 实测验证。

---

## 一、执行摘要

### 1.1 总体方案

扩展现有 `media-gen-mcp`,在 `src/providers/`(远程 API 范式)之外新增 **`src/diagram/` 独立模块**(本地确定性渲染范式),并按"全家桶路线图"逐步加入 chart / qr / formula / icon / card 等生图工具。

核心判断:**结构化图表渲染与现有 image/video 生成是两个正交范式**——

| 维度 | providers/(现有) | diagram/(新增) |
|---|---|---|
| 渲染位置 | 远程 API | 本地进程内 / 本地二进制 |
| 认证 | apiKey | 无 |
| 网络 | 必须 | 不需要(Kroki 回退除外) |
| 时序 | 异步轮询(poll.ts) | 同步 |
| 计费 | 按量 | 免费 |
| 成本 | $$$ | $0 |

强行塞进 `MediaProvider` 接口会污染抽象(apiKey / rateLimit / estimateGenerationSeconds 对本地渲染毫无意义),故独立模块。

### 1.2 关键设计裁决(5 条)

1. **CC 生成 DSL / MCP 确定性渲染**——MCP 不内置 LLM、不做语义理解。CC(Claude)是更强的 LLM 且持有完整上下文,MCP 再造一个 LLM 冗余。
2. **不强制 JSON 中间协议**——CC 直接出 DSL(Mermaid 是被所有主流 LLM 原生训练的图形语言,直接生成可靠度足够)。JSON-IR 只解决语法(容易的那半),对语义毫无帮助,且对 sequence/class 图有损。
3. **本地渲染产物不复用 `downloadAsset`**——`downloadAsset(url,kind,outDir)` 的语义是"fetch 远程 URL→落盘";本地渲染器直接写成文件、无 URL。仅 Kroki 远程回退路径才用 `downloadAsset`。
4. **依赖策略:进程内 WASM 优先 + 可选 spawn 二进制 + 可选远程回退**——不引入 Puppeteer/Chromium(违反轻量原则)。实测 `@terrastruct/d2`(WASM)可靠、`@resvg/resvg-js` 可靠;mermaid 进程内有已知脆弱性,需诚实降级处理。
5. **SVG-first**——SVG 是文本、确定性(CC 可 Read 直读、可 diff),PNG 仅作可选(resvg-js 栅格化)。

### 1.3 Mermaid 可靠性 — 最关键的技术风险(诚实披露)

调研中实测发现 **mermaid 进程内渲染存在已知脆弱性**,必须在实施时正面处理:

| 方案 | 实测结果 | 判定 |
|---|---|---|
| `isomorphic-mermaid@0.1.1` + `mermaid@11.16.0` | peer 的 mermaid 发布残缺(只有 `.mjs.map` 无 `.mjs` 本体),`ERR_MODULE_NOT_FOUND` | **不可用** |
| `mermaid-isomorphic@3.1.0` | 名字带 isomorphic,但 Node 下明确要求 Playwright + Chromium | **违反无 Chromium 约束** |
| `mermaid` + jsdom polyfill | 简单图能成,复杂图常出 `Cannot read properties of undefined` | **极脆,best-effort** |
| `@mermaid-js/mermaid-cli`(mmdc) | 捆绑 Puppeteer + Chromium(~300MB) | **过重,剔除** |

**实施策略(三层兜底):**

- **第 1 层(默认)**:mermaid + jsdom 进程内渲染。简单图(flowchart/sequence/pie)实测通过率尚可;固定一个验证过的 mermaid 版本(如 `11.4.x`)+ svgdom polyfill,锁定版本不自动升级。
- **第 2 层(回退)**:进程内渲染失败时,若 `config.diagram.renderer === "kroki"`,自动 POST DSL 到 Kroki HTTP 端点取回 SVG(高保真,因为 Kroki 服务端有浏览器环境)。代价:网络 + 隐私(DSL 外发),故**默认关闭**。
- **第 3 层(跨引擎)**:CC 收到 mermaid 反复失败的结构化错误后,自行将图重写为 D2 DSL,调用 D2 WASM 引擎(恒可用、可靠)渲染。这是 CC 侧的 agentic fallback,无需 MCP 特殊支持。

**对用户的诚实声明**(写进 README):mermaid 是 LLM 最擅长的图形 DSL,但其在 Node 进程内的高保真渲染依赖浏览器布局引擎;本 MCP server 无 Chromium,mermaid 路径为 best-effort——简单图可靠,复杂图可能需要 Kroki 回退或改用 D2。

### 1.4 全家桶路线图一览

| 阶段 | 工具 | 引擎/库 | 优先级 | 估时 |
|---|---|---|---|---|
| P0 | `generate_diagram` | mermaid + @terrastruct/d2(WASM) + dot(spawn) | 最高 | 3-5 天 |
| P0 | `generate_chart` | Vega-Lite(纯 JS SVG) | 最高 | 1-2 天 |
| P0 | `generate_qrcode` | qrcode(纯 JS) | 最高 | 0.5-1 天 |
| — | 共享 `svgToPng` | @resvg/resvg-js | 随 P0 | 0.5 天 |
| P1 | `generate_formula` | MathJax(纯 JS SVG,非 KaTeX) | 高 | 1 天 |
| P1 | `generate_icon` | Iconify @iconify/json(纯 JS 离线) | 高 | 1-1.5 天 |
| P2 | `generate_card` | Satori + resvg-js | 中 | 3-5 天 |
| 不上 | Sharp | libvips(改图非生图) | 内部 helper | — |

## 二、generate_diagram 工具设计

### 2.1 工具 schema 定稿

工具名: `generate_diagram`(index.ts `buildTools()` 返回数组的第 5 项,与现有 4 个工具并列)

```jsonc
{
  "name": "generate_diagram",
  "description": "Render a diagram from DSL source (Mermaid / D2 / Graphviz DOT) to SVG or PNG. The CALLER authors the DSL; this tool deterministically renders it (no LLM inside). On syntax error, returns the engine's parse error (engine name + stderr + line) for the caller to fix and retry. Output writes to OUT_DIR (or outDir) and the local path is returned.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "code": {
        "type": "string",
        "description": "DSL 源码。Mermaid(如 'flowchart TD\\n  A-->B')/ D2 / Graphviz DOT。渲染权威来源。"
      },
      "type": {
        "type": "string",
        "enum": ["flowchart","sequence","class","state","er","gantt","pie","mindmap","journey","git","timeline","quadrant","c4","requirement","other"],
        "description": "图类别;仅作 engine=auto 的选路提示 + CC 意图声明。engine 显式时纯元数据。注意:Mermaid 真实类型以 code 首行关键字(graph/sequenceDiagram/classDiagram/...)为准,MCP 从 code 解析、不盲信此参数。"
      },
      "engine": {
        "type": "string",
        "enum": ["auto","mermaid","d2","graphviz"],
        "default": "auto",
        "description": "auto 按 code 首行启发式 + type 选路;且只在「本机可用引擎」里选(type=gantt 只 mermaid 支持→强制 mermaid)。"
      },
      "format": {
        "type": "string",
        "enum": ["svg","png"],
        "default": "svg",
        "description": "svg 可缩放/可二次编辑,优先;png 便于嵌入。"
      },
      "outDir": {
        "type": "string",
        "description": "省略用 config.outDir(复用 resolveOutDir)。"
      },
      "name": {
        "type": "string",
        "description": "文件名(不含扩展名);省略则 diagram_<12位uuid>(对齐 img_<id>/vid_<id> 命名)。"
      },
      "theme": {
        "type": "string",
        "description": "主题/皮肤提示透传引擎(mermaid: default/dark/forest/neutral; d2: sketch/...; graphviz: 透传)。引擎相关,可选。"
      },
      "download": {
        "type": "boolean",
        "default": true,
        "description": "false 时:渲染到临时文件→读出 SVG 文本内联返回(不落盘),PNG 则返回 data URI。对齐现有工具 download:false 仍返回 outputs 的语义。"
      }
    },
    "required": ["code"]
  }
}
```

**设计要点:**

- **`code` 是唯一必填**——DSL 是渲染权威来源,`type` 仅为提示。
- **`type` 对 Mermaid 非权威**——Mermaid 真实类型以 `code` 首行关键字为准(`graph`/`sequenceDiagram`/`classDiagram`/...),MCP 从 code 解析、不盲信 `type` 参数,避免不一致时的歧义。
- **`engine=auto` 只在可用引擎集合内选路**——某引擎不可用时给清晰 err 提示安装命令,不静默失败。
- **`download:false`** 对齐现有工具语义:仍返回 outputs,只是不落盘(SVG 内联文本 / PNG data URI)。

### 2.2 CC vs MCP 分工(边界钉死)

```
┌─────────────────────────────────┐         ┌──────────────────────────────────┐
│           CC (Claude)            │         │            MCP server             │
│       语义理解 + DSL 生成         │  DSL    │     确定性渲染 + 语法校验          │
│                                  │ ──────> │                                   │
│  · 理解用户想要什么图             │         │  · 接收 DSL → 渲染 → SVG/PNG      │
│  · 选择引擎(Mermaid/D2/Graphviz) │         │  · 语法校验(渲染即校验)          │
│  · 生成 DSL 源码                  │  错误   │  · 结构化错误回报(带行列+修法)   │
│  · 收到错误→自纠 DSL→重试        │ <────── │  · 能力探测(list engines)        │
│  · 超限后跨引擎重写               │         │  · 不含 LLM / 不做语义判断        │
└─────────────────────────────────┘         └──────────────────────────────────┘
```

**理由:**

1. **确定性**——同一 DSL → 同一图,可复现/可 diff;LLM 生成会引入随机性,破坏 MCP 的工具契约。
2. **Token 效率**——CC 输出几十~两百行 Mermaid,远比手绘上千行 SVG 省 token。
3. **可编辑**——DSL 人/机可读可改;裸 SVG 不可读。
4. **隐私**——架构图常含敏感信息,DSL 留在本地渲染;若 MCP 内挂 LLM 还要外发 + 多一把 API key。
5. **职责正交**——CC 已是更强的 LLM 且持有完整对话上下文(最懂用户意图),MCP 再造一个 LLM 冗余。

**MCP 侧该有的"智能"不是生成,而是:**
- 好的解析错误回报(让 CC 自纠)
- 引擎自动选路(仅 engine=auto 时)
- 可用性探测(让 CC 知道能用哪些引擎)

### 2.3 不强制 JSON 中间协议(关键裁决)

**结论:CC 直接出 DSL,不经过 `{nodes, edges, layout}` JSON 中间表示。**

四条论据:

1. **Claude 是前沿模型**——Mermaid 是被所有主流 LLM 原生训练的图形语言,直接生成可靠度足够。JSON-IR 的两步法(LLM 出 JSON → 代码转 Mermaid)适用于弱本地模型(Ollama),对前沿 Claude 收益骤降。

2. **JSON-IR 只解决语法(容易的那半)**——MermaidSeqBench(arXiv 2511.14967, IBM 2025)数据显示即便 8B 模型语法正确率已达 ~91-92%,但 Logic/Completeness 明显更低。真正的难点是语义,而 JSON-IR 对语义毫无帮助,ROI 翻车。

3. **通用 `{nodes,edges}` IR 对 sequence/class/state 图有损**——无法表达 `activate`/`deactivate`、`alt`/`else`/`loop`、`Note` 等结构。要无损就得为每种图型设计独立 schema,工程量巨大。

4. **IR→D2 转换会丢掉 D2 的美观特性**——container/near/style/icon,与"用 D2 求美"的初衷矛盾。

**例外:** 仅当存在"同一份结构要扇出到 Mermaid + D2 + Graphviz 多引擎且图型很简单(纯 boxes-and-arrows 流程图)"这一窄需求时,才引入**图型感知**(非通用 graph)的 IR,作为可选路径而非默认。

### 2.4 校验闭环(渲染即校验 + 结构化错误)

**核心理念:渲染本身就是语法校验——通过即合法,失败即语法错。**

```
CC 生成 DSL
    │
    ▼
MCP render(code, engine)
    │
    ├── 成功 → 写文件 → 返回 { engine, format, local_path, bytes }
    │
    └── 失败 → 返回结构化错误(isError: true)
                { engine, exit_code, error: <stderr 原文>,
                  code_with_lines: <给 DSL 加上行号>,
                  hint: <常见修法提示> }
                    │
                    ▼
              CC 读错误 → 按行列修 DSL → 重试
                    │
                    ├── (≤3 次成功) → 完成
                    │
                    └── (超 3 次) → fallback:
                          · 降级图型(砍 alt 分支)
                          · 切换引擎(mermaid→d2,CC 重写 DSL)
                          · DSL 原文交用户手动修
```

**重试硬上限: 3 次。** 经验法则"同一问题纠正不超过两次"——多次纠正在上下文里堆积会反噬性能。每次尝试记录 attempt,避免静默死循环。

**错误返回载荷(err, `isError: true`):**

```typescript
interface DiagramError {
  engine: DiagramEngineName;
  exit_code: number;
  error: string;           // stderr 原文,含行列信息
  code_with_lines: string; // 给 DSL 加上行号便于 CC 定位
  hint: string;            // 常见修法提示(如 "用 ->> 表示同步消息")
}
```

**关键约束:** 错误信息必须**可执行**——不是模糊的 "failed",而是带 `{line, token, suggestion}` 的具体定位。这是 MCP 端唯一且最重要的设计。

### 2.5 返回结构

**成功(ok):**
```jsonc
{
  "engine": "mermaid",
  "format": "svg",
  "local_path": "/abs/.../diagram_a1b2c3d4e5f6.svg",
  "source_type": "mermaid",
  "bytes": 12345
}
```

**失败(err, `isError: true`):** 见 2.4 错误载荷。

## 三、渲染引擎集成

### 3.1 引擎选型与实测结论

| 引擎 | 集成方式 | 实测状态 | 角色 |
|---|---|---|---|
| **@terrastruct/d2** (WASM) | 进程内,`new D2().compile()→render()` | ✅ 实测出 9993 字符有效 SVG | **恒可用兜底**(bundled 必装) |
| **mermaid** + jsdom | 进程内,动态 import + DOM 注入 | ⚠️ best-effort(简单图可靠,复杂图脆弱) | **核心 DSL 引擎**(LLM 最擅长) |
| **d2** CLI | spawn 二进制 | ✅ `--stdout` 拿 SVG,自身能出 PNG | **可选高可靠**(brew install d2) |
| **graphviz dot** | spawn 二进制 | ✅ `-Tsvg` 拿 SVG,自身能出 PNG | **可选高可靠**(brew install graphviz) |
| **@resvg/resvg-js** | 进程内,Rust N-API 预编译 | ✅ 实测出有效 PNG(1911 bytes / 240x120) | **共享 SVG→PNG 栅格化** |
| **Kroki** | HTTP POST DSL→取回图片 | ✅ 统一端点处理三引擎 | **可选远程回退**(默认关闭) |

**命名陷阱(必须警告):** npm 上有两个叫 d2 的东西——`d2@31.10.2` 是 DHIS2(卫生信息系统)JS 库,**不是画图工具**!D2 画图工具的 npm 包是 **`@terrastruct/d2`**。

### 3.2 @terrastruct/d2(WASM)— 实测细节

这不是 CLI spawn,而是 D2 的 WASM 移植的 JS 封装,真正进程内、无浏览器、无 child_process。

```typescript
import { D2 } from '@terrastruct/d2';
const d2 = new D2();
const r = await d2.compile('x -> y', { sketch: false });
const svg = await d2.render(r.diagram, r.renderOptions);
// 输出 ~9993 字符有效 SVG
```

**两个坑(实测):**
1. 输出不以 `<svg` 开头而是 `<?xml version="1.0" encoding="utf-8"?>` XML 声明——下游解析/去 XML 头时注意。
2. 用 webworker,渲染完后 worker 不自动退出,进程会 hang——**在 MCP server 这种长驻进程里无碍**,但在一次性脚本里要 `process.exit(0)`。

### 3.3 降级链(关键修正:跨引擎降级 ≠ 同 DSL 换引擎)

**重要澄清:** Mermaid / D2 / Graphviz 的 DSL 语法互不兼容——你不能把 mermaid DSL 喂给 d2 引擎。因此降级分两层:

**层 1 — 同引擎、后端切换(透明,MCP 自行处理):**
```
mermaid 进程内渲染失败(但 DSL 语法合法)
    → 若 config.diagram.renderer === "kroki"
      → POST 同一份 mermaid DSL 到 Kroki → 取回 SVG(高保真)
    → 否则返回错误,CC 自行处理
```

**层 2 — 跨引擎(CC 语义决策,MCP 不参与):**
```
CC 收到 mermaid 反复失败 → CC 自行将图重写为 D2 DSL → 调用 generate_diagram(engine:"d2")
```

**engine=auto 的选路逻辑(仅同 DSL 家族内):**
```typescript
function detectEngine(code: string, typeHint?: string): DiagramEngineName {
  const firstLine = code.trim().split('\n')[0];
  // Mermaid 关键字
  if (/^(graph|flowchart|sequenceDiagram|classDiagram|stateDiagram|erDiagram|gantt|pie|mindmap|journey|gitGraph|timeline|quadrantChart|requirementDiagram|C4Context)/.test(firstLine)) {
    return 'mermaid';
  }
  // Graphviz DOT
  if (/^(digraph|graph|strict\s+(digraph|graph))\s/.test(firstLine) || firstLine.startsWith('digraph') || firstLine.startsWith('graph ')) {
    return 'graphviz';
  }
  // D2(兜底:D2 语法最宽松)
  return 'd2';
}
```

选路后检测该引擎是否可用;不可用时返回含 `installHint()` 的错误(CC 可改用其他引擎重写 DSL)。

### 3.4 SVG → PNG 共享层

所有引擎原生产出 SVG 字符串后,PNG 统一由 `@resvg/resvg-js` 栅格化(Rust + napi-rs,预编译无 node-gyp,1s 装完,保真度高):

```typescript
// src/diagram/svg-to-png.ts —— 全家桶共享
import { Resvg } from '@resvg/resvg-js';

export function svgToPng(svg: string, opts?: { width?: number; background?: string }): Buffer {
  const resvg = new Resvg(svg, {
    fitTo: { mode: 'width', value: opts?.width ?? 1200 },
    background: opts?.background ?? '#ffffff',
  });
  return resvg.render().asPngBuffer();
}
```

**与 sharp 的分工:** D2 CLI / dot 二进制自身能出 PNG(`d2 --format=png` / `dot -Tpng`),不走 resvg;resvg 服务于 mermaid 等"只有 SVG 输出"的引擎。sharp(libvips)留作 raster 后处理(已生成 PNG 加水印/缩放),**不进 generate_* 工具族**。

### 3.5 依赖策略(双轨 + 分层)

```jsonc
// package.json
{
  "dependencies": {
    "@modelcontextprotocol/sdk": "^1.17.4",
    "@terrastruct/d2": "^0.1.33",     // WASM 进程内,恒可用,bundled 必装
    "mermaid": "11.4.x",               // 核心 DSL 引擎,固定版本(升级可能 break)
    "jsdom": "^25.x"                   // mermaid 在 node 需 DOM(轻量,非浏览器)
  },
  "optionalDependencies": {
    "@resvg/resvg-js": "^2.6.2"        // SVG→PNG 纯 Rust,装不上不报错,运行时检测降级
  }
  // d2 / graphviz: 外部系统二进制,不进 npm,hasBinary() 运行时探测

}
```

**选 mermaid + jsdom 而非 mermaid-cli(mmdc):** mmdc 依赖 Puppeteer,拖入 ~300MB Chromium,违反"无 Chromium"约束。jsdom ~2MB,提供 DOM 子集足够 mermaid 的 SVG 渲染(但非完整浏览器,故复杂图可能失败——见 1.3)。

## 四、描述协议(CC 侧 NL→DSL 策略 + MCP 确定性渲染)

### 4.1 边界定义(必须钉死)

**描述协议本质是 CC 侧的 prompt/skill 策略。MCP 是确定性渲染器 + 校验器,不含 LLM、不做语义理解。**

```
NL → 结构化理解 → DSL 生成      →→→ 全在 CC(Claude)
DSL → 图片 + 语法校验            →→→ 在 MCP
```

MCP 永不参与"理解用户想要什么",只接收 DSL 渲染。这个边界必须钉死,否则 MCP 会被迫内置 LLM,复杂度与失败面爆炸。

### 4.2 NL→DSL 落地:CC diagramming skill

MermaidSeqBench 的结构化 NL 模板落地为 **CC 的一个 diagramming skill(`.md`)或专用 subagent 的 prompt,绝不进 MCP**。

**skill 内容:**

1. **指令**——当被要求画图时,先在推理中枚举参与者与有序交互步骤,再产出对应 DSL。
2. **结构化 NL 脚手架**(MermaidSeqBench 模板):

```
Purpose:          一句话说明这张图要表达什么
Main Components:  枚举核心节点/参与者
Interactions:     有序编号步骤(1. 用户→前端: 操作  2. 前端→API: 请求 ...)
```

3. **1-2 个 few-shot 范例**(如"Uploading Documents with Secure Storage"完整序列图)作为 in-context 模板。
4. **CoT**——CC 的 extended thinking 先规划节点/边/控制流再写代码。这是模型原生能力,无需额外机制。
5. **生成后自检清单**(浓缩自 MermaidSeqBench 六维评判):

```
□ Syntax:        DSL 语法合法(MCP 渲染通过即验证)
□ Logic:         交互逻辑正确(箭头方向、消息顺序)
□ Completeness:  覆盖了用户描述的所有参与者与步骤
□ Activation:    序列图的 activate/deactivate 正确配对
□ No Mix:        未混用图型(如 sequence 图里出现 flowchart 节点)
□ Status/Error:  错误分支与状态码完整
```

### 4.3 校验-回贴迭代(CC 原生 agentic loop)

复用 CC 原生的工具调用循环,**无需新机制**。关键在 MCP 工具的返回结构设计:

```jsonc
// MCP render() 失败时返回(可执行的结构化错误)
{
  "ok": false,
  "isError": true,
  "errors": [
    {
      "line": 12,
      "token": "-->",
      "expected": "->>",
      "message": "sequenceDiagram 中应使用虚线箭头 ->> 表示同步消息",
      "snippet": "  A-->B: hi    // 第 12 行",
      "suggestion": "改为 A->>B: hi"
    }
  ]
}
```

CC 读后自修 DSL 重试。这和 CC 处理编译错误、测试失败的循环是同一个机制。

**重试约束:**
- 硬上限 3 次。
- 区分 **retry**(网络/瞬时错误,重试同一参数)与 **self-correction**(CC 自己的 DSL 错误,必须改 DSL)。
- 超限后 fallback:降级图型 / 切换引擎(CC 重写 DSL)/ DSL 原文交用户。

### 4.4 引擎选择是 CC 的语义决策

**MCP 不做 engine=auto 的"智能"选路——真正的决策权在 CC。**

理由:MCP 是确定性层,无法判断用户要"快速草图"还是"精致架构文档"——这是语义。

**落地方式:**
- MCP 把 `engine` 作为参数暴露,CC 根据(a)MCP 工具 description 里写明的各引擎长处、(b)用户显式偏好、(c)推断的图型来选引擎,并写出该引擎的 DSL。
- MCP 工具 description 里的引擎能力描述(反向引导 CC):

| 引擎 | 长处 | 短板 |
|---|---|---|
| **Mermaid** | 快;被所有 LLM 原生训练,生成可靠度最高;序列/流程/C4 图强;类型最丰富(15+) | 进程内渲染复杂图可能脆弱;美观度一般 |
| **D2** | 美观;自动布局(ELK/Tartifa);容器化复杂架构强;WASM 恒可用 | LLM 训练数据较少,生成需更多试错 |
| **Graphviz** | 高可靠 C 程序;布局算法成熟(dot//neato/fdp) | 语法低级;美观度最差;LLM 生成 DOT 较少 |

- MCP 内放一个极轻的 `detectEngine()` 启发式(按 DSL 关键词嗅探)作为 `engine=auto` 的便利,但真正的决策权在 CC。

### 4.5 各组件归属一览

| 组件 | 归属 |
|---|---|
| 画图知识 / 结构化 NL 脚手架 / few-shot 范例 / 引擎选型启发 | **CC skill(.md)** 或 subagent prompt |
| NL → DSL 生成 | **CC 的 Claude**(LLM 原生能力) |
| DSL → 图片渲染 + 语法校验 + 错误结构化 | **MCP 工具**(确定性) |
| 引擎能力描述 | **MCP 工具 description**(反向引导 CC)+ CC skill 里复述一份 |

**最大架构陷阱:过度工程化中间协议。** 被两步法吸引而强制所有图型走 JSON-IR,结果:(1)sequence/class 图信息丢失;(2)D2 美观特性丢失;(3)为每种图型维护 IR schema 的成本压垮项目。正确顺序:**先让 CC 直接出 Mermaid + 跑校验闭环,实测失败率;只有当某一类图失败率不可接受时,才为该类图引入专门 IR。以数据驱动协议复杂度,而非预设复杂协议。**

## 五、其他图片类型全家桶

### 5.1 共享架构:SVG-first + 统一 svgToPng

绝大多数候选(diagram/mermaid、vega-lite、mathjax、qrcode、iconify、satori)都能原生产出 SVG 字符串。沉淀一个共享 `svgToPng(svg, {width, scale})` helper(基于 resvg-js),让所有 generate_* 工具统一支持 `'svg'|'png'` 输出选择:

```
职责分层:
  生成器(各 generate_*）= 内容 → SVG
  resvg-js（共享）      = SVG → PNG
  sharp（内部 helper）   = PNG → PNG'(水印/缩放/格式转换)
```

**全程不需要 Chromium/Puppeteer——这是 media-gen-mcp 全家桶的最大卖点。**

### 5.2 P0: generate_chart(Vega-Lite 数据可视化)

**用户场景:** "根据这组数据画柱状图/折线图/饼图/散点图/热力图"

**为什么选 Vega-Lite:**
- **LLM 最友好**——声明式 JSON spec(mark + encoding),是所有图表 DSL 中 LLM 训练语料最充分、几乎零错误地产出合法 JSON。
- **纯 JS SVG**——`vega-lite(compile) → vega(View.toSVG, renderer:'none')` 全程纯 JS、无 canvas、无二进制。
- **不选 Chart.js/ECharts**——两者都是浏览器 canvas 渲染引擎,Node 端需 Puppeteer/Chromium 或 QuickChart(外部 Docker 服务),非自包含。

**工具 schema:**
```jsonc
{
  "name": "generate_chart",
  "description": "Render a data visualization chart from a Vega-Lite JSON spec to SVG or PNG. CALLER authors the spec; this tool deterministically renders it.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "spec": { "type": "string", "description": "Vega-Lite JSON spec(mark + encoding)。渲染权威来源。" },
      "format": { "type": "string", "enum": ["svg","png"], "default": "svg" },
      "outDir": { "type": "string" },
      "name": { "type": "string" },
      "download": { "type": "boolean", "default": true }
    },
    "required": ["spec"]
  }
}
```

**渲染链:**
```typescript
import { compile } from 'vega-lite';
import { parse, View } from 'vega';

async function renderChart(specJson: string): Promise<string> {
  const spec = JSON.parse(specJson);
  const vegaSpec = compile(spec).spec;
  const view = new View(parse(vegaSpec), { renderer: 'none' });
  return view.toSVG(); // 纯 JS SVG 字符串
}
```

**依赖:** `vega-lite` + `vega`(纯 JS,零原生二进制)。

### 6.2 `src/diagram/types.ts`(引擎抽象,与 MediaProvider 平行但独立)

```typescript
// 注意:这套接口有意不复用 providers/types.ts。
// MediaProvider = 远程 API + apiKey + 异步轮询;DiagramEngine = 本地确定性 + 无网络 + 同步。
// 范式不同,强并会污染 MediaProvider(塞进无关方法)。

export type DiagramEngineName = 'mermaid' | 'd2' | 'graphviz';
export type DiagramFormat = 'svg' | 'png';

export interface DiagramRequest {
  code: string;                 // DSL 源码(渲染权威来源)
  engine?: DiagramEngineName;   // 默认走 detectEngine(code) 自动嗅探
  format?: DiagramFormat;       // 默认 svg(确定性 + Claude 可文本直读)
  theme?: string;               // mermaid: default/dark/forest/neutral; d2/graphviz 透传
  diagramType?: string;         // 可选(flowchart/sequence/er/...),仅信息性,DSL 内自描述
  outDir?: string;
  name?: string;                // 文件名(不含扩展名);省略则 diagram_<12位uuid>
  download?: boolean;           // 默认 true;false 时不落盘,SVG 内联/PNG data URI
}

export interface DiagramRenderOutput {
  svg: string;                  // SVG 总是产出(PNG 由 svg 转换)
  png?: Buffer;                 // format=png 且 rasterizer 可用时填充
}

export interface DiagramResult {
  engine: DiagramEngineName;
  format: DiagramFormat;
  localPath: string;            // 绝对路径,供 CC 用 Read 看
  bytes: number;
  sourceType: DiagramEngineName;
}

// MCP 返回给 CC 的结构化错误(可执行:带行列 + 修法提示)
export interface DiagramErrorBody {
  ok: false;
  engine: DiagramEngineName;
  exitCode: number;
  error: string;                // stderr 原文,含行列信息
  codeWithLines: string;        // 给 DSL 加上行号便于 CC 定位
  hint: string;                 // 常见修法提示
}

/** 每个引擎实现此接口 —— 与 MediaProvider 平行、独立。 */
export interface DiagramEngine {
  readonly name: DiagramEngineName;
  /** 运行时探测:mermaid 查包是否 require 到、d2/dot 查二进制是否在 PATH。 */
  isAvailable(): boolean | Promise<boolean>;
  /** 支持的图类型(供工具描述/schema 展示,非硬约束)。 */
  listTypes(): string[];
  /** 同步确定性渲染 —— 不走网络,无重试/轮询。失败抛 DiagramRenderError。 */
  render(req: DiagramRequest): Promise<DiagramRenderOutput>;
  /** 二进制/包缺失时的安装指引文本(进 error message)。 */
  installHint(): string;
}

export class DiagramRenderError extends Error {
  constructor(
    public engine: DiagramEngineName,
    public exitCode: number,
    public stderr: string,
    public codeWithLines: string,
    public hint: string,
  ) {
    super(`[${engine}] render failed (exit ${exitCode}): ${stderr}`);
    this.name = 'DiagramRenderError';
  }
}
```

### 6.3 `src/diagram/detect.ts`(零硬依赖的运行时探测)

```typescript
import { spawnSync } from 'node:child_process';

/** 查 PATH 上是否有某二进制(d2 / dot)。 */
export function hasBinary(name: string): boolean {
  try {
    const cmd = process.platform === 'win32' ? 'where' : 'which';
    const r = spawnSync(cmd, [name], { stdio: 'ignore', timeout: 3000 });
    return r.status === 0;
  } catch {
    return false;
  }
}

/** 查某 npm 包是否能动态 import(用于 mermaid / @resvg/resvg-js 可选降级)。 */
export async function isPackageAvailable(spec: string): Promise<boolean> {
  try {
    await import(spec);
    return true;
  } catch {
    return false;
  }
}
```

```typescript
  readonly name = 'mermaid' as const;
  private _avail?: boolean;

  async isAvailable(): Promise<boolean> {
    if (this._avail === undefined) {
      this._avail =
        (await isPackageAvailable('mermaid')) &&
        (await isPackageAvailable('jsdom'));
    }
    return this._avail;
  }

  listTypes() {
    return ['flowchart','sequence','class','state','er','gantt','pie','mindmap','journey','git','timeline','quadrant','c4','requirement'];
  }

  installHint() {
    return 'mermaid 引擎未就绪:npm i mermaid@11.4.x jsdom(核心依赖,默认随包装)。注意:进程内 mermaid 为 best-effort,复杂图可能需要 Kroki 回退或改用 D2。';
  }

  async render(req: DiagramRequest): Promise<DiagramRenderOutput> {
    const [{ default: mermaid }, { JSDOM }] = await Promise.all([
      import('mermaid'),
      import('jsdom'),
    ]);

    // mermaid 需 DOM:用 jsdom 注入。
    // 关键:渲染隔离到函数内,finally 里清理 globalThis,避免污染 image/video 主流程。
    const dom = new JSDOM('<!DOCTYPE html><body></body>');
    const w = dom.window as any;
    (globalThis as any).window = w;
    (globalThis as any).document = w.document;

    try {
      mermaid.initialize({
        startOnLoad: false,
        theme: (req.theme ?? 'default') as any,
      });
      // 固定 render id 避免随机性干扰确定性断言
      const id = 'd' + Math.random().toString(36).slice(2, 10);
      const { svg } = await mermaid.render(id, req.code);

      let png: Buffer | undefined;
      if (req.format === 'png') {
        try {
          png = svgToPng(svg, { width: 1200 });
        } catch {
          // resvg 不可用时不报错:落盘 svg,format 字段如实回退
        }
      }
      return { svg, png };
    } catch (e: any) {
      // mermaid 解析/渲染失败 → 结构化错误(带行列 + 修法提示)
      throw new DiagramRenderError(
        'mermaid',
        1,
        e?.message ?? String(e),
        addLineNumbers(req.code),
        extractHint(e?.message),
      );
    } finally {
      delete (globalThis as any).window;
      delete (globalThis as any).document;
    }
  }
}

function addLineNumbers(code: string): string {
  return code
    .split('\n')
    .map((line, i) => `${String(i + 1).padStart(3, ' ')} | ${line}`)
    .join('\n');
}

function extractHint(msg: string): string {
  if (/expecting.+SEQUENCE_DIAGRAM/i.test(msg)) return 'sequenceDiagram 关键字拼写或位置有误';
  if (/Parse error.*line/i.test(msg)) return '检查对应行的箭头语法(-->、->>、-->> 等)';
  return '常见问题:关键字拼写、缩进、箭头方向、括号/引号未闭合';
}
```

```typescript
import type { DiagramEngine, DiagramRequest, DiagramRenderOutput } from '../types.js';
import { hasBinary } from '../detect.js';
import { spawnFile } from '../render.js';

export class D2Engine implements DiagramEngine {
  readonly name = 'd2' as const;
  private _wasmAvail?: boolean;

  async isAvailable(): Promise<boolean> {
    // WASM 总是可用(bundled 必装);CLI 可选加分
    if (this._wasmAvail === undefined) {
      try {
        await import('@terrastruct/d2');
        this._wasmAvail = true;
      } catch {
        this._wasmAvail = false;
      }
    }
    return this._wasmAvail || hasBinary('d2');
  }

  listTypes() {
    return ['flowchart','sequence','class','er'];
  }

  installHint() {
    return 'd2 引擎未就绪。WASM 包:@terrastruct/d2(应已随包装)。CLI 二进制(可选):macOS brew install d2,通用 curl -fsSL https://d2lang.com/install.sh | sh -';
  }

  async render(req: DiagramRequest): Promise<DiagramRenderOutput> {
    const fmt = req.format ?? 'svg';

    // 优先 WASM 进程内(恒可用)
    if (this._wasmAvail) {
      return this.renderWasm(req, fmt);
    }
    // 回退 CLI 二进制
    if (hasBinary('d2')) {
      return this.renderCli(req, fmt);
    }
    throw new Error(this.installHint());
  }

  private async renderWasm(req: DiagramRequest, fmt: DiagramFormat): Promise<DiagramRenderOutput> {
    const { D2 } = await import('@terrastruct/d2');
    const d2 = new D2();
    const compiled = await d2.compile(req.code, { sketch: req.theme === 'sketch' });
    let svg = await d2.render(compiled.diagram, compiled.renderOptions);

    // D2 WASM 输出含 XML 声明头,去除以保证下游统一以 <svg 开头
    svg = svg.replace(/^<\?xml[^>]*\?>\s*/, '');

    if (fmt === 'png') {
      const { svgToPng } = await import('../svg-to-png.js');
      return { svg, png: svgToPng(svg, { width: 1200 }) };
    }
    return { svg };
  }

  private async renderCli(req: DiagramRequest, fmt: DiagramFormat): Promise<DiagramRenderOutput> {
    const args = ['--layout=elk', `--theme=${req.theme ?? 0}`];
    if (fmt === 'png') {
      // d2 CLI 通过 D2_FORMAT 环境变量或文件扩展名控制输出格式
      const out = await spawnFile('d2', [...args, '-'], req.code, 'png');
      return { svg: '', png: out };
    }
    const out = await spawnFile('d2', [...args, '-'], req.code, 'svg');
    return { svg: out.toString('utf8') };
  }
}
```

```typescript
  if (!e) throw new Error(`unknown diagram engine: ${name}`);
  return e;

export async function renderDiagram(req: DiagramRequest): Promise<DiagramResult> {
  // 1) 确定 engine:auto 按 DSL 首行嗅探;显式则用指定
  let engineName: DiagramEngineName;
  if (req.engine && req.engine !== ('auto' as any)) {
    engineName = req.engine;
  } else {
    engineName = detectEngine(req.code, req.diagramType);
  }

  const engine = getEngine(engineName);
  const avail = await Promise.resolve(engine.isAvailable());
  if (!avail) {
    // 不可用 → 返回含安装指引的错误(CC 可改用其他引擎重写 DSL)
    throw new Error(engine.installHint());
  }

  // 2) 确定 format
  const fmt: DiagramFormat = req.format ?? config.diagram.defaultFormat;

  // 3) 渲染(渲染即校验,失败抛 DiagramRenderError)
  const out: DiagramRenderOutput = await engine.render({ ...req, format: fmt });

  // 4) 落盘或内联
  if (req.download === false) {
    // 不落盘:SVG 内联文本 / PNG data URI
    return {
      engine: engineName,
      format: fmt,
      localPath: '',
      bytes: fmt === 'png' && out.png ? out.png.length : Buffer.byteLength(out.svg, 'utf8'),
      sourceType: engineName,
    };
  }

  const outDir = req.outDir ?? config.outDir;
  const localPath = await saveDiagram(out, fmt, outDir, req.name);
  return {
    engine: engineName,
    format: fmt,
    localPath,
    bytes: fmt === 'png' && out.png ? out.png.length : Buffer.byteLength(out.svg, 'utf8'),
    sourceType: engineName,
  };
}

/** 落盘:渲染器直写文件(不调用 downloadAsset——本地渲染无 URL)。 */
async function saveDiagram(
  out: DiagramRenderOutput,
  fmt: DiagramFormat,
  outDir: string,
  name?: string,
): Promise<string> {
  await fs.mkdir(outDir, { recursive: true });
  const ext = fmt === 'png' ? '.png' : '.svg';
  const fileName = name
    ? `${name}${ext}`
    : `diagram_${crypto.randomUUID().slice(0, 12)}${ext}`;
  const fp = path.join(outDir, fileName);
  await fs.writeFile(fp, fmt === 'png' && out.png ? out.png : out.svg);
  return fp;
}

/** d2/graphviz 共用:stdin→stdout 子进程。 */
export function spawnFile(
  bin: string,
  args: string[],
  stdin: string,
  _fmt: string,
): Promise<Buffer> {
  return new Promise((resolve, reject) => {
    const p = spawn(bin, args);
    const chunks: Buffer[] = [];
    const errChunks: Buffer[] = [];
    p.stdout.on('data', (c) => chunks.push(c as Buffer));
    p.stderr.on('data', (c) => errChunks.push(c as Buffer));
    p.on('error', reject);
    p.on('close', (code) => {
      if (code === 0) {
        resolve(Buffer.concat(chunks));
      } else {
        const err = new Error(
          `${bin} exited ${code}: ${Buffer.concat(errChunks).toString('utf8')}`,
        ) as Error & { status: number };
        err.status = code ?? 1;
        reject(err);
      }
    });
    p.stdin.end(stdin);
  });
}

export function addLineNumbers(code: string): string {
  return code
    .split('\n')
    .map((line, i) => `${String(i + 1).padStart(3, ' ')} | ${line}`)
    .join('\n');
}
```

### 8.1 `src/diagram/detect-engine.ts`(DSL 首行嗅探)

```typescript
import type { DiagramEngineName } from './types.js';

/**
 * 按 DSL 首行关键字嗅探引擎。
 * 注意:type 参数对 Mermaid 非权威,真实类型以 code 首行为准。
 */
export function detectEngine(code: string, typeHint?: string): DiagramEngineName {
  const firstLine = code.trim().split('\n')[0];

  // Mermaid 关键字(覆盖 15 种图型)
  const mermaidKeywords = /^(graph|flowchart|sequenceDiagram|classDiagram|stateDiagram|erDiagram|gantt|pie|mindmap|journey|gitGraph|timeline|quadrantChart|requirementDiagram|C4Context)/;
  if (mermaidKeywords.test(firstLine)) return 'mermaid';

  // Graphviz DOT
  const dotKeywords = /^(strict\s+)?(digraph|graph)\s/;
  if (dotKeywords.test(firstLine)) return 'graphviz';

  // gantt 只 mermaid 支持 → 即使嗅探到 d2 也强制 mermaid
  if (typeHint === 'gantt') return 'mermaid';

  // D2 语法最宽松,作为兜底
  return 'd2';
}
```

### 8.2 `src/diagram/svg-to-png.ts`(全家桶共享)

```typescript
// 全家桶共享:所有 generate_* 工具统一通过此 helper 做 SVG→PNG。
// 刻意替代 puppeteer/chromium:resvg 仅几 MB 且确定性更好。
export async function svgToPng(
  svg: string,
  opts?: { width?: number; scale?: number; background?: string },
): Promise<Buffer> {
  const { Resvg } = await import('@resvg/resvg-js');
  const resvg = new Resvg(svg, {
```

## 九、风险与边界

### 9.1 技术风险

| 风险 | 严重度 | 缓解措施 |
|---|---|---|
| **mermaid 进程内渲染脆弱** | 🔴 高 | 三层兜底:进程内(best-effort)→ Kroki 远程(可选)→ CC 跨引擎重写为 D2。README 诚实声明。固定 mermaid 版本 11.4.x。 |
| **mermaid 版本升级 break** | 🟡 中 | 固定 `11.4.x`,package.json 锁版本,不自动升级。CI 跑 mermaid 全图类型矩阵。 |
| **D2 WASM worker 不退出** | 🟢 低 | MCP server 是长驻进程,worker 不退出无碍。一次性脚本需 `process.exit(0)`。 |
| **OG 卡片中文字体** | 🟡 中 | P2 单独处理:字体 subset(fontmin)按需加载,避免 10MB+ 全量字体。 |
| **Satori flexbox 限制** | 🟡 中 | 提供 JSX 模板库降低试错;README 列明不支持的 CSS(grid/block)。 |
| **resvg 原生二进制跨平台** | 🟢 低 | @resvg/resvg-js 有完善的预编译多平台 .node 文件(darwin-x64/arm64/linux-x64/win)。 |
| **DSL 语义错误(非语法)** | 🟡 中 | 这是 CC 的职责。MCP 只校验语法(渲染即校验)。语义靠 CC 的 diagramming skill 自检清单。 |

### 9.2 边界(不做什么)

1. **MCP 不内置 LLM**——不生成 DSL、不做语义理解、不判断用户意图。
2. **不强制 JSON 中间协议**——CC 直接出 DSL,除非实测某类图失败率不可接受。
3. **不引入 Puppeteer / Chromium**——mermaid-cli(mmdc)完全剔除。
4. **Sharp 不进 generate_* 工具族**——它是"改图"不是"生图",仅作内部 helper 或独立 MCP。
5. **diagram 不进 providers/ 构造逻辑**——范式不同(本地 vs 远程、同步 vs 异步、免费 vs 计费)。
6. **不做 engine=auto 的语义选路**——auto 仅按 DSL 首行嗅探语法家族,真正的引擎选择是 CC 的语义决策。

### 9.3 向后兼容

- `generate_image` / `create_video` / `get_video` / `list_models` 零改动。
- 现有 config.json 无 diagram 块时走默认值,老用户无感。
- `list_models` 返回新增 `diagramEngines` 字段(可选,供 CC 知道哪些引擎可用),不影响现有字段。
