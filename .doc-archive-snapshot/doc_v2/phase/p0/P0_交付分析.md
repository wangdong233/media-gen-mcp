# P0 阶段交付分析(结构化生图:diagram + qr + chart)

> 阶段目标:在不引入第二个 MCP server 的前提下,把"结构化生图"(用户视角的"生图"第二种)融入 media-gen-mcp,与既有 AI 生图共用一套心智模型、一套落盘流程、一套配置。
> 交付日期:2026-07-14。状态:**已交付**(实现 + 审查 + 测试 + 文档)。

---

## 1. 背景与架构裁决

### 1.1 用户立场(产品视角,优先级最高)

> "结构图和 AI 生图确实是两种生图类型,但是从用户角度来讲这都是生图,在一种框架中做融合这不是自然而然的选择吗"

由此推翻了"独立 diagram-mcp(B 方案)"的技术范式分离建议,采用 **A 改进版:扩展 media-gen-mcp**。用户心智模型只有"生成一张图",技术实现(AI 渲染 vs 本地确定性渲染)是实现细节,不应暴露给用户。

### 1.2 架构决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 引擎 vs Provider 分离 | 独立 `DiagramEngine` 接口,不并入 `MediaProvider` | AI 模式走"可插拔厂商 + 在线 API";结构化走"可插拔引擎 + 本地渲染"。二者抽象维度不同(厂商/连接 vs 引擎/语法),强行合并会污染 MediaProvider 契约 |
| 主图引擎 | **D2 WASM**(`@terrastruct/d2`) | 进程内 SVG 渲染,无浏览器/无 Java/无 Chromium/无 spawn;唯一成熟可用的纯进程内方案。Mermaid 进程内方案不可靠(isomorphic-mermaid 模块损坏,mermaid-isomorphic 依赖 Chromium) |
| 数据图表 | **Vega-Lite + vega** | 声明式 JSON → scenegraph → SVG,纯 JS。Claude 生成 spec 友好 |
| 二维码 | **qrcode npm** | 纯 JS,零二进制依赖,SVG/PNG |
| 光栅化(PNG) | **@resvg/resvg-js** | Rust WASM,1s 安装,无 Chromium。diagram/chart 共用 |
| 落盘流程 | 共用 `writeLocalRender()` helper | 三类工具复用:文件名清洗 + PNG 断言 + 去重 |

### 1.3 用户步骤影响(产品验收)

> "我现在想知道从用户角度来讲,步骤有没有增多"

**结论:步骤零增多。** 用户仍只需"说一句话";新增的三类工具对用户而言与 AI 生图同形(都是"生成一张图"),Claude 自动判别走 AI 还是本地引擎、自动生成对应 DSL/JSON。接入命令、配置、Key 流程完全不变。

## 2. 交付物

### 2.1 新增工具(3 个,MCP 工具总数 5 → 7)

| 工具 | 输入 | 输出 | 引擎 |
|---|---|---|---|
| `generate_diagram` | `code`(D2 DSL)、engine、format、theme、diagramType、name、outDir | SVG/PNG 本地路径 | D2 WASM |
| `generate_qrcode` | `text`、format、margin、errorCorrectionLevel、dark/light、name、outDir | SVG/PNG 本地路径 | qrcode |
| `generate_chart` | `spec`(Vega-Lite JSON)、format、name、outDir | SVG/PNG 本地路径 | vega-lite + vega |

```

src/chart.ts   # Vega-Lite 图表引擎 renderChart()
src/index.ts   # +3 工具 schema/handler + writeLocalRender() helper
```

- `qrcode`(+ `@types/qrcode` dev)
- `@resvg/resvg-js`(SVG→PNG,diagram/chart 共用)

## 3. 代码审查(架构清单驱动,对抗验证)

按 [[architecture-philosophy-project]] 清单执行两轮审查。首轮 16-agent 工作流扫出候选问题,对抗验证后**确认 10 个**,全部修复。关键项:

| 编号 | 级别 | 问题 | 修复 |
|---|---|---|---|
| **CQ-1** | 严重(资源泄漏/OOM) | D2 每次渲染 `new D2()` → 创建 worker_thread + 22MB WASM,无 terminate → 内存/线程泄漏 | lazy singleton(`this.d2 ??= new D2()`)+ 串行队列防 `sendMessage` 并发竞态 |
| **CQ-2** | 功能无效 | schema 声明了 `theme`,但 `D2Engine.render()` 从未读取 → 主题参数静默失效 | theme 解析为 themeID 数字,合并进 renderOptions |
| **CQ-3** | 资源泄漏 | Vega `View` 每次渲染泄漏 dataflow + scenegraph | `try/finally` 中 `view.finalize()` |
| **BL-04** | 安全(路径遍历) | `name` 参数未清洗,可含 `../` 写出 outDir 之外 | `writeLocalRender` 内 `path.basename()` 清洗 |
| **DL-02** | 静默错误 | format=png 但引擎未产出 PNG → 静默写 SVG,产出与请求不符 | PNG 缺失则显式抛错 |
| **R-CI-02** | 重复代码 | 三处相同的 6 行落盘块 | 抽 `writeLocalRender()` helper 统一 |

> 其余 4 项为文档/schema 描述一致性与边界校验,均已修复。审查临时文件 `test_d2_tmp.mjs` 已删除并加入 `.gitignore`。

## 6. 已知边界 / 后续

- **P0 仅 D2 引擎**:`generate_diagram` 的 `engine` 参数 enum 含 mermaid/graphviz,但 `getDiagramEngine()` 目前仅返回 d2;后两者为 P1+ 占位。传 mermaid/graphviz 会返回明确错误而非静默。
- **D2 worker 不显式 terminate**:`@terrastruct/d2` 未暴露 terminate API;靠 lazy singleton 复用避免泄漏,MCP server 生命周期内常驻一个实例可接受。若未来支持热卸载需 upstream 支持。
- **PNG 光栅化字体**:Resvg 渲染 SVG 内文本依赖系统字体;极少数字体可能回退。当前图/表文本以常见字体为主,暂不内嵌字体子集(P2 评估)。
