## 一、关键技术决策(5-agent 调研结论,confidence high)

### 🔴 paddleocr-mcp --http 是 MCP 协议,不是 REST —— 不用

`paddleocr_mcp --http` 走 **MCP JSON-RPC over StreamableHTTP**(FastMCP 默认路径 `/mcp`,需 initialize 握手 + Mcp-Session-Id + SSE 解析)。issue #16586/#16316 用户都误判协议打 `/ocr` 拿 404。Node 裸 fetch 复刻握手+SSE 痛苦且易错。

### ✅ 走 PaddleX 原生 serving REST(推荐 A)

paddleocr_mcp 只是 MCP wrapper,真正干活的是 PaddleOCR 引擎。**让用户直接跑 PaddleX serving**,PaddleocrProvider 当 REST 客户端直连——Node fetch 一个 POST 搞定,无会话,对称 Agnes/Zhipu。

**部署**(用户侧,README 手册):
```bash
pip install paddlex paddlepaddle  # 或 paddlepaddle-gpu
paddlex --serve --pipeline PP-StructureV3.yaml --port 8080
# 或纯 OCR:paddlex --serve --pipeline OCR --port 8080
```
用户配 `providers.paddle.baseUrl = "http://127.0.0.1:8080"`,PaddleocrProvider 指向它。

## 二、PaddleX serving REST API(已调研确认)

**统一**:POST + `Content-Type: application/json`(非 multipart);`file` 字段接受 **URL** 或 **Base64 裸串**(不加 `data:` 前缀,server 自动识别)。

### 端点 1:`POST /ocr` — 纯文本 OCR(PP-OCRv5/v6)
- 请求:`{ file: string, fileType?: int(1=image) }`
- 响应:`result.ocrResults[]`(每项 text + bbox + confidence)
- 用于 **extract_text**(paddle 接管时,中文 SOTA;tesseract 退兜底)

### 端点 2:`POST /layout-parsing` — 版面/表格/图表/Markdown(PP-StructureV3 + PaddleOCR-VL 共用)
- 请求:`{ file, fileType?, useChartRecognition?: bool(默认 false) }`
- 响应:`result.layoutParsingResults[]`,含 `markdown.text`(Markdown 全文,表格在内联 HTML)+ `prunedResult`(结构化)
- 用于:
  - **extract_table**:解析 markdown 里的 `<table>` 或 prunedResult 表格结构 → HTML
  - **analyze_chart**:`useChartRecognition:true` → 解析图表数据
  - **describe_image**:PaddleOCR-VL 的 markdown 描述

## 三、PaddleocrProvider 设计(src/providers/paddle.ts)

`implements MediaProviderBase, VisionProvider`:

| 方法 | 实现 |
|---|---|
| `name` | `"paddle"` |
| `listModels/listVisionModels` | `[]` |
| `visionTasks()` | `["extract-text","extract-table","analyze-chart","describe-image"]`(全能主力) |
| `visionConstraints()` | `{ languages: ["en","zh-Hans","zh-Hant","ja","ko"] }` |
| `capabilities()` | `{ image/video 全 false }`(纯识别) |
| `health()` | `{ configured: !!baseUrl, cooldown, lastErrorAt? }`(未配 baseUrl→configured=false,getFallbackProvider 跳过) |
| `tier()` | `10`(主力,高于 tesseract=1) |
| `notifyUnavailable(e)` | 设 60s cooldown(symmetric agnes) |

### recognize(req) 主逻辑
```
file = uriToFile(req.image)  // data:URI→base64 裸串;http(s)→原样
if (task === "extract-text") → POST /ocr {file,fileType:1} → 解析 ocrResults → {text, blocks}
else (table/chart/describe) → POST /layout-parsing {file, useChartRecognition: task==="analyze-chart"} → 解析 markdown
  - extract-table: 提取 markdown 的 <table>...</table> → {table:{format:"html",content}}
  - analyze-chart: 提取图表数据(useChartRecognition 输出)→ {chart:{...}}
  - describe-image: markdown.text 全文 → {description}
```

### file 字段处理
- `data:image/png;base64,XXX` → 剥前缀,传 `XXX`(base64 裸串)
- `http(s)://...` → 原样传(server 拉取)
- `fileType`:data URI 推断 image→1;URL 省略(server 推断)

### HTTP 复用
- `withRetry` 包 fetch(5xx/网络退避,复用 http.ts)
- 错误挂 `.status/.body`(symmetric agnes request())
- `isFallbackWorthy` 判定(5xx/401/403/429→fallback;tesseract 兜底 extract-text)

## 四、3 工具设计

### extract_table
| 参数 | 说明 |
|---|---|
| `image`(必填) | URI |
| `format?` | html/markdown/json/latex,默认 html |
| `provider?` | 默认 paddle(M2 唯一支持 table 的) |
| `name/outDir/download` | 落盘 |

handler:resolveProvider vision → asVisionProvider → visionTasks 门禁(table)→ recognize → fallback(M2 paddle 挂无 table 兜底,清晰报错;不静默降级到 OCR 假装表格)。

### analyze_chart
| 参数 | 说明 |
|---|---|
| `image`(必填) | URI |
| `chartType?` | bar/line/pie/scatter/auto |
| `provider?` | paddle(M2)/vlm(M3 fallback) |

### describe_image
| 参数 | 说明 |
|---|---|
| `image`(必填) | URI |
| `question?` | 留空=默认描述;存在=VQA(M2 paddle-VL 基础;M3 vlm 增强) |

## 九、M2 审查结果 + 修复(5-agent,31 findings)

**多 high(含 mock 掩盖的真实 bug)**,关键全修:

| finding | 修复 |
|---|---|
| 🔴 extractText 解析假设错(ocrResults[] 每元素是「一图」含 rec_texts[]/rec_scores[],原假设每元素一行→真实接入 extract_text 永远空串,mock 掩盖) | 展开并行数组 rec_texts/rec_scores |
| 🔴 errorCode 未检(PaddleX 应用层错误是 HTTP 200 + body.errorCode!=0,原只判 !res.ok 漏掉) | request 加 errorCode 检查 |
| 🟡 format 不一致(schema 4 格式 + handler 按 hints.format 决定扩展名,但 provider 硬编码 html→format=latex 拿 html 写 .tex) | provider 按 hints.format 返回(html 提<table>/markdown 返 md/json+latex fallback+warning)+ handler 用 result.table.format 决定扩展名 |
| 🟡 analyze_chart 不落盘(schema 有 download 但 handler 不落盘) | 加落盘 .json |
| 🟡 extract_table 逆操作提示错位(应是 analyze_chart↔generate_chart,非 extract_table) | 删 |
| 🟡 describe_image question 被 paddle 忽略(PaddleOCR-VL 是文档解析非 VQA) | schema 标注(M3 vlm 支持 VQA) |
| 🟡 PaddleConfig.rateLimitTtlMs 死字段(agnes/zhipu 用了,paddle 接受即丢弃) | 删字段 |
| 🔵 uriToPaddleFile fileType 恒 1 误导 | 删 fileType,只返 file(PaddleX 自动识别) |

**未改(🔵 低优/已知边界,标 M3/M4)**:extract_text 未用 runVisionTask(medium R-CI-08,碰 M1 测试,M3 统一);命名 extractText vs layoutParsing(low);analyze_chart chart 占位结构(已知边界,真实 PaddleX chart 响应格式待用户部署验证,warning 已加)。
