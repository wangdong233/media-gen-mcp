# 卡片工具逃逸问题审查:功能缺失 vs 描述/参数缺失

> 起因:测试 #2 助手称"generate_card 做不出同行混合字号引号",逃去 Pillow —— 但 Satori 能做(已加 `quoteStyle:"flank"`,0.3.5)。
> 本审查:全面排查"助手以为做不到而逃向 HTML/Pillow"的情况,判定每项是**功能真缺失**还是**描述/参数没讲清楚**。
> 方法:读 schema/描述 + 用户视角需求穷举(86 项 brainstorm)交叉比对。

---

## 1. 逃逸根因分类(三类)

| 类别 | 含义 | 修法 |
|---|---|---|
| **A. 描述缺失** | 工具**能**做,但描述没传达能力面/边界 → 助手形成错误心智模型,误判"做不到" | 重写描述(能力 + 限制) |
| **B. 参数/功能缺失** | 引擎**能**做,但没暴露参数(如图片) → 用户要这个能力时无路可走 | 加参数 |
| **C. 引擎硬限制** | Satori 真**做不到**(JS/动画/文字沿曲线) | 文档标注为合法逃逸边界 |

**flanking-quote 案**:同时是 B(原无 flank 布局参数,0.3.5 已加)+ A(描述没传达 Satori 是 flexbox、支持行内混合字号,致助手误判"Satori 做不到")。

## 2. 能力矩阵(按"很常见"需求 × 覆盖)

### 已覆盖(✅)
标题/副标题/正文/页脚 · 渐变标题(titleGradient)· 辉光(glow)· 玻璃面板(panel)· 引言(top/flank)· 纯色/线性/放射背景 · CJK · 彩色 emoji · 阴影/圆角/边框(panel)· 模糊光斑(hero blob)· 自定义尺寸 · SVG/PNG。

### B 类:参数/功能缺失(Satori 能做,未暴露)—— 逃逸主因

| 需求 | 频率 | 现状 | 决策 |
|---|---|---|---|
| **内嵌 logo / 品牌标** | 很常见 | ❌ 无 image 参数 | **本期加 `logo`** |
| **圆形 avatar / 头像** | 很常见 | ❌ | logo 参数 + 圆角可覆盖 |
| **全屏照片背景** | 很常见 | ❌ 无 bgImage | 文档列入下一期(bgImage) |
| **图文分栏(文|图)** | 很常见 | ❌ | 下一期(需新模板) |
| **底部 logo+URL 条** | 很常见 | ❌(footer 是文本) | logo + footer 近似 |
| **自动缩放长标题(防溢出)** | 很常见 | ❌ 固定字号 | 下一期(auto-fit) |
| 卡内图标(非 emoji) | 有时 | 半(仅 emoji) | 可用 icon 工具产物做 logo |
| 徽标 pill(#64) | 很常见 | 半(subtitle 近似) | 下一期 |

### C 类:引擎硬限制(Satori 做不到,合法逃逸)
JS 执行(星场等)· 动画 · 文字沿曲线/弧 · 双色处理(duotone)· 3D 挤出。**这些才该退到 HTML+浏览器**——描述需明确标注,让助手知道边界。

## 3. 结论(回答"功能缺失 vs 描述缺失")

- **主因是 A(描述缺失)+ B(图片类参数缺失),不是引擎不行。** flank-quote 的"做不到"判断是 A 类误解;logo/avatar/照片底是 B 类真缺口。
- 引擎(Satori)能力其实很强(flexbox、混合字号、filter:blur、img、渐变...),**绝大多数"酷卡片"能做**;只有 JS/动画是 C 类硬限制。
- **修法**:
  1. **重写 generate_card 描述**(A 类根治):讲清能力面(模板/特效/富文本/Satori flexbox)+ 限制(无 JS/动画),让助手不再误判。
  2. **加 `logo` 参数**(B 类最大缺口):内嵌图片(URL/data URI/本地路径),Satori `<img>` 渲染。
  3. 文档标注 C 类边界 + B 类待办(bgImage/分栏/auto-fit)。
