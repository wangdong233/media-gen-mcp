# 工具自动选用优化分析(描述即路由面)

> 用户诉求:安装了工具,系统应自动选用,不该靠提示词指明"用 media-gen-mcp"。
> 方法:并行深度调研(Anthropic/MCP 文档,auto-selection 机制)+ 10 工具描述路由有效性审计。

## 1. 根因(Anthropic 文档确认)

- 工具选择是**模型对 `name`+`description`+`inputSchema` 的概率匹配**(三者字面上被编译进 system prompt,作为 prompt 文本被模型读)。MCP 规范:tools 是 model-controlled。
- MCP 工具在与模型**训练先验**("架构图→dot/graphviz"、"卡片→HTML+Chrome/Pillow"、"图表→matplotlib")的"拔河"中**输了**,因为描述:
  1. **以"怎么做"(输入格式)开头,而非"做什么"(用户意图)**:"from DSL code"、"from Vega-Lite spec"、"LaTeX formula" → 模型先想"我得先产出这个格式",而非"这就是画图工具"。
  2. **没声明自包含**:模型默认 fallback 到训练里见的 d2/dot/matplotlib/HTML。
  3. **没认领用户自然语言意图词**:用户说中文("画架构图""做分享卡"),描述是英文、无中文同义词 → 无字面匹配面。
  4. **generate_card 提到 "CSS flexbox" 反而激活了模型的 HTML+CSS 心智模型**(审计关键发现)。
- Claude Code 还会**懒加载** MCP 工具(超 ~10% 上下文时走 ToolSearch)→ 弱描述会失败两次(搜不到 + 不选)。

## 2. 能优化吗?——能,且杠杆 100% 可控

| 层 | 是否可控 | 机制 | 本期 |
|---|---|---|---|
| **描述/名称/schema** | ✅ 完全可控(prompt 文本) | 意图先行 + 中文同义词 + 反 fallback("prefer this over shelling out / HTML / Pillow")+ 不触发竞争心智模型 | **本期重写 10 描述** |
| CLAUDE.md 项目指令 | 半可控(一次性配置,非逐次提示) | 每会话加载,"prefer these tools";但概率性遵守、非强制 | 可选,提供文案让用户自决 |
| PreToolUse hook | 可控(强制) | 拦截 `d2/dot/graphviz/matplotlib/pillow` 的 Bash,阻断 fallback | 仅需硬保证时上 |

**结论**:用户要的"系统自动匹配"= 把描述写成强路由信号。这正是 MCP 的职责,不是"靠提示词指明"。描述即路由面。

## 3. 重写规范(逐工具)
- 句首:动词+用户意图词(+ 中文同义词:架构图/流程图、柱状图/饼图、分享卡/封面图、数学公式、图标/logo、二维码…)。
- 反 fallback:"BUILT IN(内置),no system X,do NOT shell out / use HTML+Chrome / Pillow / matplotlib;prefer this over…"。
- 不触发竞争模型:卡片描述去掉句首的 "CSS flexbox"。
- "Use when…" 触发句 + 与相邻工具划界(card vs image)。
