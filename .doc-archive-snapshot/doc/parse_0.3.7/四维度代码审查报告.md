# generate_card 四维度代码审查报告(0.3.6 → 0.3.7)

> 方法:工作流 4 维度并行审查(代码规范/数据逻辑/业务逻辑/端到端架构)× 对抗验证(28 agent);只留验证为真实的问题。

## 确认问题与修复(12 项)

### 崩溃/正确性(高优)

| # | 位置 | 问题 | 修复 |
|---|---|---|---|
| 1 | card.ts glow | `glow:true` 派生 `0 0 40px ${accent}99`——3 位 hex(#fff→#fff99)或 8 位 hex 会生成**非法颜色 → Satori 解析抛错/辉光静默失效** | 新增 `withAlpha()`:#RGB/#RRGGBB → rgba(...,0.6);其余白色兜底。不再字符串拼 alpha |
| 2 | card.ts glow / index.ts | `glow:"false"`(字符串)被当 text-shadow 值 `false` → **Satori 抛 "Failed to parse textShadow" 整卡崩** | glow 字符串值为 "false" 时 → 不设辉光(undefined) |
| 3 | card.ts fontPath | fontPath 同时按 400 和 700 加载**同一份文件**→ Satori 用 regular 数据响应 700,**标题不粗体且 weight 标签错** | fontPath 只注册一次(400);单文件无真粗体,诚实 |
| 4 | card.ts titleGradient+glow | 两者同设时 glow 被**静默丢弃**(Satori background-clip:text 把文字裁成渐变,阴影随之裁掉,输出与仅渐变字节一致) | Satori 限制不可修;在 schema/description 标注"二者不叠加,择一" |

## 误报(对抗验证驳回,未改)
- `type Node` 遮蔽全局 DOM Node:本文件零 DOM 操作、模块作用域不外泄,无实际混淆。
- 局部变量 `ls` 命名:与 `bg/sub` 等既有缩写一致,非缺陷。
- glow schema type:"string" 与 handler 布尔分支"不一致":handler 的布尔归一化是**刻意的防御**(LLM 常发字面量布尔),删之是回归。
- hasCJK 漏 Hangul/假名:**真**,但 Noto Sans SC 字体本身无 Hangul/假名字形,扩正则也不渲染——根因是字体非正则,已归入#7 文档修正。
