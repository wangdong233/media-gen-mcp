# Agnes AI 通用 MCP Server 实施方案 —— Claude Code 驱动图文/视频生成

> **成文日期**：2026-07-10
> **调研方法**：deep-research 工作流 —— 105 个子 agent、5 路并行 Web 搜索、23 个一级源抓取、25 条关键论断 3 票对抗验证（15 确认 / 10 否决）、约 411 万 token、508 次工具调用、耗时约 40 分钟。
> **目标**：为 Claude Code（CC）设计并落地一个**通用的 Agnes AI MCP server**，统一封装：图像（文生图、图生图）、视频（文生视频、图生视频、关键帧动画）。
> **路由决策**：全直连 Agnes（`https://apihub.agnes-ai.com/v1`），**不经 new-api 中转**（理由见 §3.4 与既有《new-api 生图 MCP 方案调研报告》）。
> **最关键的一条纠偏**：业界常说的"MCP 协议本质上做不了视频"是**错的**——对抗验证以 0-3 / 1-2 否决了所有协议层不可能论断。真正的壁垒在**实践层**（客户端超时、非标端点、需轮询+文件回退），MCP 完全可以覆盖视频，只是不能用"薄同步透传"，必须做显式异步设计。这决定了本方案的整个架构走向。

---

## 一、执行摘要（TL;DR）

1. **技术上清晰可行**：Agnes API 表层 OpenAI 兼容，但通过**非标准扩展**强制要求**专用封装**——这正是"为什么没有现成通用 MCP"的根因。
2. **图像侧**：端点 `POST /v1/images/generations`，OpenAI 同构响应（`data[].url` / `data[].b64_json`），但扩展了 `image[]`（图生图，**走同一 `/generations` 端点而非 OpenAI 的 `/images/edits` 多部分上传**）、`return_base64`、`extra_body.response_format`。→ 任何硬编码 OpenAI schema 的 MCP 都无法原样透传。
3. **视频侧**：完全落在 OpenAI 不存在的端点上（`POST /v1/videos` + `GET /agnesapi?video_id=` 推荐 / `GET /v1/videos/<task_id>` 兼容），异步四态（queued→in_progress→completed|failed），三种异构模式，硬约束（`num_frames` 实际只接受离散值 81/121/161/241/441）。
4. **壁垒是实践层**：MCP 客户端（CC/Cursor/Postman）有 ~5 分钟硬超时，会在多分钟视频任务完成前断连 → 必须用 **submit/poll 双工具 + 文件优先回退 + `resetTimeoutOnProgress`** 兜底。
5. **现状盘点**：最成熟的 `lansespirit/image-gen-mcp` 只做图、零视频；已存在一个 `zssty2010/agnes-mcp-server` 封装了图+视频，但 **0 star、9 天龄、未经验证、license 存疑**——可作为参考，不建议直接依赖。
6. **推荐方案**：基于 **TypeScript/Node + `@modelcontextprotocol/sdk`** 自建，**provider 可插拔架构**（Agnes 为首个实现），4 个工具（`generate_image` / `create_video` / `get_video` / `list_models`），默认非阻塞（submit→poll），可选 `wait=true` 阻塞模式配 progress 通知。

> ✅ **已落地并验证**：`media-gen-mcp/` 项目已实现 —— `tsc` build 零错误；stdio 握手 + `tools/list` 通过；真实 key `generate_image` 端到端出图（1.61MB 落盘）。接入见 §5.6 与 `media-gen-mcp/README.md`。

## 二、Agnes API 完整契约（一级源，无模糊）

> 全部参数与字段均经官方文档（`agnes-ai.com/doc/*` 与 canonical `wiki.agnes-ai.com`）逐字核对，3-0 验证通过。

### 2.1 全局约定

| 项目 | 值 |
|---|---|
| Base URL | `https://apihub.agnes-ai.com/v1` |
| 认证 | `Authorization: Bearer <YOUR_API_KEY>` |
| 兼容性声明 | 官方自称兼容 OpenAI 接口，迁移只需改 base_url / key / model |
| Key 获取 | 登录控制台 `platform.agnes-ai.com` → API Key 管理页 → 创建 |

### 2.2 图像 API（文生图 + 图生图）

**端点**：`POST https://apihub.agnes-ai.com/v1/images/generations`（文生图与图生图**共用同一端点**，靠是否传 `image[]` 区分）

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model` | string | 是 | 模型名，见 §2.4 |
| `prompt` | string | 是 | 文本描述 |
| `size` | string | 否 | 尺寸 |
| `n` | integer | 否 | 生成数量 |
| `image` | **string[]** | 图生图必填 | **输入图像数组**，支持公网 URL 或 Data URI（Base64） |
| `return_base64` | boolean | 否 | Agnes 扩展，OpenAI 规范无此字段 |
| `extra_body.response_format` | string | 否 | 输出格式，常用 `url` 或 `b64_json`（**嵌套在 `extra_body` 下**，而标准 OpenAI REST 放顶层） |

**响应**：OpenAI 同构 —— `data[].url`、`data[].b64_json`。

**🔴 承重不兼容点（决定不能套用通用 OpenAI 图像 MCP）**：
- Agnes 图生图把 `image[]` 路由到**同一个 `/images/generations`** 端点；OpenAI 则用**独立的 `/v1/images/edits` + multipart 上传**。
- 这是结构性分歧：`lansespirit/image-gen-mcp` 这类按 OpenAI schema 硬编码的 server，其 `edit_image` 工具会打 `/images/edits` multipart，**Agnes 不接受**。
- ⚠️ 待运行时确认：`image[]` 最大长度、单张最大 base64 size、是否完全拒绝 multipart（见 §6.1）。

### 2.3 视频 API（文生视频 + 图生视频 + 关键帧动画）

**端点**：
- 创建任务：`POST https://apihub.agnes-ai.com/v1/videos`
- 取结果（**推荐**）：`GET https://apihub.agnes-ai.com/agnesapi?video_id=<VIDEO_ID>` ⚠️ 不在 `/v1/` 命名空间下
- 取结果（**兼容/legacy**）：`GET https://apihub.agnes-ai.com/v1/videos/<TASK_ID>`

**三种异构生成模式**（由顶层 `mode` 参数调度）：

| 模式 | 触发条件 | 输入字段 |
|---|---|---|
| 文生视频（text-to-video） | 仅 `prompt` | `prompt` |
| 图生视频（image-to-video） | 顶层 `image` 字符串 | `prompt` + `image`（单图 URL） |
| 关键帧动画（keyframes） | `extra_body.mode='keyframes'` | `prompt` + `extra_body.image`（**URL 数组**） |

**完整参数表**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model` | string | 是 | `agnes-video-v2.0` |
| `prompt` | string | 是 | 视频内容描述 |
| `image` | string | 否 | 图生视频的输入图 URL |
| `mode` | string | 否 | `ti2vid`（文/图生视频）或 `keyframes`（关键帧） |
| `width` / `height` | integer | 否 | 默认 1152 × 768 |
| `num_frames` | integer | 否 | **≤441，须满足 8n+1，实际仅接受离散值** |
| `frame_rate` | number | 否 | 1–60，默认 24 |
| `num_inference_steps` | integer | 否 | 推理步数 |
| `seed` | integer | 否 | 复现用随机种子 |
| `negative_prompt` | string | 否 | 反向提示 |
| `extra_body.image` | array | 否 | 关键帧模式的多图 URL 数组 |
| `extra_body.mode` | string | 否 | `keyframes` |

**`num_frames` 硬约束（极易踩坑）**：
- 表层规则：`≤441` 且满足 `8n+1`。
- **实际（ComfyUI 客户端 `yay0128/Agnes` 印证）**：只接受离散集合 `{81, 121, 161, 241, 441}`，其它 8n+1 值（如 25/33）会被拒。
- MCP 工具应**对该离散集合做枚举校验**，而非仅校验算术规则。
- 根因：视频 VAE 的关键帧时间压缩（KTC）架构——latent 空间分为单锚帧（"+1"）和按因果组分组的时序分支（"8n"），是 VAE 架构不变量。

**时长控制**：`seconds = num_frames / frame_rate`

| 目标时长 | 推荐参数 |
|---|---|
| ~3 秒 | `num_frames: 81, frame_rate: 24` |
| ~5 秒 | `num_frames: 121, frame_rate: 24` |
| ~10 秒 | `num_frames: 241, frame_rate: 24` |
| ~18 秒 | `num_frames: 441, frame_rate: 24` |

**分辨率**：三档 `480p / 720p / 1080p`；宽高比 `16:9 / 9:16 / 1:1 / 4:3 / 3:4`。

**异步生命周期**（四态）：

```
queued → in_progress → completed
                    ↘ failed
```

- 创建响应同时返回 `task_id` 与 `video_id`（**官方推荐用 `video_id` 取结果**）。
- `progress` 为整数百分比；⚠️ 文档只在 0 和 100 处示例，**中间百分比值未经验证**——不要向 CC 承诺精细进度。
- 最终 `url` 字段（mp4 直链）**仅在 `status='completed'` 时出现**。

**创建响应示例**：
```json
{
  "id": "task_YOUR_TASK_ID",
  "task_id": "task_YOUR_TASK_ID",
  "video_id": "video_YOUR_VIDEO_ID",
  "object": "video",
  "model": "agnes-video-v2.0",
  "status": "queued",
  "progress": 0,
  "seconds": "10.0",
  "size": "1280x768"
}
```

**完成响应示例**（多了 `url`、`error`）：
```json
{
  "video_id": "video_YOUR_VIDEO_ID",
  "status": "completed",
  "progress": 100,
  "url": "https://platform-outputs.agnes-ai.space/videos/agnes-video-v2.0/video_xxxxxx.mp4",
  "error": null
}
```

**错误码**：`400` 参数错 / `401` 鉴权 / `404` 任务或视频不存在 / `500` 服务端 / `503` 繁忙稍后重试。

**定价**：视频 `$0/秒`（当前免费）。

### 2.4 模型名清单（当前活跃、非 deprecated）

| 模态 | 模型名 | 端点 |
|---|---|---|
| 文生图 / 图生图 | `agnes-image-2.0-flash`、`agnes-image-2.1-flash` | `/v1/images/generations` |
| 文生视频 / 图生视频 / 关键帧 | `agnes-video-v2.0` | `/v1/videos`（异步） |

> `agnes-image-2.5-preview`、`agnes-video-2.5-preview` 官网标 "coming soon"，本方案不纳入。

## 三、核心问题：为什么没有现成的通用 Agnes MCP？（技术壁垒论证）

### 3.1 先纠偏：不是"协议层不可能"，是"实践层壁垒"

对抗验证**否决**了以下强论断（均 0-3 或 1-2 被反驳）：

- ❌ "MCP 协议与长任务根本不兼容"
- ❌ "MCP 没有最终态的异步原语，所以做不了视频"
- ❌ "`tools/call` 本质同步，所以 OpenAI 系 MCP 做不了视频"
- ❌ "MCP TS SDK 没有进度通知机制"
- ❌ "视频输出无法以内联内容返回，必须用 resource_link"（1-2，存疑）

**可辩护的真实版本**：MCP 可以覆盖视频，但**没有任何薄的同步包装器能做到**——你需要一个专门的、异步感知的 server。论证"为什么 OpenAI 系 MCP 不行"时，围绕"薄同步透传不行，需专用异步 server"，**不要**围绕"协议禁止"。

### 3.2 三层真实壁垒

| 壁垒 | 说明 | 对策 |
|---|---|---|
| **① 客户端硬超时** | CC / Cursor / Postman 等 MCP 客户端有 ~5 分钟硬上限（部分文档甚至提及 7–10s 的隐式阈值，长连接会 424 Failed Dependency）。多分钟视频任务会在完成前断连。 | 双工具 submit/poll 默认非阻塞；阻塞模式配 `timeout` + `resetTimeoutOnProgress:true`，每收到进度通知重置截止时间 |
| **② Agnes 视频端点非标 + 异步** | `/v1/videos` 是 Agnes 私有端点，取结果推荐 `/agnesapi?video_id=` **不在 `/v1/` 下**。任何 OpenAI 兼容中间件（new-api、image-gen-mcp）都不会知道这个端点。 | MCP 内部实现专用 `AgnesClient`，封装 create + 两种 poll 端点 + 文件下载 |
| **③ 长任务需文件优先回退** | 即便客户端超时，任务在后端仍在跑、产物已落盘。 | `MEDIA_GEN_DIRS` 模式：工具超时后返回"最近 N 个已生成文件"，让 CC 能用 `get_video` 二次捞回 |

### 3.3 为什么 OpenAI 系"薄封装"在 Agnes 上两头不讨好

- **图像**：图生图路由分歧（Agnes `/generations + image[]` vs OpenAI `/images/edits + multipart`）→ 硬编码 OpenAI schema 的 MCP 的 `edit_image` 工具直接失效。
- **视频**：OpenAI 根本没有视频端点（且 OpenAI 自家 Sora/Videos API 据报 2026-09 关停）→ 所有"OpenAI 兼容"MCP 的工具集里压根没有视频工具的位置。
- **结论**：通用性无法靠"对接一个 OpenAI base_url"获得，必须**按 Agnes 的实际契约逐字段封装**。

### 3.4 为什么本方案不走 new-api 中转

（详见既有《new-api 生图 MCP 方案调研报告》，此处只给结论）

- new-api 视频接口是 `/v1/video/generations`，与 Agnes 的 `/v1/videos` **端点名不同**。
- Agnes 取结果走 `/agnesapi`，**不在 new-api 代理的 `/v1/*` 范围内**，透不过去。
- new-api **无原生 Agnes 渠道**（视频只有 Kling/即梦/Vidu/Gemini）。
- Agnes 本身免费 + 自带 key 管理，中转只增复杂度、零收益。
- → **全直连 Agnes**。

### 3.5 现有方案盘点

| 项目 | 覆盖 | 可用性 | 评价 |
|---|---|---|---|
| `lansespirit/image-gen-mcp` | 仅文生图 + 图像编辑（OpenAI/Imagen） | ✅ 活跃、可配 base_url | **无任何视频能力**，且图生图走 OpenAI `/images/edits`，与 Agnes 不兼容 |
| `zssty2010/agnes-mcp-server` | 图（t2i/i2i）+ 视频（t2v/i2v） | ⚠️ 0 star、9 天龄、单作者、license 存疑、**从未运行测试** | 工具抽象（`generate_video` 提交 / `get_video` 轮询 / 可选 `wait`）与本方案设计一致，**可作参考，不建议直接依赖** |
| `RamboRogers/fal-image-video-mcp` | 图 + 视频（fal 后端） | ✅ 较完整 | **参考架构来源**：TS/Node + `@modelcontextprotocol/sdk` + provider client + "精选工具 + `execute_custom_model` 逃逸 + `list_available_models`" |
| `strato-space/media-gen-mcp` | 视频（Sora/Veo） | ✅ | **异步范式的最佳参考**：`wait_for_completion` / `timeout_ms=900000` / `poll_interval_ms` + 文件优先回退 |
| `AceDataCloud/WanMCP` | 视频（Wan） | ✅ | 验证"生成与任务追踪分属两个工具族"的模式 |

## 四、MCP Server 设计

### 4.1 技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言/运行时 | **TypeScript + Node.js（≥18）** | MCP 官方 TS SDK 最成熟；参考实现（fal-image-video-mcp）同款；CC 原生支持 |
| MCP SDK | `@modelcontextprotocol/sdk` | 协议合规；支持 `progress` 通知、`resetTimeoutOnProgress` |
| HTTP | 原生 `fetch`（Node 18+ 内置）或 `openai` SDK（设 baseURL） | 图像可借 openai SDK；视频用原生 fetch（端点非标） |
| 传输 | stdio（CC 本地接入首选） | `claude mcp add` 标准方式 |

### 4.2 工具清单（4 个）

| 工具 | 模态 | 阻塞? | 说明 |
|---|---|---|---|
| `agnes_generate_image` | 文生图 / 图生图 | 同步 | 统一入口，按是否传 `image` 自动切换 t2i/i2i |
| `agnes_create_video` | 文生/图生/关键帧 | 默认非阻塞，可选 `wait=true` | 按 `mode`/`image`/`keyframes` 分支三种视频模式 |
| `agnes_get_video` | 视频取结果 | 同步单次轮询 | 用 `video_id`（优先）或 `task_id`（回退）查状态/下载 |
| `agnes_list_models` | 发现 | 同步 | 列出模型与各自能力 |

### 4.3 五个关键设计决策

**决策 1：视频用"双工具 + 可选阻塞"，默认非阻塞。**
- 默认 `wait=false`：`agnes_create_video` 立即返回 `{task_id, video_id, status}`，CC 自行再调 `agnes_get_video` 轮询。
- 可选 `wait=true`：内部轮询至完成/失败/超时，配合 progress 通知 + `resetTimeoutOnProgress`。
- 理由：规避客户端 ~5min 硬超时；非阻塞是参考实现（zssty2010、media-gen-mcp）的共识默认。
- ⚠️ 待验证：CC 客户端是否支持 `resetTimeoutOnProgress`、实际硬超时多少（见 §6.1）。若不支持，**强制非阻塞**为唯一稳态。

**决策 2：`num_frames` 离散枚举校验。**
- 工具 schema 用 `enum: [81, 121, 161, 241, 441]`，不开放任意 8n+1 值。
- 同时支持"按目标时长反推"：传 `duration_seconds`，工具自动选最近的合法离散值。

**决策 3：图生图与文生图共用一个工具、一个端点。**
- `agnes_generate_image` 不传 `image` = 文生图；传 `image[]` = 图生图，命中 Agnes 的 `/generations + image[]` 路径。
- **不走** OpenAI 的 `/images/edits`。

**决策 4：产物"文件优先"，三 URL 策略。**
- 图片/视频生成后**默认下载到本地**输出目录，返回 `{local_path, public_url, data_url?}`。
- base64/data-url **默认关闭、按需开启、有大小上限**——避免大 mp4 撑爆 CC 上下文窗口。
- CC 能 `Read` 本地图片（PNG/JPG）直接"看"；视频只能返回路径+URL，CC 用 Bash `open` 或告知用户路径（CC 无法"播放"视频）。

**决策 5：通用性 = 精选工具 + 逃逸口。**
- 主路径：4 个精选工具覆盖 90% 场景。
- 逃逸口：预留一个 `agnes_raw` 工具（接受 `endpoint` + `input_params`），应对 Agnes 未来新增端点/参数，无需改 MCP 代码。（参考 fal-image-video-mcp 的 `execute_custom_model` 模式；此为单源设计建议，非必须。）

### 4.4 工具 Schema（核心参数）

```typescript
// agnes_generate_image
{
  prompt: string                      // 必填
  model?: "agnes-image-2.0-flash" | "agnes-image-2.1-flash"  // 默认 2.1-flash
  size?: string                       // 如 "1024x1024"
  n?: number
  image?: string[]                    // 图生图：URL 或 Data URI 数组
  return_base64?: boolean
  response_format?: "url" | "b64_json"  // 映射到 extra_body.response_format
  out_dir?: string                    // 本地落盘目录
}

// agnes_create_video
{
  prompt: string                      // 必填
  mode?: "ti2vid" | "keyframes"       // 默认 ti2vid
  image?: string                      // 图生视频：单图 URL
  keyframes?: string[]                // 关键帧：多图 URL（→ extra_body.image）
  model?: "agnes-video-v2.0"
  width?: number                      // 默认 1152
  height?: number                     // 默认 768
  num_frames?: 81 | 121 | 161 | 241 | 441  // 默认 121（~5s）
  frame_rate?: number                 // 默认 24
  duration_seconds?: number           // 可选：自动反推 num_frames
  seed?: number
  negative_prompt?: string
  wait?: boolean                      // 默认 false
  timeout_ms?: number                 // 默认 900000（15min），wait=true 时生效
  poll_interval_ms?: number           // 默认 10000
  out_dir?: string
}
```

### 5.2 `agnesClient.ts`（核心 HTTP 客户端骨架）

```typescript
const BASE = process.env.AGNES_BASE_URL ?? "https://apihub.agnes-ai.com/v1";
const KEY = process.env.AGNES_API_KEY!;

async function agnesFetch(path: string, init: RequestInit = {}) {
  const res = await fetch(path.startsWith("http") ? path : `${BASE}${path}`, {
    ...init,
    headers: {
      "Authorization": `Bearer ${KEY}`,
      "Content-Type": "application/json",
      ...(init.headers ?? {}),
    },
  });
  if (!res.ok) throw new Error(`Agnes ${res.status}: ${await res.text()}`);
  return res.json();
}

// 文生图 / 图生图（同端点）
export async function generateImage(body: Record<string, unknown>) {
  return agnesFetch("/images/generations", {
    method: "POST",
    body: JSON.stringify(body),
  });
}

// 视频创建：三种模式在此分派
export async function createVideo(params: {
  prompt: string;
  mode?: "ti2vid" | "keyframes";
  image?: string;            // 图生视频
  keyframes?: string[];      // 关键帧
  model?: string;
  width?: number; height?: number;
  num_frames?: number; frame_rate?: number;
  seed?: number; negative_prompt?: string;
}) {
  const body: Record<string, unknown> = {
    model: params.model ?? "agnes-video-v2.0",
    prompt: params.prompt,
    width: params.width ?? 1152,
    height: params.height ?? 768,
    num_frames: params.num_frames ?? 121,
    frame_rate: params.frame_rate ?? 24,
  };
  if (params.image) body.image = params.image;                 // 图生视频
```

### 5.3 `poll.ts`（轮询状态机 + progress 通知 + 文件回退）

```typescript
import { getVideo } from "./agnesClient";

export async function waitVideo(opts: {
  video_id?: string; task_id?: string;
  timeout_ms?: number; poll_interval_ms?: number;
  onProgress?: (pct: number) => void;     // → 上层发 notifications/progress
}) {
  const timeout = opts.timeout_ms ?? 900_000;
  const interval = opts.poll_interval_ms ?? 10_000;
  const deadline = Date.now() + timeout;

  while (Date.now() < deadline) {
    const r: any = await getVideo(opts);
    if (r.status === "completed") return r;          // 含 url
    if (r.status === "failed") throw new Error(`video failed: ${r.error}`);
    opts.onProgress?.(typeof r.progress === "number" ? r.progress : 0);
    await new Promise((x) => setTimeout(x, interval));
  }
  // 超时但不报错——交给上层走"文件优先回退"
  return { status: "timeout", video_id: opts.video_id, task_id: opts.task_id };
}
```

### 5.4 `index.ts`（MCP server 入口骨架）

```typescript
#!/usr/bin/env node
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema, ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";
import { generateImage, createVideo, getVideo } from "./agnesClient";
import { waitVideo } from "./poll";
import { downloadAsset } from "./download";

const server = new Server(
  { name: "media-gen-mcp", version: "0.1.0" },
  { capabilities: { tools: {} } }
);

server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    { name: "agnes_generate_image", /* schema 见 §4.4 */ },
    { name: "agnes_create_video",   /* schema 见 §4.4 */ },
    { name: "agnes_get_video",      /* schema 见 §4.4 */ },
    { name: "agnes_list_models",    /* schema 见 §4.4 */ },
  ],
}));

server.setRequestHandler(CallToolRequestSchema, async (req) => {
  const { name, arguments: args } = req.params;
  try {
    switch (name) {
      case "agnes_generate_image": {
        const r = await generateImage(args as any);
        const paths = await Promise.all(
          (r.data ?? []).map((d: any) => downloadAsset(d.url, "img", args?.out_dir))
        );
        return { content: [{ type: "text", text: JSON.stringify({ paths, raw: r.data }) }] };
      }
      case "agnes_create_video": {
        const a = args as any;
        const created = await createVideo(a);
        if (!a.wait) {
          return { content: [{ type: "text", text: JSON.stringify({
            task_id: created.task_id, video_id: created.video_id, status: created.status,
            hint: "调用 agnes_get_video 轮询",
          }) }] };
        }
        // 阻塞模式：发 progress 通知以触发 resetTimeoutOnProgress
        const done = await waitVideo({
          video_id: created.video_id, task_id: created.task_id,
          timeout_ms: a.timeout_ms, poll_interval_ms: a.poll_interval_ms,
          onProgress: (pct) => server.notification({ method: "notifications/progress",
            params: { progress: pct, total: 100 } }),
        });
        const local = done.url ? await downloadAsset(done.url, "vid", a.out_dir) : null;
        return { content: [{ type: "text", text: JSON.stringify({ ...done, local_path: local }) }] };
      }
      case "agnes_get_video": {
        const r: any = await getVideo(args as any);
        let local = null;
        if (r.status === "completed" && r.url && args?.download !== false)
          local = await downloadAsset(r.url, "vid", args?.out_dir);
        return { content: [{ type: "text", text: JSON.stringify({ ...r, local_path: local }) }] };
      }
      case "agnes_list_models":
        return { content: [{ type: "text", text: JSON.stringify({
          image: ["agnes-image-2.0-flash", "agnes-image-2.1-flash"],
          video: ["agnes-video-v2.0"],
        }) }] };
      default:
        return { content: [{ type: "text", text: `unknown tool: ${name}` }], isError: true };
    }
  } catch (e: any) {
    return { content: [{ type: "text", text: `error: ${e.message}` }], isError: true };
  }
});

await server.connect(new StdioServerTransport());
```

### 6.5 实测验真结果（2026-07-11，curl 全链路）

> 用真实 API key 对全部 6 个能力点端到端 curl 验证，**全部通过**，并发现多项文档未载的实测细节。本节是 §6.1 的实证补全。

**6 个能力点实测全过**：

| 能力 | 端点 / 关键参数 | 实测结果 |
|---|---|---|
| 文生图 | `POST /v1/images/generations` `{model, prompt}` | ✅ 200，16.4s，返回 `url`（非 b64） |
| 图生图 | 同端点 + `image[]` | ✅ 200，16.4s——**承重点坐实：走 `/generations`，非 OpenAI 的 `/images/edits`** |
| 文生视频 | `POST /v1/videos` `{prompt}` | ✅ queued→in_progress(30%)→completed，mp4 1.43MB |
| 图生视频 | 同端点 + 顶层 `image`（string） | ✅ 200，queued，参数格式确认 |
| 关键帧 | 同端点 + `extra_body.image[]` + `extra_body.mode="keyframes"` | ✅ completed，mp4 1.69MB |
| 轮询 / 下载 | `GET /agnesapi?video_id=` → fetch mp4 | ✅ status/progress/url 齐全；**mp4 直链免鉴权下载** |

**关键实测发现（补充 / 修正前文）**：

1. **视频限速 = `1 req/min`（硬约束，HTTP 429）**——MCP 必须实现提交令牌桶/队列。实测两次相同请求返回**相同 request_id**，提示限速可能对幂等请求缓存响应。
2. **`progress` 有中间值（实测 30）**——推翻前文"中间值未验证"顾虑，MCP 可向 CC 推送精细进度。
3. **`size_mapping` 自动归一**——请求 `1152x768` 被映射到最近 preset `720p/4:3 (1088x832)`。**MCP 应直接传 `resolution`（480p/720p/1080p）+ `ratio`，而非裸 width/height**，避免二次映射。
4. **产物 URL 免鉴权**——`platform-outputs.agnes-ai.space` 的 mp4/png 可直接 GET，MCP 下载无需带 key。
5. **Agnes 自动注入默认 `negative_prompt`**（一长串游戏/水印/文字类反向词）；用户传的会叠加而非覆盖。
6. **轮询响应字段远比文档丰富**——含 `internal_progress` / `internal_status` / `perf_params`（含 `num_inference_steps` 默认 8、`seed`）/ `request_params` / `size_mapping` / `prompt_id` / `expires_at`，MCP 可选择性透传。
7. **耗时基线**：图像 ~16s；视频提交秒回，5s 视频生成约 1.5–2 min（81 帧关键帧约 75s）。
8. **时长公式精确**：`seconds = num_frames / frame_rate`（81/24=3.4s、121/24=5.0s，实测吻合）。

> 这些发现已直接反哺 §4 的工具设计：`num_frames` 枚举校验、`resolution/ratio` 入参、progress 通知、令牌桶限速、产物免鉴权下载。

### 6.6 视频异步生成 + 完成通知（最终方案，2026-07-12 实测）

**问题**：视频生成普遍 >60s（Agnes 81帧≈75s 起），`wait=true` 同步阻塞会撞 CC 硬超时；而 MCP stdio 是 CC 驱动（请求-响应），**server 无法主动推"完成"通知** —— 完成提醒必须在 CC 层解决。

**机制选型（均已实测）**：

| 候选 | 结论 |
|---|---|
| `create_video wait=true` 同步 | 阻塞 CC turn，长任务撞 CC 硬超时 | ✗ |
| `CronCreate`（session-only） | 依赖 CC 交互式 REPL 的 idle 调度；agent 模式 + 用户消息打断下**不触发** | ✗（实测失败） |
| 用户主动 `get_video` | 无自动通知，违背需求 | ✗ |
| **`Bash run_in_background`** | 脚本退出 harness 经 task-notification 主动唤醒 agent，不依赖 idle | ✅ **最佳** |

**三层方案**：
1. **server 智能异步**（§4 已实现）：`create_video` 省略 `wait` → `estimateGenerationSeconds` 估算 >60s → 返回 `{async:true, estimated_seconds, estimated_human, hint}`。
2. **CC 编排约定**：收到 `async` → 启 `run_in_background` 轮询脚本（轮询 `get_video` 到 completed + 下载 mp4）。
3. **自动唤醒**：脚本退出 → harness 唤醒 CC → CC 通知用户。

**实测闭环（2026-07-12）**：81帧视频 12:44:05 提交 → 后台脚本轮询（in_progress 30% → 完成时 100%）→ 12:45:27 completed（耗时 **82s**，633KB mp4）→ 脚本退出 → harness **自动唤醒 agent** → 通知用户。**用户全程无操作**。预估 76s vs 实际 82s，误差 6s。

**限制（诚实）**：
- **会话内**：CC 会话结束后台脚本可能终止（满足"会话内提醒"需求；跨会话需 `CronCreate durable`，但其在 agent 模式触发不可靠，未推荐）。
- **轮询脚本实现**：本次演示用 curl 直调 Agnes API（绑定 provider）；单 provider 够用。**未来加多 provider 时**，应给 media-gen-mcp 加 `--poll <videoId>` CLI 子命令（走 provider 抽象、脚本简洁）—— 暂不加（YAGNI）。

Agnes API 表层 OpenAI 兼容、但靠**非标扩展**（图像 `image[]` 走 `/generations`、视频 `/v1/videos` + `/agnesapi` 异步）强制要求**专用封装**——这就是没有通用现成 MCP 的根因；壁垒在**实践层**（客户端 ~5min 超时 + 非标端点 + 需轮询/文件回退）而非协议禁止。方案：**TS/Node + `@modelcontextprotocol/sdk` 自建 4 工具 MCP，全直连 Agnes，视频默认 submit/poll 非阻塞、可选 `wait`+progress 通知**。动工前先用 30 分钟 curl 跑通图像/视频 API，填掉 4 个运行时待确认点，即可消除全部模糊。
