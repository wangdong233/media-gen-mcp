#### F7 [low · 正面] · assertOutputClean severity 路由清晰(report 与 handler 反应解耦)

- **内容**:`src/checks/output-checker.ts:1218-1238` `assertOutputClean`:
  ```ts
  const fatals = report.issues.filter((i) => i.severity === "fatal");
  if (fatals.length > 0) return { fatal: ..., quality: report };
  const hardFails = report.issues.filter((i) => i.severity === "error");
  if (hardFails.length > 0 && report.profile === "strict") return { fatal: ..., quality: report };
  const warnings = report.issues
    .filter((i) => i.severity === "warning" || (i.severity === "error" && report.profile === "standard"))
    .map((i) => `[${i.code}] ${i.message}`);
  return { warnings, quality: report };
  ```
  severity 路由三档清晰:fatal(任何 profile throw)/ error + strict(throw)/ error + standard(降 warning)/ warning(永不 throw)。
- **关键设计**:`report.summary` 按原始 severity 计数(`fatals / errors / warnings`),**profile 不影响 summary**,只影响 `status` / `ok` 与 handler 反应。这一解耦让:
  - standard 档调用方看到真实 error 计数(透明),同时不被阻断(handler 把 error 降 warning 合并到响应 warnings[]);
  - strict 档调用方看到 error 计数 + 阻断(handler 把 error 转 fatal throw);
  - report 是"原始检查结果",handler 决定"如何反应",**职责分离**。
