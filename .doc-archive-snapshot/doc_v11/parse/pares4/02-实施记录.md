### 2.2 assertOutputClean severity 路由(对齐 pares4 §4.2.3)

```ts
export async function assertOutputClean(filePath: string, opts: AssertOptions): Promise<AssertResult> {
  const report = await checkOutput(filePath, opts);
  const fatals = report.issues.filter((i) => i.severity === "fatal");
  if (fatals.length > 0)
    return { fatal: new Error(fatals.map((i) => `[${i.code}] ${i.message}`).join("; ")), quality: report };
  const hardFails = report.issues.filter((i) => i.severity === "error");
  if (hardFails.length > 0 && report.profile === "strict")
    return { fatal: new Error(hardFails.map((i) => `[${i.code}] ${i.message}`).join("; ")), quality: report };
  const warnings = report.issues
    .filter((i) => i.severity === "warning" || (i.severity === "error" && report.profile === "standard"))
    .map((i) => `[${i.code}] ${i.message}`);
  return { warnings, quality: report };
}
```

### 2.3 SVG NaN/undefined 字面量扫描(inspectSvgDom 递归)

```ts
function inspectSvgDom(node: any, acc: { drawNodes: number; nanAttrs: string[] }): void {
  const tag = (node.tagName ?? "").toLowerCase();
  if (DRAW_NODE_TAGS.has(tag)) acc.drawNodes++;
  const attrs = node.attributes;
  if (attrs && typeof attrs.length === "number") {
    for (let i = 0; i < attrs.length; i++) {
      const a = attrs.item(i);
      const v = String(a.value ?? "");
      // 严格匹配裸 NaN/Infinity/-Infinity/undefined 字面量(避免误伤字符串字面值)
      if (/(^|[("\s=])(NaN|Infinity|-Infinity|undefined)(?=[)"\s]|$)/i.test(v)) {
        acc.nanAttrs.push(`${tag}@${a.name}=${v}`);
      }
    }
  }
  // 子节点递归
}
```

### 2.4 ffmpeg 容器探活(spawnSync + 5s timeout)

```ts
function probeContainer(file: string): FfprobeResult {
  if (!ffmpegPath) return { ok: false, decodable: false, /* ...跳过 */ };
  const r = spawnSync(ffmpegPath, ["-i", file, "-f", "null", "-"], {
    timeout: 5000, encoding: "utf8", stdio: ["ignore", "pipe", "pipe"],
  });
  const stderr = r.stderr ?? "";
  const hasVideo = /Video:\s/i.test(stderr);
  const hasDuration = /Duration:\s*\d+:\d+:\d/i.test(stderr);
  const invalid = /Invalid data found|No such file|moov atom not found/i.test(stderr);
  // timedOut 不在 @types/node SpawnSyncReturns 上,用 signal/error 启发式
  const timedOut = r.signal === "SIGTERM" || Boolean((r as any).timedOut) || /TIMEDOUT/i.test(r.error?.message ?? "");
  if (timedOut) return { /* mp4/timeout warning */ };
  if (invalid) return { /* container-decodable fatal */ };
  return { ok: true, decodable: hasVideo || hasDuration, hasVideoTrack: hasVideo, /* durationMs parsed */ };
}
```

## 4. 遇到的问题与解决

### P1:pngjs 无 bundled TypeScript types

**现象**:`typeof import("pngjs").PNG` 在 src/ 严模式下报 TS7016(Could not find a declaration file)。

**根因**:pngjs 5.x 不带 types(P0-3 的 test/golden/helpers.ts 能 import 是因为 tsconfig.test.json 关了 `noImplicitAny` + `strict: false`)。

**解决**:用 `createRequire` 兜底加载,inline 自定义类型 alias:
```ts
let PNG: { sync: { read: (buf: Buffer) => { width: number; height: number; data: Uint8Array } } } | null = null;
try { PNG = require("pngjs").PNG; } catch { PNG = null; }
```
不引入 `@types/pngjs`(避免新 devDep;inline 类型只声明实际用到的 surface,符合 YAGNI)。

### P2:`spawnSync` 返回类型无 `timedOut` 字段

**现象**:`r.timedOut` 报 TS2339。

**根因**:`@types/node` 的 `SpawnSyncReturns<T>` 接口只暴露 `status / signal / error`,实现层有 `timedOut` 但类型未声明。

**解决**:用 `signal === "SIGTERM"` + `(r as any).timedOut` + `error.message` 含 `TIMEDOUT` 三重启发式(timeout 时 Node 同时发 SIGTERM 和设置 error):
```ts
const timedOut = r.signal === "SIGTERM" || Boolean((r as any).timedOut) || /TIMEDOUT/i.test(r.error?.message ?? "");
```

### P3:测试断言把 standard 档 error 误认为会落到 summary.warnings

**现象**:首轮 `nan.svg + standard` 测试失败,实际 `summary.warnings=0` 而 `summary.errors=1`。

**根因**:OutputReport 的 `summary` 按原始 severity 计数,**profile 不影响 summary**,只影响 `status`/`ok`。error 降级 warning 的逻辑在 `assertOutputClean`(handler 钩子入口),不在 `checkOutput`(report 装配)。

**修正**:测试断言改为 `summary.errors=1 + ok=true`(standard 档 error 不 fail,但仍按 error 计数)。这一区分是有意为之:report 是"原始检查结果",handler 决定"如何反应"。

### P4:`html-as.png` 不带 `--format=png` 时落 "unknown" kind,只 warning 不 fatal

**现象**:`detectKind` 看 magic bytes,HTML 不匹配任何签名 → "unknown" → 只走 `file/unknown-kind` warning,不触发 `png/magic-bytes` fatal。

**根因**:CLI 不传 `--format=png` 时,checker 无法知道 caller 期望 PNG,只能按 bytes 启发式。

**裁决**:这是正确行为(无 caller 提示时不能用扩展名强假设)。**handler 钩子一定会传 `format`**(每个 case 都有),所以运行时不会出现这个问题。CLI 反例测试改用 `--format=png` 显式触发,语义更清晰。

### P5:valid.gif 体积 912B < GIF 最小阈值 1024B → min-size warning

**现象**:CLI 显示 `valid.gif [strict] PASS warnings=1 (min-size=X)`。

**裁决**:不改阈值(pares4 §6.1 明确 GIF/MP4/WebM > 1KB);改用 ffmpeg 生成更大尺寸 GIF 增加成本无意义,接受 warning(non-fatal,strict 也只 PASS)。**这是该阈值的一个已知小尺寸盲区**,正式生产中 GIF/MP4/WebM 几乎不可能 < 1KB,warning 设计意图就是"占位/损坏"提示。

### P6:npm test 第二段统计 "tests 173" 与新增 35 个 check-render-output 测试的对应关系

**现象**:`node --test` 输出的 `tests N` 是顶层 test 数,subtest 在子 describe 内部不计顶层计数。

**裁决**:无需修复,只要 `fail 0` 即可。每个测试都用 `✔` 显式标出,P0-4 测试全部显示 PASS。
