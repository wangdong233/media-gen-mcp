## 1. 目标(不变)

在 media-gen-mcp 的产物侧建立**第一道字节级守门员**:

- 任何 `local_path` 指向的产物文件,落盘后**立刻被校验**:能不能读 / magic bytes 对不对 / 能不能解码 / SVG 有没有 NaN / 容器 ffmpeg 认不认。
- 校验失败按三档处置(fatal / hard-fail / warning),fatal Day 1 即 `isError:true`,hard-fail 标准档 warning-only 灰度两周后评估升档,warning 永不阻断。
- 提供独立 CLI `scripts/check-render-output.mjs`,任何产物文件可单跑校验,输出结构化 JSON(`{ok, file, checks[], issues[]}`)。
- 不破坏现有 19 工具签名、不破坏 npm run build、不破坏 npm test 三段式、不破坏 G1/G2/G3 schema 断言。

**与 P0-3 的边界**(必须明确,防重叠误判):

| 维度 | P0-3(golden byte-compare) | P0-4(产物合法性) |
|---|---|---|
| 守什么 | 同输入同输出 byte-identical(**确定性回归**) | 产物本身物理合法(**任何一次调用**) |
| 何时跑 | `npm test`(CI / 本地测试期) | **handler 运行时** + 独立 CLI + `npm test` 末段冒烟 |

### 2.2 为什么 output-checker.ts 放 `src/checks/` 不放 `test/checks/`

**实地核实**:`tsconfig.test.json` 当前是
```jsonc
{ "extends": "./tsconfig.json",
  "compilerOptions": { "rootDir": "test", "outDir": "dist-test", ... },
  "include": ["test/**/*.ts"] }
```
`rootDir=test` + `include=test/**/*.ts` ⇒ 只编 `test/` 下的 `.ts`,**完全不编 src/**(已用 `find dist-test -type f` 验证:dist-test/ 下只有 golden.test.js / golden/golden.config.js / determinism.test.js / golden-helpers.unit.test.js,无任何 src/ 镜像)。

PRD §4.7 提议把 tsconfig.test.json 改成 `include: ["src/**/*", "test/**/*"]` + `rootDir: "./"` —— **会破坏 P0-3**:
- `render-golden.mjs` 的 `import(ROOT/dist-test/golden/golden.config.js)` 路径会变(因 rootDir 不再是 test,golden.config.js 不再出现在 dist-test/golden/ 而在 dist-test/test/golden/)。
- `golden.test.ts` 的 `import "./golden/golden.config.js"` 相对路径会断。

**正确方案**:**output-checker.ts 放 src/checks/**,由**主 tsconfig.json**(`include: ["src/**/*"]`)编到 `dist/checks/output-checker.js`。三方 import 都从 `dist/checks/output-checker.js` 进:
- handler:`import { assertOutputClean } from "./checks/output-checker.js"`(运行时,已被 build 编译)
- CLI:`import { checkOutput } from "../dist/checks/output-checker.js"`
- 测试:`import { checkOutput, assertOutputClean } from "../dist/checks/output-checker.js"`

**tsconfig.test.json 不动**(P0-4 不触碰)。`tsconfig.json` 也不动(它的 `include: ["src/**/*"]` 已天然覆盖新增的 `src/checks/`)。

## 4. 关键接口签名(output-checker.ts)

完整签名对齐 PRD §4.2.1-4.2.3,**三档 severity 与 §9 未决点 16 的修正一致**(fatal/error/warning):

```ts
// src/checks/output-checker.ts
export type Profile = "standard" | "strict";
export type Severity = "fatal" | "error" | "warning";
//  fatal  = 任何 profile 都 throw → isError:true(file/readable, magic-bytes,
//           svg/parseable, svg/has-root, container-decodable)
//  error  = hard-fail:strict profile throw,standard 降级 warning
//           (decodable, dimensions-sane, svg/viewbox-nonzero, svg/no-nan-attrs, svg/has-content)
//  warning= 永不 throw(non-blank, tracks-present, file/min-size per-kind)

export interface CheckIssue {
  severity: Severity;
  code: string;            // "png/magic-bytes" / "svg/has-content" / "qrcode/decode-roundtrip" 等
  message: string;         // LLM 友好:定位 + 阈值 + 修复动词
  details?: Record<string, unknown>;
}

export interface CheckResult {
  name: string;            // "magic_bytes" / "decodable" / "decode_roundtrip" 等
  ok: boolean;
  details: string[];       // 人类可读,带 [code] 前缀
}

export interface OutputReport {
  schemaVersion: 1;
  profile: Profile;
  status: "pass" | "fail"; // fail 当且仅当 fatals>0(任何 profile) 或 errors>0(strict)
  ok: boolean;             // === (status === "pass")
  file: string;            // 绝对路径
  kind: "png" | "jpeg" | "webp" | "svg" | "mp4" | "gif" | "webm" | "unknown";
  checks: CheckResult[];
  summary: { fatals: number; errors: number; warnings: number };
  metrics: {
    bytes?: number;
    width?: number; height?: number;
    svgDrawNodes?: number;
    mp4DurationMs?: number; mp4HasVideoTrack?: boolean;
  };
  issues: CheckIssue[];
}

export interface AssertOptions {
  tool: string;            // "generate_qrcode" / "render_video" 等,路由工具专属检查
  format?: string;
  profile?: Profile;
  originalInput?: unknown; // QR decode roundtrip 比对值
}

// 顶层入口:跑完所有检查,返结构化 report(不抛)
export async function checkOutput(
  filePath: string,
  opts: { tool?: string; format?: string; profile?: Profile; originalInput?: unknown } = {},
): Promise<OutputReport>;

// handler 钩子入口:基于 report 决定 throw 还是返 warnings
export async function assertOutputClean(
  filePath: string,
  opts: AssertOptions,
): Promise<{ warnings: string[]; quality: OutputReport } | { fatal: Error; quality: OutputReport }>;
```

**assertOutputClean 实现骨架**(对齐 PRD §4.2.3 已修正版本):
```ts
export async function assertOutputClean(filePath, opts) {
  const report = await checkOutput(filePath, opts);
  const fatals = report.issues.filter(i => i.severity === "fatal");
  if (fatals.length > 0)
    return { fatal: new Error(fatals.map(i => `[${i.code}] ${i.message}`).join("; ")), quality: report };
  const hardFails = report.issues.filter(i => i.severity === "error");
  if (hardFails.length > 0 && report.profile === "strict")
    return { fatal: new Error(hardFails.map(i => `[${i.code}] ${i.message}`).join("; ")), quality: report };
  const warnings = report.issues
    .filter(i => i.severity === "warning" || (i.severity === "error" && report.profile === "standard"))
    .map(i => `[${i.code}] ${i.message}`);
  return { warnings, quality: report };
}
```

### 6.1 三档检查归档(对齐 §4.4 真相源)

**fatal**(任何 profile throw → isError:true):
- `file/readable` —— fs.readFile 成功且 size > 0
- `png|jpeg|webp/magic-bytes` —— 前 8 字节签名匹配
- `svg/parseable` —— @xmldom/xmldom DOMParser 不抛
- `svg/has-root` —— 根元素 tagName === "svg"
- `mp4|gif|webm/container-decodable` —— `ffmpeg -i <file> -f null -` 退出码 0(spawnSync + 5s timeout)

**error / hard-fail**(strict throw / standard warning):
- `png|jpeg|webp/decodable` —— pngjs(PNG)/ @napi-rs/canvas loadImage(JPEG/WebP,若装)解码成功
- `png|jpeg|webp/dimensions-sane` —— width/height finite 且 width*height ≤ 16_000_000
- `svg/viewbox-nonzero` —— viewBox 宽高 > 0(或 width/height > 0)
- `svg/no-nan-attrs` —— 全树 attrs 无 `NaN/Infinity/-Infinity/undefined` 字面量
- `svg/has-content` —— `<path>/<use>/<rect>/<circle>/<line>/<polygon>/<text>` 节点数 > 0

**warning**(永不 throw):
- `png/non-blank` —— alpha 通道不全 0 + RGB 方差 > 0
- `mp4/tracks-present` —— ffmpeg stderr 含 `Video:` 或 `Duration: 00:`
- `file/min-size`(per-kind)—— PNG/JPEG/WebP > 64B、SVG > 32B、MP4/GIF/WebM > 1KB(对齐 §9 未决点 15:不能用 universal 1024 fatal,会误杀小 QR/icon)

**工具专属**(附加,按 `tool` 字段触发):
- `qrcode/decode-roundtrip`(format=png)—— jsQR 解码 === originalInput.text(byte 级)
- `qrcode/svg-has-modules`(format=svg)—— `<path>` 数 > 0 且根 svg 含 viewBox
- `formula/has-glyphs` —— `<path>` 或 `<use>` > 0
- `render-svg/chrome-pixel-variance`(backend=chrome)—— pngjs 解码后 RGB 方差 > 阈值(防 Chrome 抓空白页)

### 6.2 测试 fixture 来源策略(对齐 §5.2)

**正例(零新增物料,直接复用 P0-3 已 commit 的 golden)**:
- PNG 正例:`test/golden/expected/qr/url.png`(P0-3 实跑生成,byte 稳定)
- SVG 正例(5 选 1 即可):`test/golden/expected/formula/basic.svg` / `qr/basic.svg` / `chart/bar-basic.svg` / `card/cjk-og.svg` / `render-svg/passthrough.svg`
- QR roundtrip 正例:同 `qr/url.png`,originalInput 从 `test/golden/fixtures/qr/url.json` 读
- **MP4 正例**:无现成 fixture,需在 step 9 用 `render_video` 跑一份 1s 的最小 mp4 commit 到 `test/fixtures/check-render-output/valid.mp4`(约 10-30KB,可控)

**反例(全部手造小文件,commit 到 `test/fixtures/check-render-output/`)**:
- `zero.png`(0 字节)→ 触发 `file/readable` fatal
- `html-as.png`(`<html>404 Not Found</html>` 存 .png)→ 触发 `png/magic-bytes` fatal
