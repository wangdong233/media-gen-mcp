## 1. 本阶段做了什么

### 1.1 解决的"运行时合法性无守护"问题(用户/生产视角)

P0-3 golden byte-compare 守「同输入同输出」的**测试期回归**(CI 与本地 `npm test` 期捕获 byte 漂移),但**运行时**产物合法性无任何守护:handler 落盘 PNG / JPEG / SVG / MP4 / GIF / WebP 后直接 `return ok(...)`,从不校验"产物能不能读 / 签名对不对 / 能解码 / 有内容 / 容器合法"。这意味着 provider 返 HTML 错误页存 `.png`、渲染器除零产 `width="NaN"` SVG、网络中断产 0 字节文件、Chrome 抓空白页产全透明 PNG —— 这类**物理损坏**产物会一路畅通送到调用方(CC/Cline/用户),直到用户肉眼看图才发现。

P0-4 在产物侧建立**第一道字节级守门员**(对照 Archify addCheck 范式 + media-gen-mcp 已有 check-schema.mjs 范式 reimplement,零第三方代码引用):

| 维度 | P0-3(测试期回归) | P0-4(运行时合法性) |
|---|---|---|
| 守什么 | 同输入同输出 byte-identical | 产物本身物理合法(任何一次调用) |
| 何时跑 | `npm test`(CI / 本地测试期) | **handler 运行时** + 独立 CLI + `npm test` 末段冒烟 |
| 用什么比 | test/golden/expected/ 下基线 byte | 无基线,自洽(可解码 / 有内容 / 签名对) |
| 覆盖工具 | 6 个本地确定性工具 | **11 个有 `local_path` 的工具** |
| 产物种类 | SVG byte + PNG byte + QR roundtrip | 7 类(png/jpeg/webp/svg/mp4/gif/webm) |
| 失败处置 | diff 报告 + 刷新命令提示 | 三档(fatal throw / hard-fail strict throw / warning) |

**互补关系**:P0-3 守"测试期回归",P0-4 守"运行时合法性",两者正交不重叠。P0-3 的 8 个 golden 产物直接被 P0-4 复用作合法正例 fixture(零新增正例物料);P0-3 helpers.ts 与 P0-4 output-checker.ts 都用 pngjs/jsQR —— **是把测试期已验证的解码能力推到运行时**,非重复实现。

### 1.3 三档 severity + 双 profile + 工具专属检查

**三档 severity**(对齐 PRD §4.2.3 + pares4 §6.1):

| 档 | 检查项 | 行为 |
|---|---|---|
| **fatal**(任何 profile throw → `isError:true`) | `file/readable` / `png\|jpeg\|webp/magic-bytes` / `svg/parseable` / `svg/has-root` / `mp4\|gif\|webm/container-decodable` | Day 1 即阻断,standard/strict 都 throw |
| **error / hard-fail**(strict throw / standard 降 warning) | `png\|jpeg\|webp/decodable` / `dimensions-sane` / `svg/viewbox-nonzero` / `svg/no-nan-attrs` / `svg/has-content` | 灰度两周后评估升档 |
| **warning**(永不 throw,只写入 `warnings[]`) | `png/non-blank` / `mp4/tracks-present` / `file/min-size`(per-kind) | 透明透传 |

**双 profile**:
- **standard**(生产默认):只 fatal throw;error 降 warning;warning 透传
- **strict**(`MEDIA_GEN_CHECK_PROFILE=strict`,CI / 严档调用):fatal + error 都 throw;warning 透传

**report.summary 与 handler 反应解耦**(03-代码审查 F7):`summary` 按原始 severity 计数(`fatals/errors/warnings`),profile 只影响 `status`/`ok` 与 handler 反应。standard 档调用方看到真实 error 计数同时不被阻断 —— 「原始检查结果」与「如何反应」分离。

**工具专属检查**:
- `generate_qrcode` PNG → jsQR decode roundtrip(byte 级等比 `originalInput.text`);SVG → `<path>` 数 > 0 且 viewBox 存在
- `generate_formula` → `<path>` 或 `<use>` 数 > 0(防 MathJax 字体未加载产空 SVG)
- `render_svg` chrome backend → RGB 方差 > 阈值(防 Chrome 抓空白页)

### 1.4 紧急回滚与灰度策略

- **紧急回滚**:`MEDIA_GEN_CHECK_DISABLE=1` 全跳过,handler 返 `{ disabled: true }`,<100ms 开销忽略但有总比没有好(灾难场景一键放行)。
- **灰度策略**(对齐 PRD §4.4 + pares4 §13):warning 触发率 < 1% 升 isError / 1-5% 维持 warning 加 caveats / > 5% 降级永久 warning;两周观察期由灰度评估者维护。

  const mergedWarnings = [...(rendered.warnings ?? []), ...checked.warnings];

  ...(checked.warnings.length ? { warnings: checked.warnings } : {})
