### 2.1 Round 1 修复的三条 HIGH(实施记录 §3.1 已透明登记)

R1 在实施阶段对 test 链做了 CI 兼容性自审,发现初版方案有**两个致命缺陷 + 一个连锁问题**,全部当场修复:

| # | 位置 | 历史 bug | R1 修复 | 验证 |
|---|---|---|---|---|
| **R1-H1** | `package.json` scripts.test 初版 `node --test "dist-test/**/*.test.js"` | **Node 20 无内部 glob 引擎**(glob 在 Node 21.7+ 引入、22 稳定、未回移 20.x)。双引号包裹的 `**` glob 在 Node 20.19.6 被当**字面路径**:`Could not find '.../dist-test/**/*.test.js'`,exit 1。由于 test 链 `&&` 串联,后续 check-error-text / check-schema 全部不跑 —— **立场红线 #5(G1/G2/G3)直接破**,CI matrix `[20,22]` 中 Node 20 那档 day-1 红屏 | 改为 `dist-test/*.test.js`(单星、去引号)。test 文件都在 `dist-test/` 顶层(非嵌套),单星 glob 在 sh/bash/zsh **三端都展开**,Node 20/24 双绿 | `package.json` 实测:`"test": "npm run build && npm run build:tests && node --test dist-test/*.test.js test/*.mjs && ..."`;本审查 `npm test` Node 24.12.0 ✅ 94/92/0;CI 矩阵 Node 20/22 由 `dist-test/*.test.js` 单星 glob 在两端都被 shell 展开为文件列表,Node 20 无需内部 glob 引擎 |
| **R1-H2** | 同上(test 链 glob 模式) | 「去引号 `dist-test/**/*.test.js` 让 shell 展开」也不够 —— `**` 在 `sh`/`bash`(npm 在 Linux CI 用的 shell)**不展开**(需 `globstar` 选项;只有 zsh 默认开启),会原样传给 Node,Node 20 仍失败 | 同 R1-H1 修复(单星 `*`,三端 shell 都展开,无 globstar 依赖) | 同上 |
| **R1-H3** | `package.json` scripts.test 初版无 `npm run build &&` 前缀 | npm test 跑 golden.test.ts / determinism.test.ts 时 import `../dist/*.js`,若开发者改了 src/ 后只跑 `npm test` 不先 `npm run build`,会测 **stale dist 快照**(用旧 dist 跑新测试 → 测试通过但代码已破)—— 隐蔽回归风险 | test 链前置 `npm run build &&`(让 npm test 自洽,不再依赖开发者记得先 build) | `package.json` 实测含 `npm run build &&` 前缀;`prepublishOnly` 链 `npm run build && chmod +x ... && npm test` 仍正确(嵌套 build 是幂等,tsc 二次 no-op) |

**R1 修复质量评估**:R1 三条 HIGH 的根因是同一个初版方案(`dist-test/**/*.test.js` 双星 + 双引号 + 无 build 前缀),实施者发现后**整体回退为单星 + 去引号 + 加 build 前缀**,一次性闭环三条。修复方案在 sh/bash/zsh 三端 + Node 20/22/24 三档全覆盖,且在 `02-实施记录.md §3.1` 以 `> ⚠️ 第 1 轮代码审查订正(2026-07-22)` 引用块**透明登记**(包含失败方案描述、根因、本机实证命令、最终采用方案),流程规范性高。

**R1 还触发了 user-journey timeout 调整**(连锁修复):test 链加 build 前缀后,CI 在慢 / 高负载 runner 上 D2 WASM 首次编译可能 >60s,callTool 内置 60s 超时会杀掉 happy/error 路径,导致 npm test 卡死(进而 prepublishOnly 链影响 npm publish)。修复:`test/user-journey.error-format.mjs` 的 `callTool` 默认 timeout 60s → 120s,本地快机仍 ~2s 返回不受影响。**此修改在 02-实施记录.md §1.2 改动面表漏列**(见 F1)。
