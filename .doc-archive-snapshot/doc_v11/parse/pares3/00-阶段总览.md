## 1. 本阶段做了什么

### 1.1 解决的"测试基建缺位"问题(开发者/CI 视角)

P0-2 在 `test/` 下写了 4 个 .mjs(78 case)但**故意不接入 `npm test`**(保 P0-3 立场);P0-3 是这条立场的"实现方"。实施前 `npm test` 只跑 `scripts/check-schema.mjs`(5 断言),无任何引擎输出 byte 守护;任何对 6 个本地确定性工具(QR/formula/chart/card/render_svg/diagram)的"无意识 byte 漂移"(如升级 vega-lite / MathJax / resvg / D2 WASM)都不会被发现,直到用户在生产里拿到不同的图。

P0-3 把 Archify 的 golden byte-compare 范式 reimplement 进 media-gen-mcp,从口号("同输入同输出可入 git")变成 CI 门:

| 维度 | P0-2 前 | P0-3 后 |
|---|---|---|
| `npm test` | 5 断言(check-schema) | 138 tests + 16 断言(五段式 build→build:tests→node:test→check-error-text→check-schema) |
| 引擎输出 byte 守护 | 无 | 8 active golden 用例 + 9 user journey 端到端 + 35 unit helpers 边界 |
| 刷新器 | 无 | `npm run render:golden` 一键刷新 `test/golden/expected/`,失败信息含刷新命令 |
| CI | 无 | `.github/workflows/ci.yml` push/PR Node 20+22 双矩阵 |
| 跨平台 byte | 无验证 | 本机 macOS arm64 byte-identical 已验证;Linux CI 首跑待 push |
