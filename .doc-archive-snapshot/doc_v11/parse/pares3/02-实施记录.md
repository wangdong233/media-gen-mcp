### 2.1 R-01:normalizeMathJaxIds(`test/golden/helpers.ts`)

```ts
/** R-01:抹 MathJax SVG 的 MJX-N- 自增计数器(lazy singleton 内部状态)。
 *  对非 MathJax SVG 是 no-op(无 MJX- 前缀时 replace 不命中),可安全在所有 svg-byte 路径调用。 */
export function normalizeMathJaxIds(svg: string): string {
  return svg.replace(/MJX-\d+-/g, "MJX-N-");
}

export function compareSvg(fresh: string, checked: string, opts?: { preNormalize?: (s: string) => string }) {
  // 若 case 显式提供 preNormalize(如 formula case)则尊重;否则用全局默认 normalizeMathJaxIds(no-op 安全)
  const norm = opts?.preNormalize ?? normalizeMathJaxIds;
  const a = normalizeNewlines(norm(fresh));
  const b = normalizeNewlines(norm(checked));
  if (a === b) return { ok: true };
  // ...
}
```

formula case 设 `preNormalize: normMathJax`(等价 `s.replace(/MJX-\d+-/g, "MJX-N-")`),其它 case 用全局默认。**不动 src/formula.ts 一行**(立场红线)。

## 3. 实施中遇到的问题 + 解决

### 3.1 问题 1:Node 24 不接受 `node --test dist-test/` 作为目录参数

**现象**:`node --test dist-test/` 在 Node 24.12.0 报 `Cannot find module '/.../dist-test'`,把它当文件路径处理。

**根因**:Node 20+ test runner 对 `--test <path>` 参数的处理在 Node 24 收紧 —— 路径必须能 resolve 为文件或匹配 glob,目录需显式 glob 模式。

**解决**:`package.json` 的 test 链改为 glob 模式:
```jsonc
"test": "... && node --test \"dist-test/**/*.test.js\" test/*.mjs && ..."
```
(`dist-test/**/*.test.js` 双引号包裹防 shell 展开;Node 内部 glob 引擎匹配。)

**对 PRD 的影响**:PRD §4.3 写 `node --test dist-test/`,在 Node 24 失效。本阶段实施时已修(本记录 §2.2)。后续 P0-4 实施者注意:Node 24+ 跑测试目录需用 glob 模式,不要直接传目录路径。

> **⚠️ 第 1 轮代码审查订正(2026-07-22)**:上面 §3.1 的「双引号包裹 `dist-test/**/*.test.js` + Node 内部 glob 引擎匹配」方案有**两个致命缺陷**,已被审查回退:
> 1. **Node 20 无内部 glob 引擎**(glob 在 Node 21.7+ 引入、22 稳定、未回移 20.x)。双引号包裹的 `**` glob 在 Node 20.19.6 被当**字面路径**:`Could not find '.../dist-test/**/*.test.js'`,exit 1。由于 test 链是 `&&` 串联,后续 check-error-text / check-schema 全部不跑 —— **立场红线 #5(G1/G2/G3)直接破**,CI matrix `[20,22]` 中 Node 20 那档 day-1 红屏。本机实证:`nvm use 20 && node --test "dist-test/**/*.test.js"` → 失败。
> 2. 审查建议的「去引号 `dist-test/**/*.test.js` 让 shell 展开」也不够 —— `**` 在 `sh`/`bash`(npm 在 Linux CI 用的 shell)**不展开**(需 `globstar`;zsh 才默认展开),会原样传给 Node,Node 20 仍失败。
>
> **最终采用的修复**:`dist-test/*.test.js`(单星、去引号)。因 test 文件都在 `dist-test/` 顶层(非嵌套),单星 glob 在 sh/bash/zsh **三端都展开**(实证),且 Node 20/24 双绿。test 链同时前置 `npm run build &&`(让 npm test 自洽、不再测 stale dist 快照 —— 同轮审查 high 问题)。

### 3.2 问题 2:`jsqr` 类型/运行时形态不一致

**现象**:`import jsQR from "jsqr"`(默认 import)build:tests 报 `TS2349: This expression is not callable. Type 'typeof import("...")' has no call signatures.`

**根因**:`node_modules/jsqr/package.json` 声明 `main: "./dist/jsQR.js"`(CJS,`module.exports = factory()`)但 `types: "./dist/index.d.ts"` 写的是 `declare function jsQR(...); export default jsQR;`(ES default)。TypeScript 按 d.ts 检查,期待 `m.default` 是函数;但运行时 `require("jsqr").default` 实际是 undefined,而 `require("jsqr")` 本身才是函数。

**实证**:`node -e "import('jsqr').then(m => console.log(typeof m.default, typeof m))"` → `function object`(即 `m.default` 存在且是函数 —— esModuleInterop 在 ESM import 时合成了 default)。

**解决**:`test/golden/helpers.ts` 改用 namespace import + `.default` 双兜底:
```ts
import * as jsQRns from "jsqr";
const jsQR: (...) => ... = (jsQRns as any).default ?? (jsQRns as any);
```
兼容两种打包形态(纯 CJS 直接是函数 / UMD 带 `default` 字段)。

### 3.3 问题 3:`dist/*.js` 无 .d.ts,TS strict 报 implicit any

**现象**:`test/golden/render.ts` 写 `import { renderQR } from "../../dist/qr.js"` 编译报 `TS7016: Could not find a declaration file for module '../../dist/qr.js'`。

**根因**:主 `tsconfig.json` 设 `declaration: false`,dist/ 只产 .js 不产 .d.ts;test 配置 extends 主配置,strict + noImplicitAny 都开。

**解决**:`tsconfig.test.json` 在 R-05 路径 A 基础上加 `noImplicitAny: false` + `strict: false`(放宽,因 helpers/render import 现有 dist/.js)。**主 tsconfig.json 不动**(立场红线:不破坏现有 npm run build)。

### 3.4 问题 4:`scripts/render-golden.mjs` 注释含 `**/*.ts` 触发 `*/` 早闭合

**现象**:`node scripts/render-golden.mjs` 报 `SyntaxError: Unexpected token '*'` 在第 15 行。

**根因**:JSDoc 注释里写 `(只含 test/**/*.ts)`,其 `*/` 字符序列被 JS 解析为块注释结束符 → 注释提前闭合 → 后续行被当代码解析。

**解决**:注释里的 `**/*.ts` 改写为文字描述 `test 目录下的 .ts 文件`(规避 `*/` 字符序列)。

**教训**:JSDoc 内禁止出现 `*/` 字面量;包括 glob 模式(`**/*.ts`)、数学表达式 `a*/b`、C 风格指针 `int *p` 等都需转义或改写。

### 3.5 问题 5:card fault injection 不灵敏(fixture 显式 accent 覆盖默认)

**现象**:阶段 F3 故障注入,改 `src/card.ts:547` 默认 accent `#6366f1` → `#ff0000`,`npm test` **未红**(card-cjk-svg 仍绿)。

**根因**:fixture `card/cjk-og.json` 显式设 `"accent": "#6366f1"`,handler 走 `req.accent && req.accent.trim() ? req.accent.trim() : DEFAULT` 分支取 fixture 值,默认值改变不影响渲染结果。

**解决**:故障注入改用 fixture 不覆盖的字段 —— `src/card.ts:614` 的 `titleSize`(og 模板默认 76 → 改 78)。titleSize 始终应用,改后 card-cjk-svg 即时红:`height="63"` vs `height="62"`。

**启示**:golden 故障注入要选**始终应用且 fixture 无法覆盖**的代码路径(默认值常量、模板字段计算),否则会出现「改了源码但测试不红」的盲区。

### 3.6 问题 6:determinism grep scope 包含 `src/diagram/` 子目录

**现象**:最初写 determinism grep 时只列了 `src/qr.ts src/formula.ts src/chart.ts src/card.ts src/render-svg.ts`,漏了 diagram。

**根因**:diagram 有 4 个文件(d2/graphviz/render/types),需要全扫。

**解决**:`grep -rnE` 命令加 `src/diagram/`(目录递归),覆盖 d2.ts(含 ICONIFY_API 字符串但非时间源)、graphviz.ts、render.ts、types.ts。0 命中,符合预期。
