### 2.2 关键测试亮点(填 helpers 边界空缺)

- **normalizeMathJaxIds 不误伤非 MJX 前缀**:`id="MJX-abc-" id="MJAX-1-" id="MJX--"` 经 normalize 后**原样返回**(正则 `MJX-\d+-` 只匹配纯数字),证明 R-01 的归一化是**安全的 no-op**(对非 MathJax SVG 不引入任何 byte 漂移)。
- **compareSvg preNormalize 覆盖语义**:显式 preNormalize 恒等 `(s)=>s` → 即使 fresh/checked 仅差 MJX ID 也 fail。这锁死了「显式 preNormalize 不再走默认 normalizeMathJaxIds」的契约,避免未来误改 compareSvg 内部默认链路时引入回归。
- **stripPngMetadata 真实 PNG 验证**:用真实 `expected/qr/url.png`(resvg 产出)strip 后遍历 chunks,type 必须在 KEEP 集(IHDR/PLTE/tRNS/IDAT/IEND)。这把 stripPngMetadata 从「合成 PNG」升级到「真实引擎 PNG」,守住了 open_point 3(resvg 元数据 chunk 风险)。
- **comparePng 元数据差异 strip 后 ok**:用合成 PNG 模拟 resvg/libpng 不同版本写不同 iTXt chunk 的场景,证明 stripPngMetadata 能正确抹掉元数据差异(开放问题 3 的设计意图落地)。
- **verifyQrPng 非 PNG 抛而不静默**:喂 `Buffer.from("not a png")`,verifyQrPng 应抛(不返回 ok=true)。这锁死「jsQR/PNG.sync.read 失败不应静默通过」的契约。

## 5. User Journey 层 —— 端到端 MCP 真实调用(本测试新增)

### 5.1 测试设计

**用户视角的契约**:
> 我作为 Claude / 开发者,通过 MCP 客户端调用 `generate_qrcode` / `generate_formula` / ...;期望收到一个 `local_path` 指向磁盘上的 SVG/PNG 文件;该文件必须 **byte-identical** 于 `test/golden/expected/<file>`(README 承诺的「同输入同输出可入 git」)。

**测试方法**:对每个工具:
1. spawn `node dist/index.js` 作为 MCP server(经 JSON-RPC over stdio)
2. 发 `initialize` → `notifications/initialized` → `tools/call {name, arguments}`
3. 从响应 `content[0].text`(JSON 格式)抽出 `local_path`
4. 读取 `local_path` 文件
5. 用与 golden.test.ts **完全相同** 的 `compareSvg / comparePng / verifyQrPng`(import from `dist-test/golden/helpers.js`)做 byte 比对

这条链路证明:**「用户调 tool → MCP handler 落盘 local_path → 文件 byte ≡ golden」**。任何破坏这条链路的改动(handler 参数透传错误、outDir 处理错误、writeLocalRender bug、渲染器升级 byte 漂移)都会被本测试捕获。
