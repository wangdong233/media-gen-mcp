### 2.3 buildInteractiveHtml 主链路(`src/interactive-html/index.ts` L82-117)

```ts
export async function buildInteractiveHtml(
  req: InteractiveDiagramRequest,
  engine?: DiagramEngine,
): Promise<InteractiveDiagramBuildResult> {
  if (!req.code || !req.code.trim()) {
    throw new Error("`code` is required and must be a non-empty string");
  }
  // 1. D2 渲染(传三杠杆)
  const d2Engine = engine ?? getDiagramEngine("d2");
  if (!d2Engine) throw new Error("D2 engine unavailable");
  if (!d2Engine.isAvailable()) throw new Error("D2 engine not available");
  const rendered = await d2Engine.render({
    code: req.code,
    engine: "d2",
    format: "svg",
    theme: req.theme,
    darkTheme: req.darkTheme,           // → darkThemeID(C1,d2.ts 合并)
    noXMLTag: true,                      // C2 硬编码(HTML 内联必去 <?xml?>)
    salt: D2_INTERACTIVE_SALT,           // C3 硬编码(固定 salt,零成本防御 + 防 ID 冲突)
  });
  const svg = rendered.svg;

  // 2. 套 HTML 模板
  const html = fillTemplate({
    svg,
    title: req.title ?? "Interactive Diagram",
  });

  // 3. 契约 asserts(S2/S4/S6/S9/S11;S3 由调用方 / golden 验证)
  assertSelfContained(html);
  assertNoXmlDecl(html);                // C2 防线
  if (req.darkTheme != null) assertDualPalette(html);
  assertMotionGovernor(html);
  assertSizeUnder(html, 256 * 1024);    // S6 默认 256KB

  return {
    html,
    bytes: Buffer.byteLength(html, "utf-8"),
    hasDarkLightDualPalette: req.darkTheme != null,
    svg,
  };
}
```

### 2.4 S4 双调色板断言(放宽,匹配 D2 实际产出格式)

```ts
export function assertDualPalette(html: string): void {
  // matches "@media ... prefers-color-scheme: dark" (D2 form: "@media screen and (prefers-color-scheme:dark)")
  if (!/@media[^{]*prefers-color-scheme\s*:\s*dark\b/.test(html)) {
    throw new Error(`S4 dual-palette contract violated: @media ... prefers-color-scheme:dark not found in HTML/SVG. D2 darkThemeID may not have injected the dark palette.`);
  }
}
```

### 2.5 fillTemplate 函数式 replace 防 $& 解释(markmap 范式)

```ts
export function fillTemplate(opts: { svg: string; title: string }): string {
  const titleEscaped = escapeHtml(opts.title);
  // 函数式 replace:返回值原样使用,$&/$'/$1 不解释(markmap 范式)。
  // /g 全局:模板内 __MGM_TITLE_SLOT__ 出现 2 处(<title> + <h1>),都要填同一 escapeHtml(title)。
  return HTML_TEMPLATE
    .replace(new RegExp(escapeRegex(TITLE_SENTINEL), "g"), () => titleEscaped)
    .replace(new RegExp(escapeRegex(SVG_SENTINEL)), () => opts.svg);
}
```

## 4. 遇到的问题与解决(7 项,均闭环)

### 4.1 D2 darkThemeID 实际注入格式与预期不符(C-Major · open_point #6 解决)

**现象**:首次 smoke test `assertDualPalette` 抛错 —— 我的严格正则 `/@media\s*\(\s*prefers-color-scheme\s*:\s*dark\s*\)/` 不匹配 D2 实际产出。

**排查**:dump D2 SVG style block 发现 D2 WASM v0.7.0-HEAD 实际产出格式是 `@media screen and (prefers-color-scheme:dark){...}` —— 有 `screen and ` 前缀 + `:`与 `dark` 间无空格。

**解决**:放宽 `assertDualPalette` 正则为 `/@media[^{]*prefers-color-scheme\s*:\s*dark\b/`,匹配多种 @media 形式(canonical + D2 实际)。同步更新契约测试 S4 正例正则。

**实证**:`@media[^{]*prefers-color-scheme\s*:\s*dark\b` 同时匹配 `@media (prefers-color-scheme: dark)` 与 `@media screen and (prefers-color-scheme:dark)`,前者为 canonical、后者为 D2 实际。

**结论**:D2 WASM 行为与 PRD §0 C1 杠杆描述一致(双调色板 + @media 注入);open_point #6 RESOLVED。

### 4.2 viewer-min.ts 注释含 `<?xml?>` 字面量,触发 S11 断言(C-Major)

**现象**:`buildInteractiveHtml` 抛 `S11 no-xml-decl contract violated`,但 D2Engine.render(noXMLTag:true)的 SVG 实测无 `<?xml`(dump 验证)。

**排查**:用 `_test_p05_xml2.mjs` 直接调 fillTemplate 拿 HTML,grep `<?xml` 找到 1 处命中,定位在 viewer-min.ts 的中文注释 `// export SVG(序列化 + Blob 下载,不加 <?xml?>)`。注释里的 `<?xml?>` 字面字符串被 S11 断言的 `/<\?xml/` 正则匹配。

**解决**:重写 viewer-min.ts 注释为英文 `// export SVG(serialize via XMLSerializer + Blob download; no XML declaration added)`,移除 `<?xml` 字面量。

**教训**:HTML 内任何位置(包括 inline JS 字符串/注释)的 `<?xml` 都会被断言抓 —— S11 是对**全 HTML 字节内容**的硬约束,不限位置。

### 4.3 工具定义插入时编辑器误删 `generate_qrcode` 块开头(C-Minor · 立即捕获)

**现象**:首次插 `generate_interactive_diagram` 工具定义块后,tsc 仍编译通过(因为 generate_qrcode 的 inputSchema 字段恰好独立成行),但 grep 显示 `name: "generate_qrcode"` 消失。

**排查**:`grep -n "name: \"generate_qrcode\"\|name: \"generate_interactive_diagram\"\|name: \"generate_diagram\""` 显示 generate_qrcode 行号缺失;Read 文件确认 line 327 直接是 `description:` 而非 `{ name: "generate_qrcode", description:`。

**根因**:Edit 工具 old_string 末尾含 `\n    {\n      name: "generate_qrcode",` 三行,但 new_string 末尾只回填到 `},`,把这三行删掉了。

**解决**:Edit 修复,把 `\n    {\n      name: "generate_qrcode",` 加回。

**教训**:Edit 的 old_string / new_string 必须严格对齐结尾(尤其 multi-line 上下文);改后 grep 验证工具名完整。

### 4.4 S4 反例测试假阳性(C-Minor)

**现象**:`S4 反例: 不传 darkTheme → 不含 prefers-color-scheme:dark` 失败 —— 不传 darkTheme 时 HTML 仍 match `/prefers-color-scheme\s*:\s*dark/`。

**排查**:viewer pre-paint resolver script 含字面字符串 `'(prefers-color-scheme: dark)'` 用于 `window.matchMedia('(prefers-color-scheme: dark)').matches` 探测系统主题。这是 viewer JS 的正常逻辑(决定 auto 解析为 light/dark),与 D2 SVG 的 @media 块无关。

**解决**:S4 反例测试改用与正例相同的 @media-anchored 正则 `/@media[^{]*prefers-color-scheme\s*:\s*dark\b/`(viewer JS 不含 `@media`,故不匹配)。

**结论**:断言正则要锚定**结构性信号**(`@media` 前缀),不能裸匹配字符串。

### 4.5 S3 几何 byte-identical 测试过严(C-Major)

**现象**:`S3: light/dark 几何 byte-identical` 失败 —— 即使 strip `<style>...</style>` 块,light 与 dark 的 SVG 仍不等。

**排查**:dump diff 发现 D2 darkThemeID 触发后,SVG 内 shape 元素的 `fill="#..."` / `stroke="#..."` **内联属性**被移除,改用纯 CSS class 着色(`class=" fill-B3"` 而非 `fill="#E3E9FD" class=" fill-B3"`)。这是 D2 的**预期行为** —— @media 切换需要 CSS 接管着色,不能 bake 单一内联色值。

**几何结构(路径 d / rect xy / text xy+content / viewBox)** 实测 byte-identical,只有颜色属性集差异。

**解决**:S3 测试的 extractGeometry helper 除 strip `<style>` 外,也 strip 内联 `fill="..."` / `stroke="..."` 属性 + 多空格归一化。剩余几何内容 byte-identical。

**结论**:S3 "切主题不改 SVG 几何" 的正确解读是**几何**(path d / 位置 / 文本)不变,而非完整 SVG byte-identical —— D2 darkThemeID 模式必然改变属性集(CSS-class-only 着色),否则 @media 切不动。

### 4.6 assertOutputClean 调用计数偏 1(C-Minor)

**现象**:`check-render-output.test.mjs` 报 `assertOutputClean 调用数=12,预期 11`。
