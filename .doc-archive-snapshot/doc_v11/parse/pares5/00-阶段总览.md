## 1. 本阶段做了什么

### 1.1 解决的"GitHub README 主题切换盲区"问题(用户/生产视角)

P0-1..P0-4 把工具描述路由、错误契约、golden byte-compare、运行时产物守门员四件套补齐后,media-gen-mcp 已有的 19 个工具仍存在一个**用户可观察的功能盲区**(PRD §1.1):架构图嵌进 GitHub README 后,**深色读者与浅色读者看到的是同一张 SVG** —— GitHub 不允许 `<script>`,所以即使工具能产 dark-theme SVG,也无法在 README 里按读者系统主题动态切换。

`generate_interactive_diagram` 是这个盲区的最小可用解(MVP):

| 维度 | `generate_diagram`(既有)| `generate_interactive_diagram`(P0-5A 新增) |
|---|---|---|
| 产物 | 矢量 SVG(单主题 baked-in)| **单文件 HTML**(双调色板 baked-in + @media 自动切换)|
| GitHub README 嵌入 | 单主题;深/浅读者看同色 | **深/浅读者各看各的色**(浏览器 CSS 引擎原生跟随,零 JS)|
| 交互 | 静态 | pan / zoom / theme toggle / motion toggle / export SVG |
| DSL | D2 + Graphviz | **D2(复用 `generate_diagram` DSL)** |
| 依赖 | 零新增(D2 WASM 已在)| **零新增**(D2 WASM / puppeteer-core / resvg 全复用)|
| 落地形态 | local SVG/PNG path | local HTML path(+ 可选 PNG preview) |

**不是替代**:`generate_diagram` 继续是静态 SVG/PNG 的首选;`generate_interactive_diagram` 专攻"嵌 README 自动跟随系统主题"这一档交互场景。description 双向 cross-ref 已在两工具之间建立(`generate_diagram` 末段 NEXT 指向 `generate_interactive_diagram`;反向亦然)。

**关键设计裁决**(pares5/01-功能分析 §0 + §3,见本文件 §5):

- **C1 darkThemeID 杠杆**:D2 WASM 接受 `darkThemeID` 参数,传后 SVG `<style>` 块自动注入 `@media screen and (prefers-color-scheme:dark){...}` + dark palette CSS class(`.fill-B\d+`),light/dark 几何 byte-identical(只颜色属性集差异 —— S3 几何断言 strip fill/stroke 后 byte-identical 实证)。
- **C2 noXMLTag 杠杆**:D2 默认 SVG 顶部带 `<?xml version="1.0"?>`,HTML 内联时与 `<!doctype html>` 冲突会触发浏览器怪异模式;`noXMLTag:true` 去 xml 声明。
- **C3 salt 杠杆**:D2 内部用 salt 生成 element ID,多图同盐不冲突;固定 salt(`media-gen-mcp-interactive`)让同输入产同 ID → 同输出 byte-identical。
- **三杠杆条件展开最小加性**:`{ ...compiled.renderOptions, ...(themeID != null && {themeID}), ...(darkThemeID != null && {darkThemeID}), ...(noXMLTag === true && {noXMLTag: true}), ...(salt && {salt}) }` —— `generate_diagram` 路径不传三字段 → 三展开项全 false → renderOpts 与改造前 byte-identical。
- **HTML 跳过 assertOutputClean**(pares5 §0.3 裁决 A):HTML 是 viewer 容器文档,非 raster/vector 渲染产物,P0-4 守门责任域(magic bytes / decodable / viewbox nonzero / no-NaN-attrs)不适用;5 个契约 assert 在 `buildInteractiveHtml` 内部做(assertSelfContained / assertNoXmlDecl / assertDualPalette / assertMotionGovernor / assertSizeUnder),handler 拿到的 result 已自带 bytes / hasDarkLightDualPalette。
- **markmap 函数式 `.replace(callback)` reimplement**(pares5 §3.4):HTML 模板用 sentinel `__MGM_TITLE_SLOT__` / `__MGM_SVG_SLOT__` 占位,fillTemplate 用函数式 replace 返回值原样使用,$&/$'/$1 不解释(markmap 范式)—— 防 SVG 内容里 `$&` 字符被字符串 replace 解释。**零 markmap 包 import,零 Archify 拆**。
