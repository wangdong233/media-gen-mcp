### 0.3 新发现:assertOutputClean(P0-4)不支持 HTML kind(C-Major,PRD 未覆盖)

PRD 完全没讨论 P0-4 产物守门人对接。实地核实 `src/checks/output-checker.ts`:

- `Kind` enum(L47):`"png" | "jpeg" | "webp" | "svg" | "mp4" | "gif" | "webm" | "unknown"` —— **不含 "html"**。
- `detectKind(buf, format)`(L200):format 提示 + magic bytes 启发式,HTML 无 magic bytes。
- L488 fatal: `"无法识别产物种类(magic bytes 均不匹配);format 提示=..."` → HTML 输入会触发 fatal throw。
- 所有 12 个 write 路径(`src/index.ts` L629/785/806/999/1019/1048/1069/1088/1121/1159/1186 等)都过 `assertOutputClean(fp, { tool, format })`。

**P0-5 必须三选一**:

| 选项 | 裁决 | 理由 |
|---|---|---|
| **A. 跳过 assertOutputClean**(推荐 ✅) | GO | HTML 是 viewer 容器文档,非 raster/vector 渲染产物。P0-4 的责任域是"产物是否是合法 image/video"(magic bytes / decodable / viewbox nonzero / no-NaN-attrs)。HTML 这些检查都不适用。**契约 asserts(S2 自包含 / S6 ≤256KB / S9 reduced-motion / S11 无 <?xml?>)在 `renderInteractiveHtml` 内部做**,handler 拿到的 result 已自带 bytes / hasDarkLightDualPalette 字段。handler 注释明示:"HTML 不走 assertOutputClean(P0-4 守 raster/vector 渲染产物;HTML 是 viewer 容器,契约 asserts 在 renderer 内)"。 |
| B. 扩 Kind 加 "html" + html 专属检查 | NO-GO | 扩展 P0-4 scope 违反本 P0 立场(P0-4 已闭环,不在 P0-5 范围)。且 HTML 检查项(S2/S6/S9/S11)与 P0-4 的 image/video 检查范式不兼容,硬塞会污染单一真相源。 |
| C. 让 detectKind 把 HTML 当 "unknown" | NO-GO | 会 fatal throw,工具直接报错失败。 |

**裁决:A**。handler 写法见 §4.2。

## 3. 详细架构(六层,沿用 PRD §3 + 本节修正)

### 3.1 输入契约:接受 DSL(不走 JSON-IR)

**采纳 PRD §3.1 立场决策**:接受 D2 DSL 文本,不引入 JSON-IR。理由:
- LLM 负担低(写 D2 DSL,engine 管布局)
- auto-layout 用 D2 dagre 自带
- 与 media-gen-mcp "DSL 直传快速出图" 哲学一致
- 校验复杂度低(D2 自己解析报错)
- 不推翻 engine 价值(调研文档 §3.3 红线)

**结论**:复用 `generate_diagram` 的 D2 后端(同 DSL 语法),额外传 `darkTheme` + 固定 `salt` + `noXMLTag`。

### 3.2 渲染层:复用 D2Engine,新增三个杠杆(最小加性方案)

**复用** `src/diagram/d2.ts` 的 `D2Engine`(已进程内、lazy singleton、串行队列、icon 解析全要)。

**实地核实修正(PRD §3.2 + open_point #13/#14 已解决,本节确认最小方案)**:

PRD §3.2 给出两个方案:
1. **最小加性改动(主推)**:`types.ts` `DiagramRequest` 加 3 可选字段 + `d2.ts` L137-140 renderOpts 合并三字段。
2. **替代方案(更干净)**:在 d2.ts 加 `export function renderD2Raw(code, opts)`,`D2Engine.render()` 与 `render-d2.ts` 都调它。

**P0-5A 裁决:采纳方案 1(最小加性)**。理由:
- 改动最小(3 个可选字段 + 1 处合并逻辑),易审查、易回滚。
- `generate_diagram` 调用路径(index.ts L977-984)不传三字段 → byte-identical(向后兼容立场守住)。
- 方案 2 需在 d2.ts 加 export + 改 D2Engine.render() 内部结构,侵入更大。
- 方案 1 的"类型污染 DiagramRequest"顾虑(noXMLTag/salt 是 interactive-html 专属):可接受——这三个字段都是**纯可选**,graphviz 引擎收到也忽略(types.ts 注释明示),不破坏现有 type 合约。

**实现(在 d2.ts L137-140 改造)**:

```ts

```

### 3.3 主题层:CSS 变量 + `html[data-theme]` 属性 flip + D2 双调色板

- **D2 自带双调色板**(C1 杠杆):D2 用 `darkThemeID` 自动在 SVG 注入 `@media (prefers-color-scheme: dark) { .d2-xxx .fill-N1 { fill: <darkColor> } }`。GitHub README 嵌入时浏览器自动跟随系统主题,无需 JS。**Step 1.2.5 必须实测验证**(PRD open_point #6):grep 产出 SVG 含 `@media (prefers-color-scheme: dark)`。
- **viewer 外观主题**(toolbar/背景):~45 个 CSS 变量 + `html[data-theme="auto|light|dark"]` 属性 flip + pre-paint resolver(防 FOUC)。
- **三层主题来源优先级**:`URLSearchParams(?theme=)` > `localStorage` > `prefers-color-scheme` > 默认 `auto`。

**不变量**:viewer 主题切换**绝不重渲染 SVG、绝不重算几何**(S3 的实现基础)。

**降级预案(PRD open_point #6)**:若 Step 1.2.5 实测 D2 darkThemeID 不注入 @media(D2 WASM 与 CLI 行为差异),降级为 P0-5 自研 CSS 变量双主题方案(~80 行,在 theme.ts 注入 `[data-theme="dark"] .d2-xxx { fill: ... }` 覆盖规则),多 1-2 人日。

### 3.4 动画层:Motion Governor 极简版

借鉴 Archify 5 触发条件(265 行 → 极简 ~50 行):

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation: none !important; transition: none !important; }
}
html[data-motion="still"] * { animation: none !important; }
```

- **留**:`prefers-reduced-motion`(无障碍硬需求,S9)+ 1 个暂停按钮(`data-motion="still"`)。
- **删**:多面板互斥所有者逻辑(MVP 只有 1 个面板)、Story Trail 章节回放、visibilitychange 暂停(Tier 2)。

### 3.5 导出层:PNG 预览(可选)

**PNG 导出路径优先级**(沿用 PRD open_point #3,行号已修正):
1. **首选 puppeteer-core**(L48,已在 dependencies `^25.3.0`):headless Chrome 截图,色彩与 viewer 一致,CSS 变量自动解析。
2. 备选 `@napi-rs/canvas`(L56,optionalDep):离线兜底,某些 Linux 环境装不上。
3. 末选 `@resvg/resvg-js`(L43,已在 dependencies):进程内、确定性,但不解析 CSS 变量,需先用 `resolveVars(themeAttr)` off-DOM probe 把 CSS 变量烤进 SVG 属性再光栅化。

**`pickSafeScale` 4→3→2→1 降级**:防 iOS Safari 16Mpx canvas 上限。

**MVP 默认 `previewPng=false`**,用户显式要才导(避免每次启 Chrome 拖慢)。

### 3.6 自包含:markmap 范式 fillTemplate

- **sentinel 占位符 replace**:用函数式 `.replace(callback)` 避免 `$&`/`$'` 被解释为替换模式。
- **零外链 `<script src=`**(S2 硬约束):所有 JS inline。允许 `<link rel="stylesheet"` 指字体 CDN(Google Fonts),但 MVP 默认不引(系统字体栈兜底)。
- **确定性**:模板内无 `Math.random`/`Date.now`,无字典乱序遍历,同输入同输出。

### 4.3 renderer 函数签名(`src/interactive-html/index.ts`)

```ts
export interface InteractiveDiagramRequest {
  code: string;                        // D2 DSL(必填)
  theme?: string;                      // 浅色(D2 themeID 或 default/neutral)
  darkTheme?: string;                  // 深色(传了才触发 @media prefers-color-scheme 双调色板)
  title?: string;                      // HTML <title>
  previewPng?: boolean;                // 是否同时导 PNG 预览
  name?: string;                       // 文件名(不含扩展名)
  outDir?: string;                     // 落盘目录(handler 已 resolveOutDir 解析)
}

export interface InteractiveDiagramResult {
  localPath: string;                   // HTML 绝对路径
  previewPngPath?: string;             // PNG 预览绝对路径(previewPng=true 时)
  bytes: number;                       // HTML 体积(S6 校验)
  hasDarkLightDualPalette: boolean;    // 是否双主题烤进(S4 校验)
}

export async function renderInteractiveHtml(
  req: InteractiveDiagramRequest,
  engine?: DiagramEngine,  // 可选,测试注入 stub(方案 A,PRD open_point #15 已解决)
): Promise<InteractiveDiagramResult> {
  // 1. D2 渲染(传 darkThemeID/noXMLTag/salt 三杠杆)
  const d2Engine = engine ?? (getDiagramEngine("d2") as D2Engine | undefined);
  if (!d2Engine) throw new Error("D2 engine unavailable");
  const rendered = await d2Engine.render({
    code: req.code,
    engine: "d2",
    format: "svg",
    theme: req.theme,
    darkTheme: req.darkTheme,           // → darkThemeID(C1,在 d2.ts L137-140 合并)
    noXMLTag: true,                      // C2 硬编码
    salt: "media-gen-mcp-interactive",   // C3 硬编码
  });
  const svg = rendered.svg;
  // 2. 套 HTML 模板
  const html = fillTemplate({ svg, title: req.title ?? "Interactive Diagram" });
  // 3. 断言(S2/S3/S4/S6/S9/S11)
  assertSelfContained(html);
  assertNoXmlDecl(html);               // C2 防线
  if (req.darkTheme != null) assertDualPalette(html);
  assertMotionGovernor(html);
  assertSizeUnder(html, 256 * 1024);
  // 4. 落盘(renderer 内部直写,不经 writeLocalRender —— HTML 不在 svg|png format 类型内)
  const safeName = path.basename(req.name ?? `interactive_${Date.now().toString(36)}`);
  await fs.mkdir(req.outDir!, { recursive: true });
  const localPath = path.join(req.outDir!, safeName + ".html");
  await fs.writeFile(localPath, html, "utf-8");
  // 5. 可选 PNG
  let previewPngPath: string | undefined;
  if (req.previewPng) previewPngPath = await exportPngFromSvg(svg, req.outDir!, safeName);
  return {
    localPath,
    previewPngPath,
    bytes: Buffer.byteLength(html),
    hasDarkLightDualPalette: req.darkTheme != null,
  };
}
```

**注**:`Date.now()` 用于"用户未传 name 时的默认文件名",不影响产物 HTML 内容(HTML 内无 Date.now())——所以**不破 S5 byte-identical**(HTML 内容确定性,文件名非产物内容)。

### 4.4 output 类型(handler 返回给 MCP client)

沿用项目 `ok(data)` 范式(L1469),data 结构见 §4.2 的 `ok({ local_path, bytes, ... })`。
