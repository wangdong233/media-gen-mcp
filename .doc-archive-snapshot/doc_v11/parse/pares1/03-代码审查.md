## 4. Round 1 · 每维度详查

### 4.1 代码规范(4 条:F1 / F2 / F3 / F4)

#### F1 [medium] · render_video 多语言触发词双重出现

- **现象**:`render_video` 描述同一组多语言词 `Animation · animación · animation · Animation · анимación` 出现 2 次 —— 一次塞进 WHEN 子句末尾的括号内 `(Animation · animación · animation · Animation · анимación)`,一次作为尾部正规的 `Multilingual triggers:` 段。其余 18 个工具一律只在尾部 `Multilingual triggers:` 段放一次,`render_video` 是唯一破例。
- **后果**:
  1. 浪费约 58 字符 context 预算(PRD §3.3 L128 明示要控 ≤1100;实测 820 字符,虽未破硬限,但字符预算冗余);
  2. 同一信息两处来源,日后更新易漏改其一(产生新不一致);
  3. WHEN 段本该聚焦"场景",混入多语言关键词反而稀释 WHEN 路由信号。
- **根因**:PRD §4.5 render_video 明细要求"补触发词 Animation · animación · ...(ja/es/fr/de/ru)"一份,PRD §4.4(4) after 模板原文本身又把该词清单塞进 WHEN 括号。实施者按 02-实施记录 §2.3 逐字落地 PRD after 文案 —— **PRD 文案层冗余,非实施引入**。
- **R2 复审决策**:**不改代码**。若 P0-1 自行删 WHEN 内嵌版本,会与 PRD after 文案产生偏离,违反"实施者忠于 PRD"红线;正确路径是 PRD 文案优化(去 WHEN 内嵌版本)。已登记至 open_points 转交 PRD 维护方,并由 P0-3 LLM-as-judge 验证路由收益(若路由无收益则 PRD 删冗余,若 Claude 实际靠 WHEN 内嵌版本命中则保留并同步更新 §4.2 模板)。

#### F2 [low] · generate_diagram 字符预算紧约束

- **现象**:`generate_diagram` 描述当前 **1096 字符**(实测一致),距 PRD §3.3 L128 的 1100 硬限仅余 4 字符。
- **影响**:PRD §2.3 R11 + 功能分析 §2.3 明确 P0-5 将在本描述末尾 append `NEXT` 指向新工具 `generate_interactive_diagram`;一条最简 NEXT 行(如 `\n\nNEXT: for interactive HTML diagrams use \`generate_interactive_diagram\`.`)即约 75 字符,1096 + 75 = 1171 **必破 1100**。P0-1 当前落地让 P0-5 的 rebase 协议(R11)面临"违约超限"或"回头缩 generate_diagram"二选一。
- **R2 复审决策**:**不改**。R11 明示 P0-5 rebase onto P0-1 时负责压缩(典型手段:合并 LIMITS 段 4 行、裁掉 `mermaid is not supported in-process (needs a browser); use d2 or graphviz instead` 这种已在 engine enum description 里说过的兜底句);PRD §9 open_point #9 RESOLVED 已预判此协调。**P0-1 自身 ≤1100 合规**,非 P0-1 缺陷。

#### F3 [low] · AVOID 格式列表式 vs 内联式混用

- **现象**:7 工具含 AVOID,格式两派:
  - **列表式**(5 个,canonical 形态):`generate_image`(L123)、`create_video`(L151)、`analyze_chart`(L236)、`generate_chart`(L325)、`render_svg`(L411)

- **R2 复审决策**:**可选**(建议方案 A:把 3 个内联式改列表式)。不阻断 P0-1;若做,独立小 PR。PRD §4.2 模板把 AVOID 写成列表式为 canonical 形态。
