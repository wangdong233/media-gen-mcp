## 4. 遇到的问题与解决

### 4.1 PRD before/after 文本内的双引号 → 改用单引号嵌入(R9 衍生)

**问题**:PRD §4.4(1)–(5) 的 after 文本在 `WHEN: user says "柱状图..."` 处用了 **双引号**。若直接照搬到 TS 双引号字符串字面量内,需逐个转义为 `\"`,源码可读性下降,且易漏转义触发 tsc 错。

**解决**:沿用现有 `create_video` L151 的 `'生成视频/做动画'` 模式 —— **双引号字符串内嵌单引号**(无需转义),把 `WHEN: user says "X"` 全部改为 `WHEN: user says 'X'`。语义不变,Claude 读到单引号亦理解为引用片段。

**验证**:`grep -nE 'description:\s*\`' src/index.ts` 零命中;`npm run build` 0 error。

### 4.2 generate_diagram NEXT 行归属(P0-1 vs P0-5)

**问题**:分析 §2.3 / R11 警告 generate_diagram L289 是 P0-1 与 P0-5 都要改的"单行字符串热点",后落地者全量重写会静默丢失对方 cross-ref。

**解决**:严格按分析 §6 S3 + §14 硬规则 4 —— **P0-1 只做中段 AVOID in-place 改写**(`hand-writing SVG is appropriate` → `use \`render_svg\` (hand-written SVG with feGaussianBlur) instead`),**不加 NEXT 行**;`render_svg ↔ generate_diagram` 双向 cross-ref 的 NEXT 在对侧 `render_svg` 上(§2.2 已落)。

**验证**:T5 `generate_diagram` 描述含 `render_svg` ✅ + 不含 `NEXT:` ✅。P0-5 实施者按此 canonical 字符串末尾 append NEXT 指向 `generate_interactive_diagram` 即可。

### 4.3 count-desc-chars.mjs 入库位置(避免污染代码 repo)

**问题**:PRD §5.2 + 分析 §4.2 提到该脚本"不入 media-gen-mcp repo"。若放 `scripts/` 会被 npm test 误执行 / 被 `npm publish` 误打包。

### 4.4 tools/list 渲染冒烟(T4)的等价覆盖
