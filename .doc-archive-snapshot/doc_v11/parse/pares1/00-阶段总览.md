## 1. 本阶段做了什么

### 1.1 解决的路由盲区(用户视角)

media-gen-mcp 的 19 工具是 **model-controlled**(Claude 自主选工具),`description` 是路由唯一信号源。本阶段修复四处实证缺陷:

| 缺陷 | 修复 |
|---|---|
| **互逆操作零 cross-ref** —— `generate_chart ↔ analyze_chart` 双向零互指,用户说"识别图表数据"可能误选 `generate_chart` | 双向 AVOID 建立:`analyze_chart` 加 `AVOID: Rendering a chart FROM data → use \`generate_chart\` instead`;`generate_chart` 加反向 AVOID |
| **memory 实证翻车** —— `generate_image` 未指 `generate_card`/`generate_icon`,用户 memory 里有 `prefer-generate-card-for-cards.md` 补丁(补丁的存在即缺陷证据) | `generate_image` 加 `AVOID: Text-heavy cards / OG images / posters → use \`generate_card\``+ `existing brand logo → use \`generate_icon\``,根因消除 |
| **单向 cross-ref 缺 reciprocal** —— `create_video → render_video`(仅对侧反指)、`render_svg ↔ generate_diagram`(互提"D2"不点工具名) | `create_video` 加 AVOID 指向 `render_video`;`render_svg` 把模糊的"that D2 cannot produce"改为点名 `generate_diagram` 并加双向 AVOID |
| **6 工具缺 NEXT 工作流引导** —— `extract_text`/`extract_table`/`generate_formula`/`generate_qrcode`/`list_vision_capabilities`/`extract_pdf` 邻居不可达 | 每工具追加 1 行 NEXT 指向伴生工具(P0-5 rebase 预留:`generate_diagram` 不加 NEXT) |

### 1.2 改造形态(架构视角)

纯 prompt engineering,**零结构变动**:
- 没有新模块、没有新 import、没有新 handler 分支、没有新 inputSchema 属性、没有新 enum 值
- `buildTools()` 仍是单文件 19 元素数组(L114–491)
- handler 仍是 L495 的 `CallToolRequestSchema` 单 switch
- 唯一改动 = 16 个 TS 双引号字符串字面量的值

### 1.3 写作约定(给后续阶段复用)

- **单行双引号字符串** + `\n\n` 段落分隔(全 19 工具共 42 处;`tools/list` 渲染正常)
- **反引号 `` `tool_name` `` 标注 sibling 工具名**(双引号内嵌反引号合法 TS)
- **四段标记全英文全大写**:`WHEN:` / `AVOID:` / `NEXT:` / `Multilingual triggers:`(便于 grep 验证)
- 严禁模板字面量 `` `...` ``(防 `${}` 误插值)
