## 1. 背景与目标

### 1.1 P0-1 解决什么盲区

media-gen-mcp 的 19 个 MCP 工具是 **model-controlled**(由 Claude 自主选择),description 是路由的唯一信号源。当前 description 偏"参数说明书",缺失三个工作流要素:

1. **WHEN 触发不显式** — 仅 15/19 工具有 WHEN,4 个伴生/列表工具(get_video / get_pdf / list_models / generate_qrcode)只列参数。
2. **AVOID 负向引导缺位** — 仅 7/19 有(render_video / generate_card / extract_table 是黄金范例),12/19 完全没有"什么场景别用我"。
3. **cross-reference 兄弟工具单向或断链** — 9/19 有,但存在**三处断链实证**:
   - `generate_chart ↔ analyze_chart`(职责互逆,双向零 cross-ref)— **最高路由冲突**
   - `generate_card ↔ generate_image`(仅 generate_card 单边指)
   - `create_video ↔ render_video`(仅 render_video 单边指)
   - `generate_diagram ↔ render_svg`(互提引擎名"D2"却不点对方工具名)

**翻车实证**:`memory/prefer-generate-card-for-cards.md` 条目"文字/OG/分享卡先用 generate_card(Satori 确定性出图);HTML+headless Chrome 仅作特效兜底"——**这条 memory 的存在本身就是 generate_image 描述路由失败的证据**,用户被迫人肉补丁。

### 1.2 成功标准(可验证)

| # | 标准 | 验证方法 |
|---|---|---|

   **答案(已抓 Anthropic 官方 define-tools.md / tool-use/overview.md 一手原文核实)**:三个子假设里——一条官方直接支持(WHEN/AVOID 的"正负向触发"思路),一条官方沉默(首句权重),一条官方实际上**反向**(cross-reference 与"压缩"方向)。把它当"社区共识"是**高估了**。逐条核对:

   - **假设 1「首句权重最高」→ 官方无此说法(基本可否定)**。define-tools L81 把"description 的最重要的因素"排序为"**Provide extremely detailed descriptions.
