### 2.3 关键时序约束(必读)

1. **P0-1 → P0-5 的 description 合并约束**(P1,机械可解):两 PR 都改 `src/index.ts` L288-289 的 generate_diagram description 单行字面量,Git 三方合并必报 textual conflict。**推荐落地顺序:P0-1 先合并 → P0-5 rebase**,把 P0-5 的 NEXT append 拼到 P0-1 改过的 canonical 字符串末尾,**禁止全量重写覆盖 P0-1 的 AVOID 句**。合并断言:含 `render_svg` + 含 `generate_interactive_diagram` + `NEXT:` 出现恰好 1 次 + 长度 ≤1100。
2. **P0-2 ↔ P0-3 同批落地**:P0-2 冒烟测试 `test/error-format.smoke.mjs` 依赖 P0-3 引入的 `node --test` runner;**建议同 PR 链或紧接落地**。
3. **P0-3 pngjs 是 P0-4 的版本单一来源**:P0-4 后合时只新增 `@xmldom/xmldom ^0.9.0` + `jsqr ^1.4.0`,pngjs 版本号不独立选型(跟随 qrcode@1.5.4 传递依赖 ^5.0.0),否则触发 lockfile 漂移 + npm 嵌套两份。

## 6. P0-5 立项决策门(量化标准)

### 6.1 触发条件(任一满足即可立项 MVP)

> **重要前置**:P0-5 调研文档 §1.1 单句断言"用户想在 GitHub README 嵌一张随系统主题切换的架构图,当前完全无解"是当前唯一依据(等级 C)。三源归零实测:GitHub issues `wangdong233/media-gen-mcp` open+closed 均 0;9 个 user memory 文件 grep 关键词全 0;README 同关键词全 0。

| 条件 | 阈值 | 当前实测 | 是否触发 |
