## 1. 需求复述与 01 §2.1 同构论证

### 1.1 用户需求(原话)

> "嵌套构造抽象层,点层展开内部,面包屑回溯,含时序图等异构图"

四个关键诉求:

1. **嵌套构造抽象层**:支持"顶层图 → 各节点可 drill 进看子图"的多层级抽象表达
2. **点层展开内部**:点击某节点切换到该节点的子图(交互)
3. **面包屑回溯**:有面包屑导航支持回跳任意祖先层
4. **含时序图等异构图**:子图不限于架构图,支持 sequence / er / class / flowchart 多类型

### 1.2 与 01 §2.1 的同构(强对齐)

01 §2.1 原文(`01_简单架构思想.md:45-49`):

> "航母、SpaceX 火箭……在总工程师眼中,它们必须极其简单……总工程师看到的是抽象层面的逻辑分层:船体、休息舱、战斗舱、指挥室、武器系统、甲板;**每个舱室再逐层细分抽象**。"

**逐项同构映射**:

| 01 §2.1 航母例子 | 本工具 |
|---|---|
| 总工程师眼里顶层分舱(船体/战斗舱/指挥室…)| manifest 顶层图(架构的顶层抽象) |
| 每个舱再逐层细分 | 每个节点 drill 进去看它的内部子图 |
| 模块交互复杂就再抽象一层 | 子图仍复杂就再 drill 一层 |
| "限界上下文/模块化/解耦本质都是抽象的封装与分层,根本目的只有一个——为了简单" | manifest 本身就是这份"分层抽象"的显式声明 |

**它是 01 哲学的 practice tool,而非只是又一个产物**:

- **01 §1.3(L27-29)"抽象是手段,简单才是目的"** —— manifest **强制架构师把脑子里的抽象显式声明出来**。声明不出来 = 抽象未成型 = 系统还没真简单。这一步把"我觉得它简单"从口味变成可争论的工件。
- **01 §2.3(L66)"你能指着代码说出'这里把 X 和 Y 缠在一起'"** —— drill 进某节点,如果子图本身是一团乱麻,架构师**当场看见**这层抽象没做好。drill = 对每一层抽象做 §2.5 刻度一(交织度)的逐层验证。
- **01 §5.3(L316)"复杂性可以从抽象层面掌控"** —— 本工具把这句话从结论变成可操作动作:**只要每一层子图都干净,整棵树就在抽象层面简单**,无论实体多大。

**关键诚实声明(防过度论证)**:本工具**不创造简单,只暴露简单与否**。它把架构师已有的抽象外化成可 drill 的树;如果架构师**编造**一个与真实代码结构不符的 manifest,drill 进去就会发现"子图描述的模块和实际代码对不上" —— 这个落差正是 01 §2.5 刻度四(Evans DDD:"软件语言与领域真实结构是否同构",L133)的违反信号。**工具是尺子,不是手术刀**。

## 2. OSS 调研结论

详细调研见 `OSS-drill-down范式调研.md`,此处只摘决策相关结论。

### 2.1 drill-down 三范式分类与本工具裁决

| 范式 | 定义 | 代表工具 | 本工具适配性 |
|---|---|---|---|
| **A. 替换视图(view stack)** | 整层 SVG 淡出/淡入,stack push | C4/Structurizr/draw.io/D2 cross-board | **✅ 选定** |
| B. 折叠原位(fold/expand-collapse) | 父子同画布 toggle 显隐 | markmap/React Flow/D3 collapsible tree | ❌ D2 几何不支持 |
| C. 几何缩放(zoom-into) | 相机放大到子图区域 | D3 zoomable treemap/BigPicture | ❌ 需父子几何共存 |

**选定范式 A 的三条硬约束(证据 L1/L2)**:

1. **D2 几何约束**:D2 父图把 nested container `order_service.pay` 画成单个矩形框,**子图内部几何不存在于父 SVG**(D2 repo 核实 + `drill-down-navigation-design.md §1.2`)。范式 B/C 要求父子几何共存 → 要么自研 layout(违反 doc_v12 §2 第 2 条"不自研编辑器"),要么浏览器跑 D2 WASM 21MB(NO-GO 超 S6 80-125 倍)。
2. **状态模型**:范式 A 栈 = `stack=[root,X,Y]` 纯字符串数组 ~80 行 vanilla JS;范式 B 需 expanded-set + 重布局级联;范式 C 需 viewBox/transform 矩阵。**01 §2.3(simple=不交织)**:A 把"显示哪层"与"层内几何"钉在不同单元,B/C 把它们缠一起。
3. **面包屑语义**:面包屑是 supplement navigation(NN/g),只有范式 A 的 stack 自然就是面包屑;B 的 expanded-set 是分支非路径;C 的 transform 是相机非层迹。

### 2.2 关键借鉴(借工艺不抄代码)

| 来源 | 借鉴件 | license 处理 |
|---|---|---|
| **Structurizr/C4** ⭐ | Context/Container/Component/Code 四层抽象心智模型 → manifest ManifestNode 树已映射;double-click drill 语义 | L1 原文 docs.structurizr.com 确认保留 drill-down,但 diagrams-only + 多文件 + iframe 非单文件,范式借不直搬 |
| **markmap** ⭐ | `fillTemplate(root,{jsonOptions})` inline JSON 注入 HTML → design §2 `<script type="application/json">` 同构;`--offline` 全资源 inline 策略 | MIT;交互是范式 B fold 与 D2 几何冲突,只借鉴数据序列化范式 |
| **D2 原生** | `Diagram.layers/scenarios/steps` 递归 AST(`index.d.ts:82-84`)+ `target` 定向渲染(L23-24)+ `salt` 防 SVG ID 冲突(L27-28)+ `ShapeBase.link` drill 锚(L114)|  MPL-2.0 已用 |
| **Archify** | chevron-down drillable 角标(NN/g 实测最强 in-place 展开 signifier)+ viewer/geometry 分层不变量 + Motion Governor 5 触发条件 + 导出 strip viewer-state | license 未明,**全 reimplement 不抄代码** |
| **draw.io** | `shape.link = 目标 page id` 数据模型 → manifest `children: string[]` | Apache 2.0 但 viewer-static bundle ~3.8MB 超 S6 15 倍,viewer 整体 NO-GO |

### 2.3 关键差异化价值点

> **所有调研工具均无原生 breadcrumb 回溯** —— 这是本工具相对所有 OSS 的差异化价值点;design §5 的头 2+尾 2 折叠面包屑是基于 NN/g + IXDF 证据自建,无 OSS 直接先例。

### 2.4 砍弃清单(过度工程/立场冲突)

- **Archify 10500 行 viewer**(含 Story Trail/Route Probe/Semantic Lens/Overview Radar,doc_v11 §5.4 已定不搬)
- **Archify Story Trail**(时间维度叙事幻灯片,与空间维度 drill 概念不同不可混淆)
- **Archify preset 系统**(classic/signal-flow/blueprint,与 D2 theme 概念冲突)
- **ajv standalone codegen**(MCP server 运行时 ajv 不是负担)
- **结构化 IR→DSL 编译层**(推翻 engine 管布局价值)

## 3. 架构方案

### 3.1 新工具名:`generate_nested_diagram`

**弃用名** `generate_architecture_map`。三条理由:

1. **结构属性精确**:"nested" 描述"图嵌套成树"的结构属性,与 D2 官方 "nested composition" 概念、viewer 的 view-stack 范式同名
2. **diagramType 五值通用**:`architecture | sequence | er | class | flowchart` 挂每节点;"architecture" 进名会误导用户以为只画架构图
3. **命名阶梯一致**:`generate_diagram`(静态)→ `generate_interactive_diagram`(单图交互)→ `generate_nested_diagram`(嵌套树交互),三档各自独占 entry

### 3.2 与两兄弟工具的关系(深模块共用 / 分立 entry / 不缠绕)

```
                共用深核(只读 import,零改源码)
                ┌──────────────────────────────────────────┐
                │ D2Engine singleton (render.ts:14)         │
                │   ├ 三杠杆条件展开 (d2.ts:141-149)        │
                │   ├ chain 串行 (d2.ts:176-177)            │
                │   └ resolveD2Theme 空白归一 (d2.ts:54-62) │
                │ ├─ HTML template 范式 (template.ts)       │
                │ ├─ VIEWER_CSS_VARS 双调色板 (theme.ts)    │
                │ ├─ MOTION_GOVERNOR_CSS (motion-governor.ts)│
                │ ├─ ANIMATIONS_CSS (animations.ts)         │
                │ ├─ escapeHtml + F11 sentinel 范式         │
                │ │   (fill-template.ts:17-24, 40-44)        │
                │ └─ F13 错误路由 (index.ts:1050-1068)      │
                └──────────────────────────────────────────┘
                              ▲           ▲           ▲
                              │import     │import     │import
              ┌───────────────┴──┐ ┌──────┴────────┐ ┌─┴──────────────┐

              │                  │ │ diagram       │ │ (NEW)          │
              │ entry: 1 张图    │ │ entry: 单图+  │ │ entry: 嵌套树  │

**严守"独立 entry 不做超集"**(对齐 01 §3.2 Metz "错误抽象比重复更糟"):

- 绝不把 single 降为"1 节点树特例"
- 绝不引入 `mode: 'single' | 'nested'` 参数(那是退化路径)
- `generate_interactive_diagram` 签名/契约/源码零变化,byte-identical 由"不碰其代码路径"天然保证

**check-schema G2 工具数 20→21**:`scripts/check-schema.mjs:48-49` 的硬编码工具名清单须同步追加 `generate_nested_diagram`(同 P0-5A 19→20 是正当例外)。

### 3.3 端到端数据流

```

  ▼
[2. ManifestNode → LayerSpec 转换] ── 显式字段映射契约(钉死,见 §3.4)
  ▼

  │      d2Engine.render({ code, engine:"d2", format:"svg", theme, darkTheme,
  │                        noXMLTag:true,

**关键不变量**(扩展 `viewer-min.ts:13` "绝不重渲染 SVG / 绝不算几何" 到嵌套树):

> drill 只 toggle `.mgm-view` 的 `hidden` 属性(**display-toggle-only**),绝不触发 D2 render / 绝不改 SVG / 绝不算坐标。违反即回收。

### 3.4 ManifestNode ↔ LayerSpec 转换契约(钉死 🔴)

| ManifestNode(producer)| LayerSpec(viewer)| 转换规则 |
|---|---|---|
| `id: string` | `id: string` | 直传;校验 `^[a-z0-9-]+$` |
| `label: string` | `title: string` | 直传;**viewer 侧强制 `escapeHtml`**(信任边界,🔴 blocking 1) |
| `diagram: string` | `svg: string` | 经 D2 render;salt = `media-gen-mcp-nested-${id}`(确定性,🔴 blocking 3) |
| `diagram=""`(分组容器)| `viewMode: "container-list"` | svg 空串;viewer 渲染 placeholder + children 卡片高亮(🔴 blocking 2 补全) |
| `diagramType?` | (不进 LayerSpec)| 仅 producer 提示 |
| `children?: ManifestNode[]` | `children: string[]` | BFS 序列化收 id 数组(递归引用转 id 引用) |

| `notes?` | (不进 LayerSpec)| producer 自用 |

## 4. manifest 数据契约(摘要)

完整契约见 `manifest-schema与示例.md`,此处只摘决策要点。

### 4.1 Schema(6 字段,3 必填 + 3 选填)

```typescript
interface ManifestNode {
  id: string;                 // 必填,跨树唯一,^[a-z0-9-]+$
  label: string;              // 必填,UI 文字(viewer 强制 escapeHtml)
  diagram: string;            // 必填,允许空串(""= 分组容器)
  diagramType?: DiagramType;  // 选填,缺省 "architecture"
  children?: ManifestNode[];  // 选填,缺省/[]/undefined 三者等价 = 叶子
  notes?: string;             // 选填,WHY 旁注(producer 自用,不进 viewer)
}
type DiagramType = "architecture" | "sequence" | "er" | "class" | "flowchart";
type Manifest = ManifestNode; // root 就是节点,不另设 wrapper
```

### 4.2 字段数裁决(化解调查间矛盾)

inv:01-alignment-scope §2.1 倾向"≤4 字段",inv:input-manifest 是 6 字段。**主控裁决:6 字段**。理由:

1. notes 选填不影响核心简单性
2. id/label/diagram + children 已是抽象最小集
3. diagramType 缺省智能推断平衡概念完整性与易用性
4. 01 §3 "抽象是手段非目的" —— 字段数不是越少越好,而是"每个字段都过得了 review 三问"。6 字段全过审。

### 4.3 Producer 契约验证(V1-V5)

| 验证 | 含义 | 失败行为 |
|---|---|---|
| V1 | id 唯一性(DFS size == 节点数) | 整树拒绝 |
| V2 | 无环检测 | 整树拒绝 |
| V3 | 必填字段完整(id/label/diagram 非 undefined,label 非空串) | 整树拒绝 |
| V4 | diagramType 合法 enum | 整树拒绝 |
| V5 | children 递归闭合 | 整树拒绝 |

**叠加**:id 字符集 `^[a-z0-9-]+$`(URL hash 友好 + 防 D2 ID 元字符 + 防 salt 注入)。

**写前先校验**(03 §1.2 项 3):严禁部分加载,防 cc-status-dot Anchor B 同构失败类问题。

### 4.4 YAGNI 拒绝(10 项)

严拒 version/permissions/layout/$ref/style/tags/createdAt/i18n/collapsed/thumbnail。每项拒绝理由 + 何时 reconsider 详见 `manifest-schema与示例.md §5`。

## 5. 导航 UX(摘要)

详细设计见 `drill-down-navigation-design.md`,此处只摘决策要点。

### 5.1 视图栈实现(纯 vanilla JS IIFE ~230 行)

- `stack=[root, layer1, ...]` 数组,`render()` 显示 `stack[last]` 的 SVG + 渲染面包屑 + `history.replaceState` 同步 URL hash
- `drillInto(id)` push,`popTo(idx)` 面包屑跳某级,`goUp()` Esc 上一级
- 5 个不变量(INV-1..5):`stack[0]===ROOT` 永真;`stack[i+1]` 必在 `stack[i].children` 中(防 hash 越权);URL hash 与 stack 一一对应;叶子节点永不进栈;Motion Governor 管 FADE_MS

### 5.2 可点击信号(三层组合)

- **chevron 角标**(右下角 SVG `<text>▾</text>`,NN/g *Accordion Icons* 实测 caret 是最强 in-place 展开 signifier)
- hover `drop-shadow` + `cursor:pointer` + `:focus-visible` 蓝边
- `<title>` tooltip "点击/回车 进入「X」子层" + `aria-label`

**叶子节点严格不加任何 drill 信号**(防"误以为可 drill → 点击无效 → 信任崩塌",01 §3.4 诚实信号原则)。

### 5.3 面包屑

- `<nav aria-label="层级导航">` 顶部 trail,每级 `<button>` 可点回(`popTo(idx)`),当前级 `aria-current="page"` 不可点
- NN/g 证据:breadcrumbs 是 supplement 非 primary,3+ 级才有价值
- 折叠阈值 `stack.length > 5`:头 2 + 尾 2 + `…`,root 与 current 永远可见
- 单层时 `display:none` 节省垂直空间

### 5.4 深链/分享

- URL hash `#path=root/order_service/pay`,`encodeURIComponent(ids.join('/'))`
- `hashchange` 触发 `restoreFromHash()`,沿 `LAYERS[id].children` 链逐段校验(INV-2 安全边界),断裂即降级 root 不抛错
- **离线单文件 hash 仍工作** —— hash 永不到 server,`file://` 双击打开仍能恢复视图
- 用 `history.replaceState` 而非 `pushState`(浏览器 back 应是"离开此 HTML",非"视图栈内回上一层")

### 5.5 性能策略:全预嵌(推荐),懒载全部出局

证据:D2 WASM 21.0MB / browser bundle 7.8MB / elk.js 3.5MB,全部超 S6 cap(256KB)80-125 倍。懒载路径全部不可行:

- 浏览器内跑 D2 WASM 太重
- fetch 外部 .svg 破"单文件自包含"
- Service Worker 破 `file://` 支持

**全预嵌体积表**:

| N(节点数)| 单层均体积 | 总体积 | 与阈值对比 |
|---|---|---|---|
| 6 | 25KB | 150KB | 安全 |
| 8 | 30KB | 240KB | 贴单图 cap |
| 12 | 30KB | 360KB | **超单图 256KB**(故须解耦) |

**阈值裁决**:`NESTED_SIZE_CAP = 1MB`,与单图 256KB 解耦(01 §2.4 阈值校准哲学);soft cap N≤6、单层 ≤25KB 写工具 description;handler 层硬封顶 N ≤50,大树返 hint(不可静默)。

## 7. 三个 🔴 blocking issues(实施前必钉死)

### B-1 [1.2 🔴 producer 契约 / 信任边界] label escape 缺位

**问题**:`输入manifest数据模型.md §2.3` 规定 label "直接渲染 UI,不 escape(producer 负责)"。违反 03 §1.2 项 7(每个信任边界验证 input)+ §1.2 项 1(producer 契约需 L1 证据)。viewer 是 HTML 落盘的最后一跳,producer 是不可信的(AI/人手写皆可注入错误数据)。若 label 含 `</title><script>` 或面包屑注入 `</button>`,产物 HTML 即被破坏或 XSS。

**证据链**:
- `viewer-min.ts:107` 导出 SVG 用 XMLSerializer 已默认安全
- 但 nav §5.4 `renderBreadcrumb` 拼接 `escapeHtml(layer.title)` 是 JS 字符串拼到 innerHTML —— `escapeHtml` 函数位置(`fill-template.ts:17-24`)未在 viewer 侧明确
- 同样 drill §4.2 `attachDrillHandlers` 拼接 `aria-label` 与 tooltip 亦未明确 escape

**修正**:viewer 内部对每个 label/title 强制 `escapeHtml`(沿用 `fill-template.ts:17-24` escapeHtml 实现),契约文档改为"producer 保证语义,viewer 强制 escape"。**本次报告 §3.4 转换契约表已钉死此点**。

### B-2 [1.2 🔴 数据形状契约 gap] ManifestNode ↔ LayerSpec 转换未钉

**问题**:ManifestNode(producer 契约)与 LayerSpec(viewer 契约)是两个不同 shape,跨接缝的 L1 转换契约未钉死。两者间存在以下未钉死的字段映射:

- diagram 经 D2 渲染 → svg(渲染参数 theme/darkTheme/salt 从哪来?salt 必须 per-board 唯一但需确定性)
- diagramType 影响 svg 渲染但 LayerSpec 不带
- notes 是否进 viewer(设计中未渲染但 manifest 携带)
- ManifestNode.children 是 ManifestNode[] 递归,LayerSpec.children 是 string[](id 引用)—— 翻译时机(BFS 序列化)未定

违反 03 §1.4 项 5 "跨组件边界的 schema 必须 pinned 且显式"。

**修正**:**本次报告 §3.4 已显式列出每个字段映射 + 渲染参数来源 + 失败行为**(任一节点 D2 编译失败 → 整树拒绝)。

### B-3 [1.5/1.6 🔴 salt 策略未钉死]

**问题**:当前单图版固定 `D2_INTERACTIVE_SALT`(`index.ts:76`)。嵌套版必须 per-board salt 否则 D2 自身文档(`index.d.ts:27-28`)明言 "duplicate IDs cause invalid HTML"。但 per-board salt 的取值规则未定:

- 若用确定性(如 'mgm-' + board id)→ 必须明确算法并断言不含 D2 ID 元字符

**修正**:**本次报告钉死 salt = `media-gen-mcp-nested-${manifestNode.id}`**(id 已校验 `^[a-z0-9-]+$`,保证合法)。golden 测试 sha256 验证确定性。
