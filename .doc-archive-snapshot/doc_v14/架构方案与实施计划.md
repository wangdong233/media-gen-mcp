## 0. 工具定位与命名裁决

### 0.1 推荐工具名:`generate_nested_diagram`

弃用名 `generate_architecture_map`。三条理由(按权重排序):

1. **结构属性精确**:"nested" 描述的是"图嵌套成树"的结构属性,与 D2 官方 "nested composition" 概念、viewer 的 view-stack 范式同名;用户看名即知产物形态。
2. **diagramType 五值通用**:`architecture | sequence | er | class | flowchart` 挂在每节点(见 §4);"architecture" 进名会误导用户以为只画架构图,埋下"为何 sequence 节点能进架构图工具"的认知失调。
3. **命名阶梯一致**:产物形态递进对应工具名递进 ——
   - `generate_diagram`(静态一图,PNG/SVG)
   - `generate_interactive_diagram`(单图 + viewer,HTML)
   - `generate_nested_diagram`(树 + drill,HTML)

   三档各自独占 entry,共享深核(D2 render + template + viewer),不互相缠绕。

### 0.2 与两兄弟工具的关系(深模块共用 / 分立 entry / 不缠绕)

**共用深核(只读 import,零改源码)**:

| 复用对象 | 文件 | 复用方式 |
|---|---|---|
| D2 渲染深模块 | `src/diagram/render.ts` 的 `D2Engine` singleton | `getDiagramEngine("d2")` 拿 singleton(render.ts:14),N 次 `.render()` 调用,chain 串行(d2.ts:176-177) |
| 三杠杆条件展开 | `src/diagram/d2.ts:141-149` | 直接传 `theme/darkTheme/noXMLTag:true/salt`,杠杆原样生效 |
| HTML 双调色板 | `src/interactive-html/theme.ts` 的 `VIEWER_CSS_VARS` + `PREPAINT_RESOLVER_JS` | import 字符串常量 |
| Motion Governor | `src/interactive-html/motion-governor.ts` 的 `MOTION_GOVERNOR_CSS` | import |
| 动画 CSS | `src/interactive-html/animations.ts` 的 `ANIMATIONS_CSS` | import(注意 `:nth-of-type` 在隐藏 SVG 上占样式不占渲染,可接受) |
| fill-template 范式 | `src/interactive-html/fill-template.ts` 的 `escapeHtml` + sentinel 碰撞守卫(F11) | import escapeHtml;sentinel 守卫扩到 3 新 sentinel |
| PNG 预览 | `src/interactive-html/export-png.ts` | 导根层 SVG |
| F13 错误路由 | `src/index.ts:1050-1068` 范式 | 契约错抛 `[nested-diagram]` 前缀,D2/resvg 错走 `normalizeEngineError` |

**严守"独立 entry 不做超集"**(对齐 01 §3.2 Metz "错误抽象比重复更糟"):
- 绝不把 single 降为"1 节点树特例";
- 绝不引入 `mode: 'single' | 'nested'` 参数(那是退化路径);
- `generate_interactive_diagram` 的签名 / 契约 / 源码零变化,byte-identical 由"不碰其代码路径"天然保证。

**check-schema G2 工具数 20→21**:同 P0-5A 19→20 先例,是新工具正当例外;`scripts/check-schema.mjs:48-49` 的硬编码工具名清单须同步追加 `generate_nested_diagram`。

## 1. 架构与端到端数据流

```
ManifestNode 树 (producer 声明,Claude/架构师生成时写死)
  │
  ▼
[1. validateManifest] ── V1 id唯一 / V2 无环 / V3 必填 / V4 enum合法 / V5 递归闭合
  │                       字段缺失四态(undefined/null 禁 / 空串 / 空数组)逐字段定义
  │                       写前先校验(03 §1.2 项 3),严禁部分加载
  │                       🔴 label/title 等 producer 文本viewer侧强制 escapeHtml(信任边界)
  ▼
[2. ManifestNode → LayerSpec 转换] ── 显式字段映射契约(钉死,见 §3 表)
  │      diagram(DSL 字符串)→ D2 render → svg(已渲染字符串)
  │      diagramType 进渲染参数不进 LayerSpec
  │      children: ManifestNode[]  → children: string[](id 引用,BFS 序列化)
  │      notes 不进 viewer(producer 自用)
  ▼
[3. renderAllLayers] ── for each node where diagram !== "":
  │      d2Engine.render({ code: node.diagram, engine:"d2", format:"svg",
  │                        theme, darkTheme, noXMLTag:true,
  │                        salt: `media-gen-mcp-nested-${node.id}` })   // per-node 确定性 salt
  │      → 收集 LayerSpec { id, svg, title, parent, children, viewMode }
  │      (D2Engine chain 串行化自然排队;singleton 复用 22MB WASM)
  │      🔴 salt 公式钉死 = "media-gen-mcp-nested-" + node.id(id 已校验 ∈ [a-z0-9-])
  ▼
[4. assembleNestedHtml] ── fillNestedTemplate:
  │      <div class="mgm-view" data-view-id data-parent [hidden]> × N   // 视图栈,只 1 visible
  │      <nav class="mgm-breadcrumb"> ... </nav>                         // 面包屑 slot
  │      <script type="application/json" id="mgm-manifest">{树JSON}</script>  // 数据/视图分离
  │      reuse: VIEWER_CSS_VARS + PREPAINT_RESOLVER_JS + MOTION_GOVERNOR_CSS + ANIMATIONS_CSS
  ▼
[5. 契约 asserts] ── S_NESTED_1..5 + assertSelfContained(S2) + assertNoXmlDecl(S11)
  │                   + assertDualPalette(S4,if darkTheme) + assertMotionGovernor(S9)
  │                   + assertSizeUnder(html, NESTED_SIZE_CAP)   // 与单图 256KB 解耦,见 §6 阈值
  ▼
单文件自包含 HTML (落盘) + 可选根层 PNG 预览
```

**关键不变量**(扩展 viewer-min.ts:13 "绝不重渲染 SVG / 绝不算几何" 到嵌套树):

> drill 只 toggle `.mgm-view` 的 `hidden` 属性(**display-toggle-only**),绝不触发 D2 render / 绝不改 SVG / 绝不算坐标。违反即回收。

## 3. ManifestNode ↔ LayerSpec 转换契约(钉死 🔴)

| ManifestNode 字段(producer 契约) | LayerSpec 字段(viewer 契约) | 转换规则 / 渲染参数来源 |
|---|---|---|
| `id: string` | `id: string` | 直传;校验 `^[a-z0-9-]+$`(URL hash 友好) |
| `label: string` | `title: string` | 直传;**viewer 侧强制 `escapeHtml`**(信任边界,🔴 blocking 1) |
| `diagram: string` | `svg: string` | 经 D2 render;参数 `theme/darkTheme` 全局(树共享);`noXMLTag:true` 固定;**salt = `media-gen-mcp-nested-${id}`** 确定性(🔴 blocking 3) |
| `diagram=""`(分组容器) | `viewMode: "container-list"` | svg 是空字符串;viewer 渲染 placeholder + children 卡片高亮(不是 empty `<svg>`,🔴 blocking 2 补全) |
| `diagramType?: enum` | (不进 LayerSpec) | 进 D2 render 时不直接传(D2 自己 infer);仅 producer 提示用 |
| `children?: ManifestNode[]` | `children: string[]` | BFS 序列化时收 id 数组(递归引用转 id 引用) |
| (计算字段)| `parent: string \| null` | BFS 时记录父 id;root 的 parent = null |
| `notes?: string` | (不进 LayerSpec) | producer 自用,viewer 不渲染 |

**失败行为**(钉死):

- 任一节点 D2 编译失败 → **整树拒绝**(抛 `[nested-diagram]` 前缀),不部分渲染。理由:部分渲染会产生"某层点进去空白"的体验崩塌,违 viewer-min.ts:13 不变量扩展。
- manifest V1-V5 任一失败 → 整树拒绝,严禁部分加载(对齐 03 §1.2 项 3,防 cc-status-dot Anchor B 同构失败类问题)。

## 4. 关键接口签名(TS 草案)

```typescript
// manifest-types.ts
export type DiagramType = "architecture" | "sequence" | "er" | "class" | "flowchart";

export interface ManifestNode {
  id: string;                 // 必填,跨树唯一,^[a-z0-9-]+$(URL hash 友好)
  label: string;              // 必填,UI 文字(面包屑 + <title>);viewer 强制 escapeHtml
  diagram: string;            // 必填,允许空串(""= 仅分组容器,viewMode=container-list)
  diagramType?: DiagramType;  // 选填,缺省 "architecture"
  children?: ManifestNode[];  // 选填,缺省/[]/undefined 三者等价 = 叶子
  notes?: string;             // 选填,WHY 旁注(producer 自用,不进 viewer)
}
export type Manifest = ManifestNode; // root 就是节点,不另设 wrapper(01 §3 不发明概念)

// viewer 契约 shape(ManifestNode 经转换后的扁平化形态)
export interface LayerSpec {
  id: string;
  title: string;              // 已 escapeHtml 后的字符串
  svg: string;                // 已渲染 SVG(分组容器为空串)
  parent: string | null;
  children: string[];         // id 引用数组
  viewMode: "diagram" | "container-list";
}

// nested-diagram/index.ts
export interface NestedDiagramRequest {
  manifest: Manifest;        // 必填,树根
  theme?: string;            // 全局浅色(整树共享,01 §2.5 刻度四正交)
  darkTheme?: string;        // 全局深色;省略时 renderNestedDiagram 默认 "200"
  title?: string;            // HTML <title>+<h1>,默认 manifest.label
  previewPng?: boolean;      // 导根层 PNG(默认 false)
  name?: string;
  outDir?: string;           // handler resolveOutDir 注入
}
export interface NestedDiagramBuildResult {
  html: string;
  bytes: number;
  hasDarkLightDualPalette: boolean;
  layerCount: number;        // 实际渲染 SVG 数(diagram !== "" 的节点数)
}
export interface NestedDiagramResult extends NestedDiagramBuildResult {
  localPath: string;
  previewPngPath?: string;
}
export async function buildNestedHtml(
  req: NestedDiagramRequest, engine?: DiagramEngine
): Promise<NestedDiagramBuildResult>;
export async function renderNestedDiagram(
  req: NestedDiagramRequest, engine?: DiagramEngine
): Promise<NestedDiagramResult>;
```

## 6. 性能预算与尺寸阈值

### 6.1 渲染性能(N 次 sequential render 是硬上界)

- D2 WASM singleton 复用 22MB(d2.ts:10-11),N 次调用经 chain 串行(d2.ts:176-177)
- 单次 compile+render 各一次 WASM IPC 调用;源码无实测耗时,但 singleton 复用是最优解
- N > 20 时是真实瓶颈 → handler 层硬封顶 N(建议 ≤50)+ 大树返 hint(不可静默)

### 6.2 HTML 体积预算

| N(节点数)| 单层均体积 | 总体积 | 与阈值对比 |
|---|---|---|---|
| 6 | 25KB | 150KB | 安全(贴近单图 256KB cap) |
| 8 | 30KB | 240KB | 贴单图 cap |
| 12 | 30KB | 360KB | **超单图 256KB,必抛 S6**(故须解耦) |

**阈值建议**:`NESTED_SIZE_CAP = 1 * 1024 * 1024`(1MB);soft cap N≤6、单层 ≤25KB 写工具 description;超硬阈值抛清晰错误 + handler 返 hint 建议 producer 拆树或减节点复杂度。

**懒载全部出局**(单文件立场):浏览器跑 D2 WASM 21MB(超 80-125 倍)/ fetch 外部 .svg(破自包含)/ Service Worker(破 file:// 支持)—— 三条都不可行。**全预嵌是唯一可行性能策略**。

## 8. blocking 验证(实施前必跑)

### B1 [架构决定性·Phase 3 前必验] D2 SVG `<style>` 块的 CSS 作用域

多张 salt 后的 SVG 同 DOM 时是否 class 选择器冲突?

**probe 脚本**:用 node 跑两段 D2(不同 salt),查其 `<style>` 块:
- 若用 `#salted-id` 选择器 → 安全(hidden-div-toggle 可行,view-stack 架构成立)
- 若用 `.class` 选择器 → 冲突,须改 "template-store" 方案(只活一张 SVG,display 切换改为 stage.innerHTML swap)

**这是 view-stack 架构二选一的硬门**。WASM 冷启 ~60s,probe 已写待跑。

### B2 [drill 协议决定性·Phase 3 前必验] D2 `shape.link` 渲染产物

`b -> c: { link: "layers.foo" }` 产出 `<a xlink:href>` 还是仅 appendix?

**决定 viewer 拦截协议**:
- 若 `<a href>` → 直接 `preventDefault` + 读 href 切视图(零 DSL 扩展,最优)
- 若仅 appendix → 须自造 `data-drill-target` 属性注入(需后端 SVG 后处理)

probe 同 B1 一次跑即出。零 DSL 扩展优于自造点击机制,但依赖此验证。

### B3 [MVP 路径选择·Phase 1 前决] Path A vs Path B

- **Path A**(显式 manifest,N 段独立 D2 源):零 D2 能力验证依赖即可实施,简单可控
- **Path B**(单 DSL + D2 layers + target 定向渲染):需验 target 渲染产出 SVG 各 board 独立 viewBox/坐标系 + Shape.link 在 target 模式下产出可导航 URI

**主控建议**:MVP 走 Path A(零验证依赖),Path B 作 Tier 2。

**L1 证据补充**(本次核实):`@terrastruct/d2/index.d.ts:23-24` target 字段明言 "Multi-board outputs are currently only supported for animated SVGs",即 Path B 中"一次 render 多 board"不可行,必须 N 次独立单 target render —— Path B 相对 Path A 的优势仅是 compile 共享(1 次 vs N 次),render 次数相同。这降低了 Path B 的相对优势,支持 MVP 选 Path A。

### B4 [尺寸预算·Phase 4 前定] 嵌套版 S_NESTED 阈值

256KB 对 N 图明显偏紧(N=12 复杂图或破 360KB)。需按典型 N=10/20 的真实 D2 产出均体积回测后校准(01 §2.4 阈值校准哲学)。

**建议**:先跑 3 层电商示例 fixture 测实际体积,再定 `assertSizeUnder` 阈值(初步建议 1MB,可按回测收紧)。封顶 N 取多少待用户场景明确。
