## 1. 一句话结论

**当前 `generate_interactive_diagram` 在交互谱系上停留在 T3 viewer 档,用户"只切主题不算交互图"的判定在源码层成立;契约内最优升级 = T4 light-interact + AI 自然语言微调(click 选节点 → 回对话改 DSL 重生成),工时合计 ~2.5 人日,守全 5 立场 + inputSchema 零 diff,比自研拖拽(5+ 人日 / 破 3 立场 / 60% 用户价值)高 10× ROI;视觉拖拽编辑器(T5/T6)与单文件自包含立场物理冲突,必须文档化为出局 + 推荐外部工具;同时必须先修一个已存在的重大缺口——工具头号卖点"GitHub README 自动跟随主题"在当前实现下不成立(handler 从不写独立 `.svg` 文件,HTML 在 README 被剥 script 成废件,PNG 不能切主题)。**

## 2. 交互谱系定义 + 我们当前在哪档

### 2.1 六档定义(体积 / JS 依赖 / README 兼容性三层证据)

| 档 | 代表能力 | JS? | 体积量级 | GitHub README inline? | 备注 |
|---|---|---|---|---|---|
| **T1 static** | 纯 SVG/PNG,无动画无交互 | 无 | 几 KB | ✅ `<img src=*.svg>` | `generate_diagram` 在此档 |
| **T2 animated** | SVG + CSS `@keyframes` / SMIL,无 JS | 无 | 几 KB ~ 30KB | ⚠️ `<img src=*.svg>` 经 camo 透传时 `@media` + `@keyframes` 部分保留 | `animations.ts` 已交付 0.12.1 |
| **T3 viewer** | pan/zoom/theme/motion/export | inline vanilla ~150 行 ~30KB | ~30KB | ❌(README 剥 `<script>`) | **当前位置** |
| **T4 light-interact** | hover tooltip / click 高亮 / 详情面板 / 键盘导航 | inline vanilla ~10-30KB | <64KB | ❌ | **契约内升级目标** |
| **T5 mid-interact** | 拖节点 / contenteditable 标签 / 视觉改后导出 SVG | inline vanilla ~50-150KB + 轻量路由 | 64-256KB(贴 S6 上限) | ❌ | 拖节点边路由断裂是硬弱点 |
| **T6 full-editor** | 增删节点 + 自动重布局 + DSL 持久化 | React Flow / Cytoscape / draw.io / D2 WASM | 500KB-几十 MB | ❌ | **不可达**(破 S6 80-125 倍) |

### 2.2 当前位置证据(已在源码层核实)

- **viewer-min.ts = 126 行 vanilla JS**(`src/interactive-html/viewer-min.ts` L17-126)。`addEventListener('click', ...)` 全部绑在 toolbar 按钮上:`themeBtn`(L89)、`motionBtn`(L98)、`zIn`(L82)、`zOut`(L83)、`zReset`(L84)、`expSvg`(L106)。**SVG 内部 `<g class="shape">` / `<path class="connection">` 零事件监听**(grep `addEventListener` 实证)。
- **pan** = `viewer` 级 `pointerdown/move/up`(L53-74)、**zoom** = `wheel` + 按钮(L76-87)、**theme toggle** = `auto→light→dark→auto`(L89-96)+ `localStorage`、**motion toggle**(L98-104)、**export SVG** = `XMLSerializer + Blob`(L106-119)、**键盘** = `Esc/+/-`(L121-125)。
- **动画**(animations.ts,纯 CSS `@keyframes`):边数据流(L25-35)、边依次脉冲(L38-48)、节点淡入(L51-67)、悬停辉光(L68-70 `g.shape:hover` drop-shadow,纯视觉高亮,无信息展示)。

**判定**:用户"只切主题不算交互图"的判定 **在 SVG 层面 100% 成立**——viewer-min.ts 全部交互都绑 toolbar 按钮,SVG 内零节点级监听。当前是 T3 viewer 档(扎实)+ T2 动画档(已加 0.12.1),距用户字面诉求"T5/T6 拖拉拽/改标签/加节点"还差两档。

## 3. 两个根本约束 + 各自天花板

### 3.1 约束一:单文件自包含 HTML(离线 / 零外链 / 同输入同输出 / 守 S6 ≤256KB)

**天花板 = T5 mid-interact(有诚实弱点)/ T6 BLOCKED**。

| 交互 | 技术可行 | 体积代价 | 与 D2 auto-layout 冲突? | 结论 |
|---|---|---|---|---|
| hover tooltip(CSS `:hover` + `<title>`) | ✅ | ~2KB | 无 | **可入档**(D2 SVG 自带 `<title>`,零成本) |
| click 选中 + 兄弟 dim | ✅ | ~1KB | 无 | **可入档** |
| 节点/边详情侧栏 | ✅ | ~3KB | 无 | **可入档** |
| 键盘 Tab/箭头导航(a11y) | ✅ | ~1KB | 无 | **可入档** |
| 拖节点重定位 | ⚠️ 技术可 | ~5KB | **硬冲突** | 半残(边端点不跟随,视觉断裂) |
| 标签编辑(contenteditable `<text>`) | ✅ DOM 层 | ~2KB | 无 | **持久化有损**(SVG 不携带 DSL) |
| 增/删节点 + 重布局 | ❌ | — | 必须重布局 | **天花板**(需 dagre.js ~150KB 或 D2 WASM 21MB) |

**致命体积证据**(已实地核实 `/media-gen-mcp/node_modules/@terrastruct/d2/dist/node-esm/`):
- `d2.wasm` = **22,072,784 字节 = 21.0 MB**
- `elk.js` = **3,677,009 字节 = 3.5 MB**
- `browser/index.js` bundle = **7.8 MB**
- 对 `asserts.ts` L90 的 `256 * 1024` 上限 **超 80-125 倍**

**结论**:"增删节点 + 浏览器内重布局"在单文件 HTML 契约内技术不可行。**唯一干净路径 = MCP 回流**(用户改 DSL → 重跑 `generate_interactive_diagram` → 重生成 HTML)。

### 3.2 约束二:GitHub README 嵌入(JS 被 sanitize)

GitHub README 用 `sanitize` gem(rgrove/sanitize)+ `html-pipeline` SanitizationFilter,默认剥 `<script>` / `<iframe>` / `<style>` 块 / SMIL / `on*` 事件 / inline style。**README 是 markdown,不能嵌整段 HTML 文档**。

| 路径 | JS 能跑? | 暗色自动切换? | 动画? |
|---|---|---|---|
| 内联整段 HTML 文档 | ❌ README 不允许嵌 `<html>/<body>` | — | — |
| 内联 `<svg>`(markdown 直贴) | ❌(strip `<script>`) | ❌(strip `<style>` 块,连 `@media prefers-color-scheme` 也丢) | ❌(strip SMIL + `<style>`) |
| `<img src="*.svg">`(commit SVG 到 repo) | ❌(img-loaded SVG 浏览器安全模型禁 JS) | ✅(SVG 内 `<style>` + `@media prefers-color-scheme` 保留并 honor;D2 `darkThemeID` 字段就是为此设计) | ⚠️ CSS `@keyframes` 部分浏览器跑 |
| `<picture>` + `<source media>` 双 PNG | ❌ | ✅(两份切换) | ❌ |
| `<iframe>`(本地 `.html`) | ⚠️ | — | — |

**README 嵌入天花板 = T2 animated(且仅限 `<img src=*.svg>` 路径)**。T3 viewer 及以上档全部不可达 README(`<script>` 被剥,viewer 全废)。这是硬天花板,非可优化项。

### 3.3 重大缺口点名(必须先修)

**工具头号卖点"GitHub README 自动跟随主题"在当前实现下不成立**:

- `src/index.ts` L292 `generate_diagram` NEXT 句:"for interactive HTML with theme switch + animation that auto-follows system theme in GitHub README, use `generate_interactive_diagram`."
- `src/index.ts` L310 `generate_interactive_diagram` description:"auto-follows system theme via @media (prefers-color-scheme: dark) — **embeddable in GitHub README** so dark/light readers see the right palette with zero JS."
- `src/index.ts` L319 schema:"D2 inks BOTH palettes + @media (prefers-color-scheme: dark) into the SVG so GitHub README auto-switches."
- `src/index.ts` L1048 hint:"Open in browser to interact; **embed in GitHub README to auto-follow system theme**."

**但 handler**(`src/interactive-html/index.ts` L162-163)只 `fs.writeFile(.html)`,L167-168 可选 `.png`,**从不写独立 `.svg` 文件**(SVG 在 `built.svg` 内存,L113/135)。**结果**:HTML 在 README 被剥 `<script>` 成废件;PNG 不能切主题;唯一能让 README 自动切主题的独立 SVG 产物,工具不暴露。

**修复路径二选一**(详见 §5 与 §9 路线图):
- **(a) 新增 `format: svg | html | html+svg` 三选产物路径**(守 P0-1 工作流化立场,需避免 inputSchema 膨胀);
- **(b) 诚实降级文档化**,推荐用户用 `<picture>` + 双 PNG 退路。

### 4.3 核心裁决

**没有现成 lib 能直接 inline 进单文件 HTML 拿到"高交互编辑档(拖拽/连线/增删)"还守全 5 立场**:

- React Flow 破零 React(首次拉 React runtime 进项目)+ 4 文件拼装 + jsx-runtime shim;
- Cytoscape 守全立场但占 137KB gz(贴 cap 53%)+ 抛弃 D2 已生成的 SVG 几何层重画(工程断裂);
- JointJS Core 缺 Stencil/Inspector(在商用 Rappid);
- vis-network 163KB gz 最重 + 物理布局导向非架构图;
- draw.io 3.8MB 超 cap 15 倍 + 远程 script;
- Excalidraw 44MB + React peerDeps + 要求 LLM 写 x/y/seed(坐标幻觉红线);
- tldraw license 红线。

**结论**:高交互编辑档必须自研轻量 vanilla(light-interact ~10KB)或走 MCP roundtrip(NL → DSL patch → regenerate),没有第三条 lib 集成路径。

## 6. 快速微调专项(核心论证)

### 6.1 三范式对比(带立场检查的 ROI)

| 范式 | 工时 | 立场 | 用户价值 | 致命问题 |
|---|---|---|---|---|
| **A 重写 DSL**(当前) | 0 | 全守 | — | 用户原话已否决"重写 DSL 再生成" |
| **B 视觉拖拽编辑** | 5+ 人日 | **破 3 条**(① 单文件因 React runtime + asset bundle 外链;③ 同输入同输出因 transform 后下次 auto-layout 重算直接冲掉;② 纯免费因 tldraw 需 key+watermark) | 60% | B2 拖位置与 D2 auto-layout 是**根本技术冲突**(非工程量问题,物理不可能) |
| **C AI 自然语言微调** ★ | 0.5 人日 | 全守 | 90% | 需 Claude Code/CLI 会话留驻 |

**结论:C 比 B 高 10× ROI**。B 三路线全踩坑:B1 contenteditable 只能改标签不能拖位置;B2 拖位置与 auto-layout 物理冲突(重生成即冲掉 transform);B3 React Flow/tldraw 破单文件立场。

### 6.2 范式 C 是 MCP 原生最优解

用户对 Claude 说"把支付移到右下" / "加 redis 在订单和 db 之间" → Claude 改 DSL → 重生成。**零额外编辑器代码,复用 Claude 能力 = 零成本差异化**(drawio/tldraw 前面没 LLM,这是它们做不到的 moat)。

**深度论证**(详见 [`增强方案与微调工作流.md`](./增强方案与微调工作流.md) §3):
1. **MCP 是 LLM 调用接口**——LLM 擅长结构化 intent,不擅长鼠标事件;
2. **Excalidraw Architect MCP(BV-Venky,MIT,135★)已验证范式**:LLM 只产结构(layout 算法算位置)+ `architecture.md` 知识图谱为 source-of-truth + diagram 只是 view;
3. **D2 d2oracle 是 OSS 唯一成熟 AST edit 层**:`Create/Set/Move/Delete/Rename` 5 函数 + `d2lsp GetRefRanges`,可包装为 `edit_diagram(dsl, ops[])` MCP 工具,d2.wasm 在 Node 服务端调用(21MB 不入单文件 HTML);
4. **不做 visual canvas**——巨大前端工程量,且不符合 MCP 的 LLM-first 定位。

### 6.3 混合范式 C+(视觉 click 选择 + 对话修改)— 强推荐

**杀手发现·D2 SVG 已内嵌 base64 URL 编码的节点 ID 作为外层 `<g class>`**(已实证)。

本地 golden 实证(`media-gen-mcp/test/golden/expected/interactive-html/architecture.golden.html` L407 区域):

| base64 class | `atob` 解码 | 含义 |
|---|---|---|
| `<g class="Y2xpZW50">` | `client` | 节点 |
| `<g class="Z2F0ZXdheQ==">` | `gateway` | 节点 |
| `<g class="YXBp">` | `api` | 节点 |
| `<g class="Y2FjaGU=">` | `cache` | 节点 |
| `<g class="ZGI=">` | `db` | 节点 |
| `<g class="KGFwaSAtJmd0OyBjYWNoZSlbMF0=">` | `(api -> cache)[0]` | 边 |

**上游源码确认是故意行为**(非偶然):`d2svg.go` L8 `import encoding/base64` + L1012(边)+ L1627(节点)`base64.URLEncoding.EncodeToString(connection.ID / targetShape.ID)`。内层 `<g class="shape">` 是视觉形状,**外层 `<g class="BASE64">` 才是 ID 载体**。P0-3 golden byte-compare + 10 次确定性审计已间接证明跨渲染稳定。

**落地路径**(归入 P0-5B cleanup PR):
- viewer 加 `click` 事件委托(挂 stage 而非每节点绑监听,大图 N listener 会拖性能):
  `e.target.closest('#mgm-stage svg > g[class]')` → `atob(class)` 解码节点 ID → 写 `location.hash`(GitHub README iframe sandbox 友好)+ 可视 chip "已选 client,回对话说怎么改" → Claude 收到"用户点了 X"上下文 → patch DSL(不全量重写,保用户注释/样式)→ 重生成。
- **代码量**:~40 行 JS + ~10 行 CSS。**inputSchema 零 diff**(守立场 ④)。守 S2/S4/S6/S9/S11 全契约。
- **ROI**:0.5 人日 / 90% 用户价值 / 全守立场。对比自研拖拽 5+ 人日 / 60% 用户价值 / 破 3 条立场 = **10× ROI 差距**。

### 6.4 关键前置(DSL 持久化,P0,0.2 人日)

**实测 `src/interactive-html/index.ts` L162-163 handler 只 `fs.writeFile(.html)`,从不写 `.d2` 源码**。当前 `built.dsl` 在内存但被丢弃,导致每次微调用户必须重新粘 DSL,无法连续对话式迭代。

**P0 修复**:在 L163 旁加一行 `fs.writeFile(localPath.replace(/\.html$/, '.d2'), req.code)`(~10 行含错误兜底)。这是解锁整个 C 范式工作流的前置条件,**无此则 C 范式实际不可用**。

### 6.5 诚实局限性(必须文档化不可掩盖)

1. **NL 微调只在 Claude Code 会话内可用**;用户在浏览器单独打开 `.html` 时无 postMessage 通道回灌 Claude。工具 description 必须显式说"微调请回到对话,不要在浏览器里改"——这是部署模型的诚实声明。
2. **click-select 的 `location.hash` 是浏览器本地态**,不自动流入 Claude,用户仍需口述节点;chip 只是 wayfinding 辅助。
3. **"拖拽"心智重构**:用户说"拖拉拽节点"的心智来自 tldraw/Excalidraw/draw.io 这类 T6 full-editor。在架构图场景,拖拽通常 = 重新组织布局,而 D2 auto-layout 重算比重画一条 transform 更干净(无边的端点断裂、无 viewBox 越界)。诚实重构:把"拖拽"重新表述为"重新组织",由 NL 微调("把 X 移到 Y 附近")在 DSL 层解决。
4. **GitHub README 用 `<img src=*.svg>`(D2 `darkThemeID` `@media prefers-color-scheme`)在 macOS 暗色下是否真自动切色**:WebSearch 通用答案主张 NO,P0-5 文档 L139/L576 主张 YES,需建测试仓库实际截图验证(等级 C 单句断言)。
5. **AI 改 DSL patch vs 全量重写策略待定**:倾向 patch 保用户注释/样式,但需稳定行号映射,可能需给 DSL 加 `// <id>` 注释锚点。

## 7. 两产物假说 + 是否需要独立编辑器产物

### 7.1 假说成立且必要,但与微调问题正交

实测当前产物同时宣称服务 README 自动主题(`src/index.ts` hint)和本地查看,但两边都没服务好。诚实拆为:

| 产物 | 形态 | 交互档 | README 嵌入? | 当前状态 |
|---|---|---|---|---|
| **A. README 嵌入版(只读 + 自动主题)** | 独立 `.svg` 文件(D2 `darkThemeID` 注入 `@media prefers-color-scheme`),可选 `.png` light/dark 双图配 `<picture>` | T1/T2 | ✅(img/picture) | **缺口:工具不暴露独立 SVG 产物**(只写 HTML) |
| **B. 本地查看版(viewer + light-interact)** | 单文件 `.html`(当前产物),内联 viewer + 动画 + 可扩展 hover/click/select/tooltip/detail-panel | T3/T4 | ❌(JS 被剥) | **当前实现在此,但交互档还停在 T3,未到 T4** |
| **C. 全交互编辑器版** | 独立 app / 大文件(Cytoscape / React Flow 等) | T5/T6 | ❌ | **不可达**(破 S6 契约;属独立产品) |

A/B 服务**不同部署上下文**,而非不同微调模式。**AI NL 微调是 Claude 侧工作流,对 A 和 B 都成立**(只要 `.d2` 持久化)。

### 7.2 AI 对话未让编辑器完全不必要,但将其压缩到 light-interact 最小档

即使用户走 NL 微调,仍受益于视觉 affordance:click 看"这是 client 节点"、hover 看"连接关系"。media-gen-mcp 立场下的"编辑器" = T4 light-interact overlay(hover tooltip ~2KB + click select ~1KB + detail chip ~3KB,合计 ~10KB,远低于 S6 256KB 上限),而非 T5/T6 拖拽编辑器。

### 7.3 C 档(全编辑器)建议明确文档化为"超出范围,推荐外部工具"

**理由**:T6 full-editor 是另一个产品(全状态/undo/collab/multi-page/backend,500KB-几十 MB),市面已有 Excalidraw/tldraw/draw.io 免费方案。media-gen-mcp 应聚焦 A+B,把 C 明确 README FAQ 化"超出范围,推荐用户外部 Excalidraw/draw.io 改完 paste DSL 回流"。

## 8. 不该做的(NO-GO + 立场冲突 + 过度工程)

### 8.1 立场红线点名(README FAQ 显式记拒因)

- **不嵌任何 canvas 编辑器 lib(React Flow / Cytoscape / JointJS / vis-network)进单文件 HTML**:体积贴 256KB cap 53-63% + 抛弃 D2 渲染层工程断裂。**替代**:若未来真要做编辑,开 P1 独立立项 + 30 天需求观察期,Cytoscape.js 是首选。
- **不做视觉拖拽节点(B2 路线)**:与 D2 auto-layout 根本冲突(重生成即冲掉 transform),持久化无解(浏览器沙箱不让 JS 写磁盘,`localStorage` 不入 git 破立场 ③)。**替代**:NL 微调("把 X 移到 Y 附近")在 DSL 层解决。
- **不引入 tldraw / PlantUML / GoJS**:tldraw 五证(production 禁 + watermark + 遥测 + License Key 强制 + 商用 $6000/yr);PlantUML 双证(主仓 + server 双 GPL-3.0);GoJS 商业。**替代**:tldraw/GoJS → Cytoscape;PlantUML → D2 或 Kroki 远程;tldraw 视觉拖拽 → Excalidraw Architect MCP 范式(NL→结构 op 非 drag)。
- **不做 full-editor 档(React Flow / tldraw / Excalidraw / draw.io)**:是另一个产品。**替代**:推荐用户外部 Excalidraw/draw.io 后 paste DSL 回流。
- **不抄 Archify 7 个分析面板**(Story Trail / Route Probe BFS / Semantic Lens 计数 / Overview Radar minimap / Node Finder / Presentation Stage / Diagram Guide 命令面板):viewer 产品级工程,doc_v11 P0-5 L326-332 已立红线"Archify 10500 行 viewer 永不做"。**只借工艺**(state-on-container + match-on-element + 声明式 CSS + `data-just-panned` + 导出剥离)。

### 8.2 冲突点名

- **Cytoscape / React Flow 是"正确答案给错产品"**:`inv:node-graph-libs` 推荐 Cytoscape 为编辑档首选——裁决正确但产品错位。当前 `generate_interactive_diagram` 是生成器(viewer 档),引 137KB 库替代 ~200 行自研 viewer 是过度工程。**维持 P0-5 §2 已裁决的 A 路线**(D2 WASM + markmap 范式 `fillTemplate` + ~200 行 vanilla viewer),把 Cytoscape 备选留给"未来立独立 P1 编辑档项目 + 30 天需求观察期"。
- **draw.io 双重陷阱**:Apache 2.0 代码可用,但"draw.io"是 EU 商标 #018062448 需书面许可 + viewer-static 3.8MB 超 cap 15 倍 + 远程 script 破 self-contained。**替代**:借 `<div data-mxgraph>` 配置接口形态,不抄实现。
- **Excalidraw**:MIT 但 element data 要求 LLM 写死 x/y/width/height/seed(坐标幻觉红线)+ 手绘风与架构图冲突。**替代**:若需手绘风走 `rough.js` 0.16MB 直接渲染 D2 几何,不引 Excalidraw 本体。
- **JointJS Rappid 边界**:`@joint/core` standard shapes 够画基础架构图,但 Stencil / Inspector / Scroller 全在商用 JointJS+。若用户期望"拖新节点进画布"Core 做不到,需明确"编辑"最小定义。

## 10. 开放问题(诚实列)

1. **GitHub README `<img src=*.svg>` 真自动切暗色吗?** D2 `darkThemeID` 字段设计意图 + P0-5 文档主张 YES,WebSearch 通用答案主张 NO(img-browsing-context 不继承 `prefers-color-scheme`)。**需建测试仓库实际截图验证**(等级 C 单句断言,见 doc_v11 P0-5 §11.1 未决问题 #17 三源归零)。
2. **`.d2` 落盘命名/覆盖策略**:与 `resolveOutDir` 既有命名规则是否冲突?倾向覆盖(DSL 是 source of truth,git 管版本)。
3. **GitHub README iframe sandbox 是否真允许读 `location.hash`?** 本地不可复现,需线上嵌测试图实测。
4. **多图同 HTML(salt 防 ID 冲突)时 click 是否误命中其他 stage?** 骨架已用 `closest('#mgm-stage svg > g[class]')` 限定,需多图场景测试。
5. **边的 hit-test**:边 base64 可解但 path 细难点中,是否加透明粗 hit 区(`stroke-width:12;stroke:transparent`)?需评估视觉污染。
6. **Claude 改 DSL 用 patch 还是全量重写?** 倾向 patch 保用户注释/样式,但需稳定行号映射——是否给 DSL 加 `// <id>` 注释锚点是独立设计题。
7. **是否新增 `edit_interactive_diagram({htmlPath, instruction})` 显式工具(21→22)?** 倾向不加(约定足够,守 inputSchema 零 diff),列入 P2 候选。
8. **Mermaid Chart(商业)的 visual↔code round-trip 同步保真度未公开 benchmark**:需付费账号实测(若未来需要商业方案对比)。
9. **D2 d2oracle 对 edge references 在 Move 后的完整性测试覆盖**:复杂 cross-scope 移动 + 多重 edge 引用是否 100% 安全?需读 `testdata/d2oracle/TestMove/` 全集确认。
10. **AI edit 的语义 fidelity 如何测?** 改一个节点后如何确认未触及节点的坐标/连线 100% 未变(golden byte-compare 范式延伸到 edit 场景)?需定义 edit-aware 测试范式。
