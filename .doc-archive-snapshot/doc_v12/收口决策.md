# 交互图方向收口决策(2026-07-22)

> **角色**:主控(在与用户复盘后)
> **目的**:纠正 `交互图增强调研报告.md` 中被夸大的结论,定格 generate_interactive_diagram 的产品边界,防止后续再漂移。

---

## 1. 被纠正的过度结论(报告里的话术偏差)

调研报告把以下两点定为"P0 必须先修的重大缺口",**经复盘认定为过度结论,降级**:

| 报告原结论 | 纠正后定位 |
|---|---|
| "README 自动主题卖点与实现脱节,P0 修(handler 不写 .svg)" | **非 bug,是营销话术过度**。README 嵌入只是一个用例,不是核心功能;GitHub 会剥 `<script>` 是平台特性,不是我们实现错了。已把 README.md + 8 翻译 + 工具 description/hint 的"嵌 GitHub README 自动跟随主题"措辞改诚实(改为"浏览器打开交互,主题跟随系统")。是否额外导出独立 `.svg` 服务 README 用例 = **可选润色,非 P0**。 |
| "`.d2` 源码从不落盘 → C 范式不可用,P0 修" | **条件性前置,非独立缺口**。`.d2` 落盘只有在决定做"AI 自然语言微调"工作流时才需要;若不做该工作流,此事不相关。降级为"AI 微调线的前置项,按需做"。 |

**根因**:早先用"GitHub README 嵌一张随主题切换的架构图"举例解释"交互式 HTML 图",该例子在 P0-5 规划中被固化成"头号用例",又被本次调研当成"卖点"去审计,最终把一个随口举例循环成了"伪 P0 危机"。已在用户复盘中戳破。

## 2. 产品边界定格(四条收口)

1. **generate_interactive_diagram = 轻量交互查看器**(浏览器打开:viewer + 动画 + 主题切换)。**够用就停,不自研拖拽编辑器**。
2. **拖拽 / 全编辑器明确不碰** —— 那是 draw.io / Excalidraw / tldraw 的地盘,与"单文件自包含"立场物理冲突(编辑器需状态/保存/运行时)。用户要全编辑体验 → 推荐外部工具,不重造。
3. **"快速改图"的唯一增强线 = AI 自然语言微调**:用户对 Claude 说"加个 redis""把支付挪右下" → 改 D2 DSL → 重生成。复用 Claude、零编辑器代码、规避拖拽与 auto-layout 冲突、契合 MCP 形态。**视觉拖拽编辑不做**。
4. **README 嵌入不是功能目标**。措辞已诚实化(浏览器打开交互)。独立 `.svg` / `<picture>` 双图等 README 专门产物 = 可选,有明确需求再做。

## 3. 对报告推荐路线图的修订

| 报告 Step | 原定级 | 修订后 |
|---|---|---|
| 修 README `.svg` 缺口 | P0(0.3 人日) | **降为可选**(营销措辞已修;`.svg` 导出按需) |
| 落盘 `.d2` + description NEXT | P0 | **条件前置**(仅当启动 AI 微调线时做,~10 行) |
| viewer click 选节点 + hover tooltip + 详情侧栏(T4 light-interact) | Step 1 | **保留为可选增强**(让浏览器体验更像交互图;非必须) |
| AI 自然语言微调 | 隐性 ROI 冠军 | **升为唯一增强主线**(若用户要"快速改图",走这条) |
| M1a 视觉拖拽 / 重档全编辑器 | Step 2/3 | **取消**(立场冲突,不自研) |

## 4. media-gen-mcp 的核心定力(防再漂移)

media-gen-mcp 是**"所有图像操作归一个 MCP"(生成 + 识别 + 渲染)**。`generate_interactive_diagram` 产出 HTML 应用已是版图边缘,不应再向"前端画图编辑器"扩张。新增能力须通过"是否仍是图像/产物生成(而非交互应用开发)"的检验。
