## 0. linchpin 发现:D2 SVG 已内嵌 base64 URL 编码节点 ID

**这是轻/中档全部增强的技术地基——click/hover/drag 都靠它拿稳定节点 ID,无需任何 D2 改动。**

### 0.1 实证(本地 golden 文件)

`media-gen-mcp/test/golden/expected/interactive-html/architecture.golden.html` L407 区域,D2 产出的 SVG 每个节点外层 `<g class="...">` 是节点 ID 的 **base64 URL 编码**:

| base64 class(原始) | `atob()` 解码 | 含义 |
|---|---|---|
| `<g class="Y2xpZW50">` | `client` | 节点 |
| `<g class="Z2F0ZXdheQ==">` | `gateway` | 节点 |
| `<g class="YXBp">` | `api` | 节点 |
| `<g class="Y2FjaGU=">` | `cache` | 节点 |
| `<g class="ZGI=">` | `db` | 节点 |
| `<g class="KGNsaWVudCAtJmd0OyBnYXRld2F5KVswXQ==">` | `(client -> gateway)[0]` | 边 |
| `<g class="KGdhdGV3YXkgLSZndDsgYXBpKVswXQ==">` | `(gateway -> api)[0]` | 边 |
| `<g class="KGFwaSAtJmd0OyBjYWNoZSlbMF0=">` | `(api -> cache)[0]` | 边 |
| `<g class="KGFwaSAtJmd0OyBkYilbMF0=">` | `(api -> db)[0]` | 边 |

本地 `echo Y2xpZW50 | base64 -d` → `client`,全部对上。

### 0.2 源码确认(非偶然,D2 故意为之)

`curl https://raw.githubusercontent.com/terrastruct/d2/master/d2renderers/d2svg/d2svg.go`:

- L8:`"encoding/base64"` 显式 import;
- L1012(边):`classes := []string{base64.URLEncoding.EncodeToString([]byte(svg.EscapeText(connection.ID)))}`;
- L1627(节点):同上模式 `targetShape.ID`;
- L1663:`<g class="shape...">` 是内层视觉形状;**外层 `<g class="BASE64">` 才是 ID 载体**。

### 0.3 稳定性已证

P0-3 golden byte-compare + 10 次确定性审计(同 DSL 多次渲染 sha256 全同)已间接证明 base64 class 跨渲染不变。**这是"click → 取 ID → 回喂 Claude 改 DSL"的可靠往返桥梁,零 D2 改动**。

```javascript
function showDetail(nodeId){
  var panel = document.getElementById('mgm-detail-panel');
  if (!panel) return;
  // 从 SVG 现有结构取连入连出边
  var incoming = [], outgoing = [];
  stage.querySelectorAll('svg > g[class]').forEach(function(g){
    var c = g.getAttribute('class').split(' ')[0];
    try {
      var decoded = atob(c);
      var m = decoded.match(/^\((.+?) -> (.+?)\)\[\d+\]$/);
      if (m) {
        if (m[2] === nodeId) incoming.push(m[1]);
        if (m[1] === nodeId) outgoing.push(m[2]);
      }
    } catch(err){}
  });
  panel.innerHTML = '<h4>' + escapeHtml(nodeId) + '</h4>'
    + '<p><strong>连入:</strong> ' + (incoming.join(', ') || '无') + '</p>'
    + '<p><strong>连出:</strong> ' + (outgoing.join(', ') || '无') + '</p>'
    + '<p class="hint">要改?在对话里说"改 ' + escapeHtml(nodeId) + '..."</p>';
  panel.style.display = 'block';
}
```

### 1.4 S4 键盘导航 + roving tabindex(a11y)

**改文件**:`src/interactive-html/viewer-min.ts` 加 Tab/箭头键遍历节点,`setAttribute('tabindex', 0/-1)` 轮转。抄 Archify 工艺 I。Enter/Space 走与 click 同路径(键盘对等)。

```javascript
var focusableNodes = function(){
  return Array.prototype.slice.call(stage.querySelectorAll('svg > g[class]'));
};
document.addEventListener('keydown', function(e){
  if (e.target !== document.body && e.target !== stage) return;
  var nodes = focusableNodes();
  if (!nodes.length) return;
  var curIdx = nodes.findIndex(function(n){ return n.hasAttribute('data-focus-match'); });
  if (e.key === 'Tab' || e.key === 'ArrowRight' || e.key === 'ArrowDown') {
    e.preventDefault();
    var nextIdx = curIdx < 0 ? 0 : (curIdx + 1) % nodes.length;
    selectNode(nodes[nextIdx]);
  } else if (e.key === 'ArrowLeft' || e.key === 'ArrowUp') {
    e.preventDefault();
    var prevIdx = curIdx <= 0 ? nodes.length - 1 : curIdx - 1;
    selectNode(nodes[prevIdx]);
  } else if ((e.key === 'Enter' || e.key === ' ') && curIdx >= 0) {
    e.preventDefault();
    showChip(atob(nodes[curIdx].getAttribute('class').split(' ')[0]));
  }
});
```

## 3. AI NL 微调范式深度论证(范式赢家)

### 3.1 三范式 ROI 对比(带立场检查)

| 范式 | 工时 | 立场 | 用户价值 | 致命问题 |
|---|---|---|---|---|
| **A 重写 DSL**(当前) | 0 | 全守 | — | 用户原话已否决 |
| **B 视觉拖拽编辑** | 5+ 人日 | **破 3 条**(① React runtime + asset bundle 外链;③ transform 后下次 auto-layout 重算冲掉;② tldraw 需 key+watermark) | 60% | B2 拖位置与 D2 auto-layout 物理冲突 |
| **C AI 自然语言微调** ★ | 0.5 人日 | 全守 | 90% | 需 Claude Code/CLI 会话留驻 |

**结论:C 比 B 高 10× ROI**。

### 3.2 范式 C 是 MCP 原生最优解的深度论证

用户对 Claude 说"把支付移到右下" / "加 redis 在订单和 db 之间" → Claude 改 DSL → 重生成。**零额外编辑器代码,复用 Claude 能力 = 零成本差异化**(drawio/tldraw 前面没 LLM,这是它们做不到的 moat)。

**深度论证**:

1. **MCP 是 LLM 调用接口**——LLM 擅长结构化 intent,不擅长鼠标事件;
2. **Excalidraw Architect MCP(BV-Venky,MIT,135★)已验证范式**:LLM 只产结构(layout 算法算位置)+ `architecture.md` 知识图谱为 source-of-truth + diagram 只是 view。README 原话:"separates the what from the where - the AI focuses on structure, the engine handles the pixel math";
3. **D2 d2oracle 是 OSS 唯一成熟 AST edit 层**:`Create/Set/Move/Delete/Rename` 5 函数 + `d2lsp GetRefRanges`,可包装为 `edit_diagram(dsl, ops[])` MCP 工具,d2.wasm 在 Node 服务端调用(21MB 不入单文件 HTML);
4. **不做 visual canvas**——巨大前端工程量,且不符合 MCP 的 LLM-first 定位。

### 3.4 部署前提必须文档化

此工作流**只在用户留驻 Claude Code/CLI 会话(有文件系统访问)时成立**;用户在浏览器单独打开 `.html` 时无 postMessage 通道回灌 Claude。因此工具 description 必须显式说"微调请回到对话,不要在浏览器里改"——这是部署模型的诚实声明,不可省略。

### 3.5 Claude 改 DSL patch vs 全量重写策略(开放问题)

**倾向 patch 保用户注释/样式**,但需稳定行号映射。两种实现选择:

- **(a) 简单 patch**:Claude 读 .d2 → 用字符串替换改局部 → 写回。优点零额外基建;缺点若 DSL 复杂可能误改;
- **(b) 结构化 op via d2oracle**:包装 `edit_diagram(dsl, ops[])` 工具,ops 为 `{op:"create", key:"cache", parent:"api"}` 等结构化 edit intent,内部映射到 `d2oracle.Create/Set/Move/Delete/Rename`。优点可控、保留未触及部分、易测、错误可定位(契合 doc_v11 P0-2 错误契约 + P0-4 产物守门);缺点需 Go→Node bridge 或 d2.wasm 在 Node 调用(21MB 在 MCP 服务端可接受)。

**建议**:MVP 先用 (a) 简单 patch + description 约定,(b) 列入 P1 候选(若 30 天需求观察期确认编辑需求)。

### 3.6 "拖拽"心智污染,需诚实重构

用户说"拖拉拽节点"的心智来自 tldraw/Excalidraw/draw.io 这类 T6 full-editor。但在架构图场景,**拖拽通常 = 重新组织布局,而 D2 auto-layout 重算比重画一条 transform 更干净**(无边的端点断裂、无 viewBox 越界)。像素级拖拽与 auto-layout 物理冲突(B2 老大难,非工程能解)。诚实重构:把"拖拽"重新表述为"重新组织",由 NL 微调("把 X 移到 Y 附近")在 DSL 层解决,重生成布局更一致。用户若坚持像素级拖,media-gen-mcp 立场不支持,应文档化导流到外部 Excalidraw/draw.io。

## 5. README 嵌入场景的根本限制(必须诚实告知用户)

2. **`<img src=*.svg>` commit 到 repo** → SVG 经 camo 代理透传,CSS `@media` + `@keyframes` 部分保留,但 JS 全失效;
3. **`<picture>` + `<source media>` 双 PNG 切换** → 最可靠但产两份图。

**(a) 新增 `format: svg | html | html+svg` 产物路径**

## 7. 诚实局限性(必须文档化不可掩盖)

## 8. README FAQ 草稿(直接可用)

### Q: 为什么不支持拖拽节点?

**A**:D2 是 auto-layout 引擎——每次重生成时 dagre 算法根据 DSL 重新算节点坐标,任何"视觉拖拽"留下的 transform 都会被冲掉,这是物理冲突而非工程量问题。我们有更好的方案:**回到对话用自然语言说"把 X 移到 Y 附近",Claude 改 DSL 重生成,布局更一致**。若需像素级拖拽编辑,推荐外部工具 Excalidraw / draw.io 改完 paste DSL 回流。

### Q: 为什么不能在浏览器里直接编辑保存?

**A**:浏览器沙箱不允许 JavaScript 写磁盘(安全模型),`localStorage` 不入 git。本工具的立场是"同输入同输出可入 git",所以编辑请走对话(NL→Claude 改 DSL→重生成),产物 .d2 源文件 + .html 视图都 git-able。

### Q: GitHub README 怎么自动跟随系统主题?

**A**:GitHub README 会剥 HTML 的 `<script>`,viewer 的 JS 交互层在 README 内全部失效。但 SVG 经 `<img src="*.svg">` 引用时,内部 `<style>` + `@media (prefers-color-scheme: dark)` 会被浏览器 honor(D2 `darkThemeID` 字段就是为此设计)。本工具落盘 `.svg` 文件后,README 写 `<img src="diagram.svg" alt="...">` 即可自动跟随主题(无 JS,纯 CSS)。

### Q: 为什么不集成 React Flow / tldraw 做全功能编辑器?

**A**:体积:React Flow 全栈 107KB gz(4 文件 + jsx-runtime shim)/ tldraw 需 License Key + 强制 watermark(商业 ~$6000/yr)/ Excalidraw 44MB / draw.io 3.8MB——都破单文件自包含立场(≤256KB)或纯免费立场。全编辑器是另一个产品类(市面已有 Excalidraw/tldraw/draw.io 免费方案),media-gen-mcp 聚焦"LLM 程序化生成静态单 HTML"。

```go
func Create(g *d2graph.Graph, boardPath []string, key string, obj *d2graph.AttributeMap) (*d2graph.Graph, error)
```
