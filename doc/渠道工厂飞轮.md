## 每轮结构(7 段)

```
S1 发现:四通道扫描(榜单/中文媒体/英文社区/融资)→ 增量候选去重入队
S2 深挖:能力探到极致 —— lasso 实探页面 + agent 三路(能力配额/条款风控/技术先例)→ 「能力边界清单」(已知/未知全景)
S3 裁决:GO / SKIP-记册 / NO(三态,2026-09-23 用户强化:发现前期调查有误或性价比不高者,
        **不直接对接**——跳过并记入「延迟判定册」[错在哪/当前性价比/ revisit 条件],
        攒一批后综合判定(批量对比增量价值),再决定是否进入 S4)
S4 实施:provider(简单名)+ 白盒 stub 套件 + channelInfo 结构化说明 + 注册表/工具描述接入
        (轮4 起完成标准追加:能力声明与实现逐项对齐——supportsImageToImage/capabilities 说
         支持的每个输入,provider 内必须有对应接线,禁静默丢弃)
S5 测试:机械门(全量回归)+ 真机门(XX_IT 双门;有登录态→把 S2 未知项逐一测成已知,写入 channelInfo;
        无登录态→BLOCKED-on-login 登记,用户动作后补测)
S6 审查:fresh agent(03 清单)+ 修复循环
S7 轮末:①再发现扫描(增量) ②飞轮自评估(流程缺陷/文档/README/说明优化,当场改)
        ③轮报落盘(本文件 §轮报)
```

## 命名与说明标准(用户重点要求)

- **渠道名**:小写短名 ≤8 字符,与平台惯称一致(上表);注册名即 `provider=` 值。
- **channelInfo(结构化说明,三处一致)**:每 provider 实现 `channelInfo()` →
  `{ freeQuota, capabilities{t2i,i2i,t2v,i2v,keyframes}, limits{rate,daily,size,duration}, watermark, prerequisites{login,proxy}, risks, status{live|blocked-on-login|disabled} }`
  透出到 list_models detail + 工具 provider 描述 + README 渠道总表——**调用方一眼看清每渠道的额度/边界/前置/风险**。
- **能力边界清单 → 测试用例**:S2 的每个"未知"(如:万相视频单日上限?图生图支持否?)在 S5 转成真机 IT 用例,测成已知后回写 channelInfo(未知项清零是完成标准)。
- **provider 开发纪律(轮4 新增)**:抛给共享 withRetry 的错误必须带 `.status`(否则 isTransient 默认 0 误判为瞬时错被重试 3 次);错误码族 S1xx 环境/S2xx 网络/S3xx 参数/S4xx 结果全渠道统一。
