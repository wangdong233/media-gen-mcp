# 渲染档共享实例:R5 裁决(不加独占锁/队列)与长期运行手册

> 2026-09-02 对抗复审留档。结论:**R5(渲染独占/队列)维持 not-needed**——单实例多 page
> 并发渲染的正确性证据链成立且比原论证更硬;但原论证未覆盖的两个长期运行风险
> (硬杀泄漏页 / 多日主进程 RSS 增长)在此留运营手册与重开条件。
>
> 背景:attach 全量切换至 lasso v1.19.0 渲染档(HEAD 772676b)后,全部渲染管线
> (render-video / render-svg / interactive-html export-png)共享同一个 lasso 治理的
> headless Chrome 实例。本文回答「共享实例上并发与长期运行是否安全」。

## 1. R5 not-needed 的完整证据链

### 1.1 页级独立性(并发正确性)

- 每次渲染 `browser.newPage()` 独立页,用毕 `finally page.close().catch(()=>{})`
  (src/render-video.ts:268/305-307,src/render-svg.ts:99/114,
  src/interactive-html/export-png.ts:44/65 同模式)。
- 逐帧 seek 时钟全部是 page 内 evaluate(`window.__hf.seek` / GSAP
  `timeline.pause+totalTime` / WAAPI `anim.pause+currentTime`),操作的是该页自己的
  window 与 DOM;帧时间用 `i/fps` 有理化,不依赖墙钟(render-video.ts:94-126/286)。
- 消费方不触碰 browser 级可变状态:`puppeteer.connect({browserWSEndpoint,
  defaultViewport:null})`,视口由每页 `setViewport` 自管(src/browser-pool.ts)。
- 并发 ensure 有 lasso 单飞锁(`render-launch-<port>.lock`,设计决议 §3.6);
  唯一共享资源是 CPU/内存——同步 evaluate + double-rAF + fromSurface 截图在任何
  负载下截的都是 seek 后的确定帧,争用只降吞吐不错帧。

### 1.2 跨渲染状态隔离(原论证未查、本复审补齐的一面)

共享的是**默认 browser context**,理论风险是 cookie / localStorage /
serviceWorker / 缓存跨页共享。实际免疫,因为:

- 全部管线用 `page.setContent(html)` 写入(无 `goto` 网络导航)——setContent 写的是
  about:blank 页,**opaque origin**:localStorage/cookie 写不进、serviceWorker
  无法注册,跨渲染页面级持久状态结构性不存在。
- 默认上下文唯一真实残余共享 = **HTTP 磁盘缓存**(子资源:字体/图片)。同 URL 同字节,
  对确定性是中性偏正向(热缓存加速);唯一注意点是**远端可变资源**(同 URL 服务端会
  改内容的)本身就是非确定性源——与并发无关,冷热跑也一样。关键资产建议 data: 内联
  (generate_diagram/generate_card 产物已是)。
- **独立复验(2026-09-02 红队实测)**:同实例双 page 并发渲同 SVG(异视口 800x600 /
  320x240,截图窗口真实重叠 + 对页 DOM churn 制造争用),两路输出与各自串行基线
  sha256 全等、互不相混;setContent 页 `document.origin === "null"`,localStorage
  写/读、cookie 写/**读**全部抛 SecurityError,serviceWorker 注册拒绝,跨页
  localStorage 亦不可读——上列结构性隔离全部实证成立。

### 1.3 结论

加锁/队列只会降吞吐换零正确性收益。维持 not-needed。

## 2. 长期运行风险与运营手册(零代码缓解)

### 2.1 硬杀泄漏页(累积有界)

- 场景:渲染中途 media-gen 进程被 SIGKILL,`finally page.close()` 不执行 → page
  target 滞留实例内(每页约一个 renderer 进程)。
- **界**:lasso idle reaper 在 touch 停止 10min 后整实例回收(`LASSO_RENDER_IDLE_MS`
  默认 600000)——泄漏页最多活到下一次空闲窗,不会无限累积;连续高负载无空闲窗时
  才会跨天滞留。
- **观测**:`npx lasso-mcp render-chrome --status` 的 `renderSessions`(CDP 实时
  page/target 计数)。**空闲基线 = 1**(实例自带初始 about:blank 标签;lasso 设计决议
  §9 真机实测同为 1,2026-09-02 红队复测确认)——健康空闲实例应恒为 1;若空闲态稳定
  **≥2** 且跨空闲窗不归零 = 有泄漏页(渲染批刚结束的短暂 +1 可能是 page.close() 的
  CDP ack 与 disconnect 竞态,隔一分钟复测再判)。

### 2.2 多日连续使用主进程 RSS 增长

- 场景:实例被 heartbeat touch 长期续命,浏览器主进程内存缓慢增长(Chromium 常态)。
- **重置配方(零代码)**:维护窗跑 `npx lasso-mcp render-chrome --stop`(收全部渲染档
  + 清临时 profile)→ 下一次渲染 `--ensure` 自动重生全新实例。建议长周期验收批之间执行。

### 2.3 并行验收(多 agent 同机)

共享单实例的生产 attach 不需要隔离;**并行真机验收**(各自跑清场命令)必须按 lasso
三 env 套装隔离,配方与清场纪律见 lasso 仓 `doc/渲染档-并行验收隔离配方.md`
(`LASSO_RENDER_PORT` + `LASSO_LAUNCHED_CHROMES_PATH` + `LASSO_RENDER_GUARDIAN_PID_PATH`,
三件配齐缺一有暗坑;并行期间禁 `chrome-stop --all` 与 `doctor --clean`)。

## 3. 重开条件(任一命中即重开 R5)

1. 并发负载下 golden byte-identical 出现实证破绽(先加并发 golden 用例定位)。
2. 内存压力事件归因到并发渲染(而非实例长期增长——那走 §2.2 重置配方)。
3. 出现需要 browser 级全局状态的消费方需求。
4. **新增**:`--status` 的 `renderSessions` 在空闲态稳定 **≥2** 且跨空闲窗不归零
   (§2.1 基线=1,泄漏信号=≥2;写「稳定非零」会因基线恒为 1 而恒真 → R5 被误重开)。
