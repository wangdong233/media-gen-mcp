## 0. 项目定位与关系图

```
┌─ Windows 主机(全流程+GPU 合成)────────────────────────────┐
│  [新仓库] nodetool-director(NodeTool 私有 fork,AGPL)      │
│    ├─ 画布+DAG 管线+timeline/storyboard(NodeTool 原生)      │
│    ├─ packages/mediagen-nodes(自建 node pack:9 渠道节点)   │ ← 本方案核心工作量
│    ├─ custom provider(智谱 OpenAI 兼容端点直挂,零代码)     │
│    ├─ ComfyUI(内置集成节点 → 本地 GPU 推理,可选阶段)      │
│    └─ credit 预算闸(并发安全件,建在 job 调度处)           │
│  [独立安装] media-gen-mcp-server(npm,MIT)                 │
│    └─ stdio 挂入 NodeTool(chat 层 27 工具)+ CC 继续直用    │
└────────────────────────────────────────────────────────────┘
   Mac(本机)继续当:CC 日常会话/开发机(可远程访问 Windows 的 7777)
```

**三条铁律**:
1. **media-gen-mcp 不改归属**:它是独立 MIT 项目(npm media-gen-mcp-server),渠道密钥/白名单/确认门全在其 config;fork 只消费它(MCP 挂入)或转写其契约(node pack manifest)——MIT 代码可单向流入 fork,fork 的改动不回流义务
2. **AGPL 边界**:fork 私有自用/内部使用完全合法;仅当「对外分发闭源二进制」时才触发开源义务(当前无此计划;渠道层独立在 media-gen-mcp,迁移门常开)
3. **上游同步策略**:fork 保留 upstream remote 定期 rebase/merge(nodetool-ai/nodetool 极活跃,09-23 仍在 push);我们的改动尽量收敛在**新增 packages/mediagen-nodes + 少量 hook 点**,降低同步冲突面

## 1. 环境准备(Windows,阶段 0 前置)

| 项 | 要求 | 验证命令 |
|---|---|---|
| Node | **≥22**(上游 .nvmrc=22.22.1;npm workspaces+turbo,**无 pnpm**) | `node -v` |
| 包管理 | npm(随 Node) | `npm -v` |
| 浏览器 | Chrome/Edge 最新(**Windows 上 WebGPU 走 DX12**——RenderTimeline 真 GPU 合成的关键) | 打开 `chrome://gpu` 查 WebGPU=Hardware accelerated |
| git | 任意近期版 | `git --version` |
| ffmpeg | 可选(部分节点依赖;无 GPU 合成仍可用) | `ffmpeg -version` |
| media-gen-mcp | `npm i -g media-gen-mcp-server@0.23.0` | `node -e "console.log(require('child_process').execSync('npx media-gen-mcp-server --help 2>&1 || echo ok').toString())"`(或直接下一步 stdio 挂入验证) |
| 硬件检查 | GPU 型号/VRAM(阶段 3 ComfyUI 用);报告给 [[comfyui-workstation-project]] 决策 | `dxdiag` |

**media-gen-mcp 的 Windows config**:`%USERPROFILE%\.media-gen-mcp\config.json`——白名单模型(enabledProviders)+ 各渠道密钥。注意:gemini(CDP 9225)/flow(9223)渠道是 Mac 专属浏览器态,Windows 白名单建议 `["agnes","zhipu","siliconflow","cloudflare","hfspaces","pixverse"]`;hfspaces 的 HF token/pixverse CLI 凭据需在 Windows 重新配置一次。

## 2. 阶段 0:跑通与零代码验证(半天)

1. **Fork 建立**:`gh repo fork nodetool-ai/nodetool --clone`(或 GitHub 网页 fork→私有化:fork 默认 public,需 Settings→Change visibility→Private;或 mirror push 到自建私有仓);记录 baseline commit(核验基线=88a9c27,2026-09-23)
2. **本地起**:`npm install && npm run build:packages && npm run dev` → 浏览器开 http://127.0.0.1:7777(单 Node 进程伺服 API+web;SQLite 落盘;纯本地 workflow 无需任何 API key)
3. **零代码验证三连**:
   - a) **智谱推理**:Settings→Models & Providers→OpenAI-compatible endpoints→Add endpoint:name=ZhipuGLM,baseUrl=`https://open.bigmodel.cn/api/paas/v4`(必须带版本路径),apiKey=智谱 key → chat/Agent 节点模型菜单立刻出现 GLM
   - b) **MCP 挂入**:Settings→External MCP Servers→Add:command=`node`,args=`["C:\\Users\\<你>\\AppData\\Roaming\\npm\\node_modules\\media-gen-mcp-server\\dist\\index.js"]`(或 npx 形态)→ 探测到 27 工具(`mcp_mediagen_*`)→ chat 里对话「用 hfspaces 生一张 1024 的雪山图」验证 LLM 填参链路+结果回资产
   - c) **CC 反向**:`nodetool mcp install`(一键注册进 Claude Code)→ 在 CC 里 `run_workflow` 验证「CC 当大脑、NodeTool 当执行器」
4. **验收门 0**:以上三连全过 → 记录实际形态截图;若 MCP 挂入失败,先查 Windows 下 spawn/npx 路径问题(上游 stdio 传继承父进程 env)

## 3. 阶段 1:自建 node pack(packages/mediagen-nodes)——确定性画布层(核心工作量,2-5 天)

> 目标:9 渠道成为**原生图节点**——画布上摆放,Inspector 表单选渠道/模型/参数,确定性可复现。

**范式二选一(建议先 factory 后手写特例)**:
- **factory+manifest**(主路):仿 `packages/higgsfield-nodes/src/higgsfield-factory.ts`(仅 89 行)——写 1 个 `mediagen-factory.ts` + 1 份 manifest JSON(声明每渠道每能力的字段 schema:provider/model/size/aspect/seed/…),运行时批量生成节点类
- **手写特例**(辅路):仿 `packages/minimax-nodes`(结构=package.json/tsconfig/vitest.config/README + src/index.ts 导出 NODES 数组+registerXxxNodes + src/xxx-base.ts 约 474 行 auth/retry/poll 基座 + src/nodes/*.ts 每节点 60-120 行:BaseNode 子类+`@prop` 装饰器声明字段+`async process()`)

**manifest 数据源(重要——不重新逆向)**:media-gen-mcp 已沉淀全部渠道 wire 契约,直接转写:
- 渠道能力/参数:media-gen-mcp 各 provider 源码(`src/providers/*.ts`)+ `list_models` 输出(每渠道 models/videoConstraints/imageConstraints/costCatalog)
- 智谱/硅基流动等 OpenAI 形状渠道:可同时走 custom provider 路线挂进模型下拉(双保险)
- 🔴 **confirm-token 渠道(pixverse 计费)必须做成节点对**:Submit 节点输出 `{needConfirm, estimatedCost, confirmToken, expiresInSeconds}` → Confirm 节点以 token 为必填入参复调同参数;token 10min TTL——**不要把确认门藏进单节点内部**(画布范式要求显式可审批);参考官方 Comfy MCP 同构先例
- 产物回传:遵循 NodeTool 的 videoRefFromBytes/asset 体系(见 minimax 节点 `process()` 返回形态)
- 免费渠道(agnes/zhipu)单节点直通;hfspaces 注意 GPU 配额错误(data:null)转结构化节点错误
- **密钥注入**:节点走 `this._secrets`/env(`requiredSettings: ["XXX_API_KEY"]` 自动出配置 UI)——密钥不进 workflow JSON

**注册**:packages/mediagen-nodes/src/index.ts 导出 NODES 数组+registerMediagenNodes(registry),workspace 挂进根 package.json;docs/custom-node-library-design.md 为官方设计文档

**验收门 1**:画布摆「Mediagen Image(agones/zhipu/siliconflow/cloudflare/hfspaces 五渠道下拉)」节点→Inspector 改参数→运行出图→改 size 重跑只影响本节点;pixverse 节点对走完一次确认流;vitest stub fetch 测试齐(仿 minimax tests)

## 5. 阶段 3:ComfyUI 本地推理接入(可选,随工作站硬件)

- NodeTool 内置 integration-nodes/comfy.ts;ComfyUI 装 Windows 机(参考 [[comfyui-workstation-project]] 选型)后,本地 Wan2.2/LTX-2 推理节点与 mediagen 云渠道节点同画布混排
- 注意 ComfyUI 单 worker prompt 级串行(天然互斥,多任务排队);缓存机制免费提供「改一镜重跑一镜」

## 6. 并发安全件(随阶段 1 落地)

- **全局 credit/配额预算闸**(唯一必须自建):建在 fork 的 job/Runner 调度处——pixverse 积分日预算+HF ZeroGPU 并发=1(其 GPU 记账按账号)+gemini 若未来启用则强制串行(S303 对应排队);多 Agent(多个 CC 会话经 /mcp CodeAct 并发驱动)共享此闸
- 确认节点不被长队列饿死:排队超 token TTL(10min)→Submit 节点自动重取 token(warning 标注)
- media-gen-mcp 侧零改动(其三层状态模型白盒结论:进程级竞态全在可接受窗口)
