## 5. CI-parity 条款(本地绿 ≡ CI 绿)

1. **单一命令**:CI 与本地跑同一条 `npm test`(build + build:tests + node --test + check-error-text + check-schema + check-readme-sync + check-render-output strict),不维护第二套 CI 脚本。
2. **测试自足**:测试不得依赖用户态 `~/.media-gen-mcp/config.json`(02a77ee 修复:provider-priority 两用例曾因 CI 无用户配置 false-fail,已改自足 fixture)、不得依赖本地媒体/output 文件、不得依赖网络。需要渠道行为一律 StubTransport / override 注入(flow 单元已示范零网络零积分)。
3. **golden 可重建**:任何 byte-identical 断言的 expected 必须能由 `npm run render:golden` 从当前代码确定性重建;不可重建即视为产物漂移,先修产物再改 golden。
4. **strict 是默认闸门**:qr/url.png 的 MEDIA_GEN_CHECK_PROFILE=strict 校验属于 `npm test` 本体(非可选步骤),CI 与本地同等生效。
5. **提交前自检**:改动 handler/engine/provider 后,本地全量 `npm test` 绿才可 push;CI 红即视为提交无效,修复合并回主干前不叠加新改动。
